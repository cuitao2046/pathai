# 问题与踩坑日志

> **用途**：开发过程中遇到的所有关键问题与踩坑的持续记录。
> **约定**：每解决一个问题就在此**追加**一条（文末，按时间正序），包含
> 时间戳、问题描述、解决方案（必要时附根因与涉及文件）。
> 回溯补录的早期条目标注「回溯补录」，日期为可考的最近记录时间。

## [回溯补录·第一阶段] 小程序服务类目二级分类不符被驳回

- **问题**：工具类目下没有「其他工具」二级分类，强行选择不匹配的工具二级分类，
  审核因「功能与类目不符」被驳回。
- **解决**：改选「交通服务 → 导航/地图」；该类目个人主体不支持，需学校/组织主体注册。

## [回溯补录·M 阶段] sqlite :memory: 多连接不共享表

- **问题**：测试用 `sqlite:///:memory:` 时每个连接各自一张库表，第二条连接找不到表。
- **解决**：测试改用**临时文件库** + `Base.metadata.create_all` 建表；
  另注意 auth 响应字段是 `accessToken` 而非 `token`。

## [回溯补录·C7] 含时间戳请求的 Idempotency-Key 哈希比对触发 409

- **问题**：请求体含 `observedAt` 等时间戳字段，两次「相同」请求哈希必然不同，
  幂等键比对判为冲突返回 409。
- **解决**：测试把请求体冻结为模块级常量后再取幂等键。

## [回溯补录·C7] 到达判定边界与幂等键重放历史会话

- **问题**：样例地图 (5,5) 坐标距终点恰 5m（`ARRIVAL_RADIUS_M=5.0`）一拍即到达，
  「非到达更新」测试误判；固定 openid + 固定幂等键会重放历史到达会话污染状态。
- **解决**：非到达更新用距终点 >5m 的坐标（如 (4,4)）；幂等键保证唯一性。

## [回溯补录·地图转换] v9 数据孤立节点与割点房间导致另一翼不可达

- **问题**：v9 真实地图有 27 个孤立/不可达节点，且 F2 生物工作室等割点房间被
  基线路由引擎规则 1/3 拒绝穿房路径 → 另一侧翼不可达。
- **解决**：转换脚本保留**最大连通分量**，割点房间提升为 intersection
  （保留 `promotedFromRoom` 标记）；F2 东翼 3 地点仅经 accessibilityLevel=999
  楼梯平台连通属源数据事实，verify 归类为警告、API 层返回 422 `ACCESSIBLE_ROUTE_NOT_FOUND` 属正确行为。

## [2026-10-25·回溯补录] mock 测试全面换真实地图/信标数据后的连锁坑

- **问题**：所有 mock 测试改用真实地图包 2026-10-25.1 与真实信标后集中暴露：
  ① 三点定位用「相同 RSSI」观测会几何退化被判 unreliable（真实信标散布大）；
  ② MAP_VERSION_CONFLICT 的派生第二版 `publishedAt` 若不晚于真实包，latest 会反转；
  ③ 真实地点名无楼层前缀且 aliases 全空，意图/地点查询须按最长匹配+同名多处语义重写；
  ④ 导航到达/偏航选点必须用真实节点坐标并冻结几何前提断言。
- **解决**：按上述四点重写用例；jest 用 `declare const require` 跨目录引真实地图 JSON，
  fixture 放 `client/tests/fixtures/real-map.ts` 模块级缓存。

## [回溯补录·2026-10 前] 微信同声传译插件个人主体不可用

- **问题**：「微信同声传译」插件类目（IT科技>软件服务提供商）仅对企业/组织主体开放，
  个人主体后台搜不到也无法添加 → live 语音无插件可用。
- **解决**：短期回滚 plugins 声明、mock 链路兜底；**最终方案**（见 2026-10-26 讯飞条）
  整体切换讯飞在线语音，插件与端侧代码全部删除。

## [回溯补录·真机] 安卓蓝牙扫描依赖系统定位服务开关

- **问题**：安卓系统下扫不到 iBeacon，与代码权限无关。
- **解决**：必须打开系统「定位服务」开关（无需申请 wx.getLocation 接口）。

## [2026-10-26·回溯补录] 真机 ERR_CONNECTION_REFUSED / 网络连接不可用

- **问题**：真机请求后端失败：`localhost` 在真机上指向手机自身；
  或后端未启动/只监听 127.0.0.1；或防火墙未放行；或手机与电脑不同 WiFi。
- **解决**：`API_BASE_URL` 用开发机**局域网 IP**；后端必须 `--host 0.0.0.0` 启动；
  放行 TCP 8000 入站规则；三查同 WiFi。

## [2026-10-26·回溯补录] WLAN IP 随 DHCP 漂移（多轮）

- **问题**：开发机地址多轮变化（192.168.100.103 → 192.168.1.28 → 192.168.68.108 → 192.168.1.28），
  真机连不上后端。
- **解决**：更新 `client/config/env.ts` 的 `API_BASE_URL` + docs/25 §1.2 表格并提交，
  开发者工具重新编译、真机重启；连接失败优先核对当前 IPv4。

## [2026-10-26·回溯补录] 开发者工具增量编译漏新文件（反复踩）

- **问题**：新增/删除的 TS 文件未进模块表，运行时报 `module 'xxx' is not defined`，
  表现为整页无响应或白屏。
- **解决**：「工具 → 清除缓存 → 全部清除」后重编译；**删增文件后必做**。

## [2026-10-26·回溯补录] 同步 sha256 大文件阻塞主线程数十秒

- **问题**：真机上对 4.6MB 地图包同步算 sha256，逻辑层阻塞几十秒，
  表现为「正在加载地图」期间整页点击无响应（PC 工具快不易察觉）。
- **解决**：走分片异步版 `utils/sha256.ts` 的 `sha256Async`（macrotask 让出主线程）；
  异步组装摘要直接 `toHex`，误用 `sha256Hex` 会二次哈希。同步版仅用于小文本。

## [2026-10-26·回溯补录] 微信 storage 单 key 上限 1MB

- **问题**：4.6MB 地图数据 `setStorageSync` 必失败（被 kv 降级吞掉只存进程内存，冷启动丢失）。
- **解决**：地图本体走**文件缓存**（`wx.getFileSystemManager` 用户目录，
  `utils/map-cache.ts`）：启动配对（缓存摘要+文件）秒开；服务端 sha 一致免下载，
  不同则后台异步覆盖（下次启动生效，不热替换以免导航会话版本冲突）。

## [2026-10-26·回溯补录] touch 手势绑定吞掉子控件 tap

- **问题**：手势事件绑在整个地图容器上，容器内楼层切换/全图按钮的 `bindtap`
  在真机无法合成，点击无反应。
- **解决**：手势改绑 **canvas 自身节点**；所有覆盖控件设显式 `z-index`。

## [2026-10-26] 单分包 2048KB 硬限击穿端侧 WASM 路线

- **问题**：真机上传失败 `subpackage /subpackages/asr/ source size 12842KB exceed max limit 2048KB`。
  实测包体规则：主包 ≤2MB、**单分包 ≤2048KB（以错误信息为准，此前"单包限制已放开"的判断有误）**、
  合计 ≤30MB；`WXWebAssembly.instantiate(path)` **只接受代码包内路径**（下载 wasm 的路线不通）。
  减重攻坚：13.15MB wasm 经 wasm-opt -Oz + brotli(q11/lgwin24) 压到 **2281KB 仍超**（限 2048KB）；
  备选三个死胡同：① `asr-main`(10.6MB) 缺配套 glue，EM_ASM 表与主 glue 不匹配、shim 后初始化挂死；
  ② `vad-asr`(11.7MB，可压到 1967KB) 只有 Offline+VAD 导出、**无在线识别器**，且其离线 zipformerCtc
  拒绝固定 T=77 的流式模型（ORT `invalid dimensions x[1]: Got 561 Expected 77`）。
- **解决**：离线路线判死，整体切换**讯飞在线 WebSocket**（首启即联网）；
  Sherpa 分包/模型下载/后端静态路由/冒烟脚本全部删除，2048KB 超限问题随之消失。

## [2026-10-26] 引擎契约假识别器 isReady 恒 true 导致死循环

- **问题**：Sherpa 契约单测的假识别器 `isReady()` 恒返回 true，
  引擎 `while (recognizer.isReady(stream)) decode(...)` 同步死循环烧 CPU，
  jest 看似卡死（node 进程 CPU 飙升 174s+）。
- **解决**：假识别器状态随 decode 递减（喂帧 +1、decode -1）。

## [2026-10-26] 讯飞真机排障：先给引擎加分段埋点

- **问题**：真机按住说话无反应且无任何报错，无法判断断在凭据、连接、录音还是服务端。
- **解决**：给 `XfyunAsrEngine`/`XfyunTts`/装配层加 vConsole 分段日志
  （`[app] 数据源` → `[xfyun-asr] 会话开始 → 凭据就绪 → 连接建立 → 首帧已发 → 识别完成/失败`），
  断在哪一环即定位哪一层；结论固化在 docs/25 §1.5。

## [2026-10-26] mock 数据源典型症状：Network 只有 parse、无讯飞请求

- **问题**：真机按住说话松开后 Network 里只有 `POST /intents/parse`，没有任何讯飞/凭据请求，
  表面上像"没录音"。
- **解决**：这是 **mock 数据源**的正常行为（Mock 引擎不录音不联网、立即出预设文本）。
  查 vConsole 开机首行 `[app] 数据源 =`，mock 则设置页切 live 并**重启小程序**。

## [2026-10-26] 设置页数据源切换对导航页/首页不生效（编译期常量 bug）

- **问题**：导航页与首页用 `DEFAULT_DATA_SOURCE`（编译期常量）判断 mock/live，
  设置页写入的 kv 覆盖被无视——切了 live 导航页仍跑 mock。
- **解决**：统一改读 `appContext.dataSource`（构造时读 kv）；
  信标源构造抽成共用工厂 `core/ble/beacon-source-factory.ts`（锚点轨迹逻辑只留一份）。

## [2026-10-26] query_location 意图客户端无处理分支，永远停在过渡话术

- **问题**：语音「我在哪儿」后界面一直显示"请稍等，正在查询您的当前位置"——
  后端返回的过渡话术被播报后，客户端**从未发起定位查询**（applyIntent 无分支）。
- **解决**：新增 `services/location-query.service.ts` 单次定位查询：
  造观测源（mock 模拟轨迹/live 实扫）→ LocationPipeline 主动 tick（绕开 standby 8s 节流）→
  按 FE-01 质量策略出播报（reliable 报楼层+地点附近、degraded 仅楼层、
  失败/10s 超时统一"暂时无法可靠确定当前位置"，**不伪造位置**）。

## [2026-10-26] 定位接口 400：rssi strict int 遇上中位数偶数平均的小数

- **问题**：`POST /api/v1/locations/estimate` 返回 400，错误信封 `INVALID_REQUEST`。
  根因（pydantic 复现确诊）：窗口聚合每信标取 RSSI 中位数，**偶数样本取平均产生 -57.5**，
  而契约 `rssi: int` 为 strict 拒绝带小数的浮点（`int_from_float`）。mock 源 500ms 密集发样，
  偶数样本是常态必踩；导航页 mock 轨迹走同一管线同样中招。
- **解决**：`core/ble/scan-window.ts` 的 median 偶数分支 `Math.round` 取整（dBm 整数语义）；
  测试补 `.5` 样本断言整数防回归。

## [2026-10-26] 文档≠实测：超拟人合成请求 text 必须 base64

- **问题**：按官方文档明文示例发 `payload.text.text`，真实网关返回
  `10163 ... field 'text' must be encode to base64 string`。
- **解决**：`xfyun-tts.ts` 请求帧 text 改 `utf8ToBase64`。
  **教训：单测只能对照文档公式，协议真实差异必须靠真实服务冒烟暴露**——
  本次用标准库手写最小 ws 客户端（客户端帧须掩码）做了「签名握手 101 → 协议帧往返
  → 合成落盘 mp3」全链路冒烟，同法也验证了听写链路。

## [2026-10-26] 微信 wss 自定义请求头真机不稳 → 讯飞鉴权选 URL 签名

- **问题**：讯飞超拟人鉴权方式一要求 `x-api-key` 请求头，但微信社区实测
  WebSocket 自定义 header「手机端/工具正常、电脑端小程序不生效」，官方社区亦建议
  不手动设置握手头。
- **解决**：采用**方式二 URL 签名**（与听写同构，后端签发、零 header 依赖、多端一致）；
  方式一仅作为无 key/secret 时的备选并标注 PC 端边界。

## [2026-10-26] fake timers 单测：窗口类组件必须持续供样

- **问题**：LocationQueryService 首版测试「未在驱动窗口内收敛」——
  假观测源只在 start 发一次样本，fake 时钟被 advance 推进后样本恰好被
  50ms 窗口的严格 `>` 边界剔除 → 永远凑不齐 3 个信标、永不发请求。
- **解决**：假源改为 `setInterval` **持续供样**（与真实源周期发射同语义），
  任意 tick 时刻窗口都有新鲜观测；另注意 jest `-t` 过滤是**正则**（`+` 等是元字符）。
