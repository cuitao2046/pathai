# PathAI · AOD 技术室内导航方案调研与成本测算

> **面向**：初中学部 1# 教学楼（2 层 / 136 间房 / 208 扇门）——视障学生为核心用户的室内定位与语音导航
> **现有资产**：CAD PDF→GeoJSON 地图（v9）、拓扑路网（593 边）、交互式 HTML 渲染、路线规划引擎、现场勘测工具包
> **调研日期**：2026-08-11

---

## 一、背景与目标

### 1.1 问题定义

视障学生在教学楼内的核心痛点：

- **无法依靠视觉识别**教室门牌、楼梯口、卫生间标牌
- **GPS 在室内失效**，无有效室内定位手段
- 蓝牙信标虽能提供粗粒度定位（2~5m），但对于"找到正确的教室门口"（需要 ≤1m 精度）仍不够
- 学校场景下要求**低成本、易维护、不破坏既有建筑装修**

### 1.2 本调研范围

以 **AoD（Angle of Departure，离开角）** 蓝牙 5.1 高精度定位为核心技术路线，结合项目已有的 CAD 地图 + 拓扑路网 + 语音导航引擎，提出完整落地方案并测算成本。

同时对比 **AoA（到达角）、RSSI 三角定位、AR 视觉 SLAM** 三种替代方案。

## 二、AoD 技术原理

### 2.1 什么是 AoD

AoD 是蓝牙 5.1 核心规范引入的**方向查找（Direction Finding）** 能力之一：

```
┌──────────────────────┐
│   发射端（Beacon）     │
│   ┌─┐ ┌─┐ ┌─┐ ┌─┐   │  天线阵列轮流发射
│   │A│ │B│ │C│ │D│   │  含 CTE 的广播包
│   └─┘ └─┘ └─┘ └─┘   │
└──────┬───────┬───────┘
       │  d1   │  d2    ← 不同天线到手机的路径差
       ▼       ▼
┌──────────────────────┐
│   接收端（手机）       │
│   ┌─┐                │  单天线接收 IQ 采样
│   │★│                │  计算相位差 → 出发角 θ
│   └─┘                │
└──────────────────────┘
```

- **发射端**（AoD Beacon）：配备天线阵列（通常 4~8 根），按顺序切换天线发送含 CTE（Constant Tone Extension）的广播包
- **接收端**（手机，Android 8+ / iOS 14+）：单天线接收，通过 IQ 采样计算相邻天线间的相位差，反推信号出发角度 θ
- **定位计算**：手机采集 ≥2 个 Beacon 的角度信息 + 三角测量 → **(x, y)** 坐标，精度可达 **0.3~1.0m**（亚米级）

### 2.2 为什么选 AoD 而非 AoA

| 维度 | AoD（出发角） | AoA（到达角） |
|------|--------------|--------------|
| 发射端 | Beacon 多天线阵列（固定部署） | 标签单天线（移动端） |
| 接收端 | 手机单天线 | 基站多天线阵列（固定部署） |
| 隐私 | ✅ 手机本地计算，不上报位置 | ❌ 基站计算，需上报信号 |
| 手机兼容 | ✅ Android 8+ / iOS 14+ 原生支持 | ❌ 手机无多天线阵列 |
| 并发 | 理论无上限（手机各自算） | 受基站处理能力限制 |
| 部署 | Beacon 电池供电（3~5 年） | 基站需 PoE/DC 供电 |

**结论**：视障用户用个人手机导航、对隐私敏感 → **AoD 是天然匹配**。

### 2.3 精度分析

| 场景 | 预期精度 | 说明 |
|------|---------|------|
| 走廊直线段（LOS 无遮挡） | 0.3~0.5m | 天线阵列 + CTE 理想条件 |
| 教室门附近（LOS） | 0.5~0.8m | 可区分相邻教室门口 |
| 走廊交叉口 / 大厅 | 0.5~1.0m | 轻微多径影响 |
| 楼梯间 / 电梯厅 | 1.0~1.5m | 空间狭小 + 金属反射 |
| 非视距（NLOS，人墙遮挡） | 1.5~3.0m | 需融合 IMU（惯性导航）补偿 |

**与需求对比**：
- 区分相邻教室门口（间距通常 3~4m）→ 需要 ≤1m → ✅ AoD 满足
- 卫生间入口识别 → ✅ 满足
- 楼梯/电梯口 → ⚠️ 需辅以 IMU + 地图匹配

## 三、方案总体架构

### 3.1 系统五层架构

```
┌──────────────────────────────────────────────────────┐
│                  ⑤ 交互层（手机端）                      │
│   微信小程序 / iOS App                                  │
│   语音播报 · 震动提示 · 盲模式 · 紧急求助                │
├──────────────────────────────────────────────────────┤
│                  ④ 导航引擎                             │
│   AoD 实时定位 ←→ 拓扑路网匹配 ←→ Dijkstra 路线           │
│   地图匹配 · IMU 航位推算 · 楼层切换检测                   │
├──────────────────────────────────────────────────────┤
│                  ③ 地图数据层                           │
│   GeoJSON 地图 + 拓扑图 + Beacon 坐标索引                 │
│   房间语义 · 门属性(常开/常闭) · 无障碍属性                │
├──────────────────────────────────────────────────────┤
│                  ② 定位基础设施                         │
│   AoD Beacon 天线阵列 × N（走廊/楼梯口/大厅/关键门附近）     │
│   手机端 SDK：BLE 扫描 + CTE IQ 采样 + 角度计算            │
├──────────────────────────────────────────────────────┤
│                  ① CAD 地图预处理                       │
│   PDF 解析 · 墙体矢量化 · 房间识别 · 门洞提取              │
│   拓扑构建 · 路线规则 · 空间语义标注（已完成 v9）           │
└──────────────────────────────────────────────────────┘
```

### 3.2 与现有 CAD 地图的衔接

本项目已从建筑业 CAD PDF 图纸生成高精度室内地图（GeoJSON v9），包含：

- ✅ 墙体线段 4442 段（米制坐标，局部坐标系）
- ✅ 房间 136 间（含类型、标签、质心坐标）
- ✅ 门 208 扇（含类型 swing/fire/opening、常开/常闭属性）
- ✅ 拓扑路网：F1 284 节点/350 边，F2 181 节点/243 边，跨层 10 条
- ✅ 走廊骨架线（手动标注）
- ✅ 房间无障碍属性（accessible / public）

**AoD Beacon 部署点位直接从 GeoJSON 数据生成**：

1. **走廊交叉口** ← `topology.nodes` 中 `nodeType=intersection` 的 TI 节点坐标
2. **关键门口** ← `semantic.rooms` 中教室/卫生间/楼梯间/电梯厅入口（`geometry.doors` 的 `center_m` 坐标）
3. **楼梯口/电梯口** ← `semantic.stairs` / `semantic.elevators` 边界中点
4. **大厅/门厅** ← `semantic.rooms` 中 `type=lobby/atrium` 的中心区域

无需人工现场逐点标定，直接用已有坐标系自动导出 Beacon 部署坐标列表。

## 四、部署方案

### 4.1 建筑参数

从 CAD 图纸实测（GeoJSON v9 米制坐标）：

| 指标 | 数值 |
|------|------|
| 建筑外轮廓（BBox） | 101.9m × 134.8m |
| 楼层 | 2 层（F1: 81 间 / F2: 55 间） |
| 总房间数 | 136 间（含教室、办公室、实验室、卫生间、楼梯间等） |
| 总门数 | 208 扇（132 + 76） |
| 走廊总长度（估算） | ~250m/层 × 2 = ~500m |
| 走廊交叉口（TI 节点） | F1 78 个 + F2 53 个 = 131 个 |
| 拓扑边总长度（估算） | ~1.2km（350 + 243 + 10 边） |

### 4.2 Beacon 部署点位

采用**分层部署策略**：走廊精确定位 + 关键门口确认 + 楼梯/电梯楼层切换。

| 部署层级 | 位置 | 间距 | 数量 | 说明 |
|---------|------|------|------|------|
| **A 级：走廊交叉口** | 每个 TI 交叉口 1 个 | — | 131 个 | 用于三角定位 + 转弯指令触发 |
| **B 级：走廊直线段** | 沿走廊每隔 8~12m | 8~12m | ~50 个/层 | 保证任意位置可见 ≥2 个 Beacon |
| **C 级：关键门口** | 教室/卫生间/楼梯/电梯门 | 每门 1 个 | ~150 个 | "到达正确门口"确认 |
| **D 级：楼梯间/电梯厅** | 每层楼梯口 + 中间平台 | 每层 2~3 个 | ~12 个 | 楼层切换检测 + 安全预警 |

**总计 Beacon 数量**：

| 楼层 | A 级 | B 级 | C 级 | D 级 | 小计 |
|------|------|------|------|------|------|
| F1 | 78 | 25 | 80 | 6 | **189** |
| F2 | 53 | 25 | 55 | 6 | **139** |
| **合计** | **131** | **50** | **135** | **12** | **328** |

> **说明**：C 级只覆盖视障用户高频访问房间（普通教室、专用教室、卫生间、教师办公室、楼梯、电梯），不对管道井、配电室等不可进入房间部署。

### 4.3 精简方案（降低成本）

若预算有限，可将 B 级删减、A+C 级合并复用：

| 方案 | Beacon 数 | 走廊定位精度 | 门口确认精度 | 总成本节省 |
|------|----------|------------|-------------|-----------|
| **完整方案** | 328 | 0.3~0.5m | 0.5~0.8m | 基准 |
| **精简方案** | ~200 | 0.5~1.0m | 0.5~1.0m | **~40%** |
| **最小方案** | ~130（仅 A 级覆盖） | 1.0~2.0m | 无专项确认 | **~60%** |

> **推荐**：学校场景下建议走**精简方案（~200 个 Beacon）**，A 级全覆盖 + C 级高频房间门口 + 走廊每 15m 补点，精度可满足视障需求。

## 六、技术方案对比

### 6.1 四种方案横向对比

| 维度 | **AoD（本方案）** | AoA 基站 | RSSI 三角定位 | AR 视觉 SLAM |
|------|-----------------|---------|-------------|-------------|
| 定位原理 | Beacon→手机测角 | 基站测标签角 | 信号强度→距离 | 摄像头→特征匹配 |
| 典型精度 | 0.3~1.0m | 0.1~0.5m | 2~5m | 0.3~0.5m |
| 硬件部署 | Beacon × ~200（贴装） | 基站 × ~40（需 PoE 布线） | Beacon × ~100 | 无需（依赖手机摄像头） |
| 硬件成本 | ¥2.9~4.1 万 | ¥6~12 万 | ¥1~2 万 | ¥0 |
| 手机端要求 | BLE 5.1+（市面主流均支持） | 需额外标签 | BLE 4.0+ | 需手持摄像头对准前方 |
| 视障可用性 | ✅ 手机放口袋，语音导航 | ✅ 需佩戴定位标签 | ⚠️ 精度不足区分门口 | ⚠️ 需手持举着手机对准前方 |
| 隐私 | ✅ 手机本地计算 | ❌ 位置上传基站 | ✅ 手机本地计算 | ✅ 本地计算 |
| 维护 | 3~5 年换电池 | 基站保电 + 网络 | 3~5 年换电池 | 地图定期更新 |
| 适用场景 | 中小型建筑，隐私敏感 | 大型园区，需后台监控 | 大区域粗定位 | 已有完善视觉特征的环境 |

### 6.2 蚂蚁集团 AR 方案参考

蚂蚁集团 2024~2025 年为视障人士开发的室内导航产品采用**视觉空间定位 AR 方案**（非蓝牙），精度 0.5m。其选择逻辑：

- ✅ 无需部署硬件 Beacon，零硬件成本
- ✅ 视觉特征丰富的室内环境（办公室、商场、展馆）
- ⚠️ **需要用户手持手机、摄像头对准前方**——对视障用户是额外操作负担
- ⚠️ 依赖摄像头成像质量（暗光/逆光失效）

**与本场景的差异**：教学楼走廊以白墙为主，视觉特征不够丰富；视障学生更适应用语音+震动而非手持手机对准前方。因此本方案优先蓝牙 AoD，手机可在口袋/挂绳中运行。

### 6.3 推荐方案：AoD + IMU 融合

```
手机 IMU（加速度计+陀螺仪）
        ↓
   航位推算（步数×步长+方向）
        ↓
  ┌─────────────────────┐
  │ 卡尔曼滤波融合       │ ← 地图匹配约束（走廊直线/墙角）
  │ AoD 测角 + IMU 推位  │
  └─────────────────────┘
        ↓
  连续位置 (x, y, θ, floor)
        ↓
  ┌─────────────────────────────┐
  │ 路线引擎（已有）              │
  │ 当前段 + 下个转弯距离 + 偏差  │ → 语音："前方 5 米左转"
  │ 门口确认（信标距门口 <0.8m） │ → 震动 + "您已到达 初一(3)班"
  └─────────────────────────────┘
```

AoD 提供绝对位置锚点（每秒 1~2 次），IMU 在两次 Beacon 扫描之间做连续推位（100Hz），弥补 NLOS 和非视距盲区。

## 七、实施路线图

### Phase 1：Beacon 部署点位自动生成（1 周）
- 开发 `export_beacon_plan.py`：从 GeoJSON 按 A/B/C/D 级规则自动导出 200~328 个 Beacon 部署坐标 CSV
- 在同一米制坐标系下标注点位编号、楼层、位置描述、三轴安装角度
- 输出可直接印刷的楼层 Beacon 点位图（叠加到现有交互式 HTML）

### Phase 2：AoD SDK 集成与原理验证（3 周）
- 选型 AoD Beacon 硬件供应商（Nordic nRF5340 / TI CC2652 方案）
- 采购 10~20 个样机
- Android 端集成 BLE CTE 扫描 + IQ 采样 + AoD 角度计算
- 在教学楼 F1 选取 3 段走廊（含 1 个交叉口 + 2 个教室门）做**精度验证**

### Phase 3：导航小程序开发（4 周）
- 微信小程序开发：地图加载 → AoD 定位 → 路线规划 → 语音播报
- 视障交互：语音 + 震动双通道、分段式指引、危险预警（楼梯/电梯口）
- 对接已有路线引擎（`route_rules.py` / 前端 Dijkstra）

### Phase 4：全楼部署与用户测试（2 周）
- 按精简方案全楼安装 200 个 Beacon
- 邀请视障学生/特教老师参与内测

## 八、风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| AoD Beacon 多径干扰（走廊金属扶手/玻璃幕墙） | 精度下降至 1~2m | 中 | 增加 Beacon 密度（8m→6m 间距）+ IMU 融合补偿 |
| 部分老旧手机不支持 BLE 5.1 CTE | 无法用 AoD 定位 | 低（2024+ 机型均支持） | 回退 RSSI 粗定位 + IMU 为主 |
| Beacon 被学生误触/破坏 | 局部定位失效 | 中 | 高位安装（距地 2.5m+）、每周巡检 |
| 走廊人墙遮挡 NLOS | 定位漂移 | 中 | IMU 航位推算撑 3~5 秒，地图匹配约束走廊直线 |
| 教室重新装修改变布局 | 地图过时 | 低 | 现场勘测工具包可快速复测，更新 GeoJSON 后重导 Beacon CSV |
