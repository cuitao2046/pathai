# 决策模型选型调研：专用决策/分类模型 vs 通用大模型

> 调研范围：语音入口的「意图判断 → 动作选择 → 地名对齐」三件事，是否值得从通用大模型换成专用决策/分类模型。
> 证据标注：**[实测-本项目]** 来自本仓库代码/日志；**[文献]** 来自论文或公开评测；**[文档口径]** 直接引自厂商文档；**[估算]** 为工程推算，未实测；**[文档未提供]** 表示厂商文档没有该项说明。
> 调研日期：2026-11-15。本文只做调研，未改动任何代码。

---

## 一、结论先行

1. **「Jev」没有记错。** 最可能指 **TypeSafe AI 的 Jev**——2026 年 9 月发布的「System One Model」，输入 `state` + 带类型的问题，只返回 `choice / score / noul` 三类结构化判断，不生成文本，官方标称 70–500ms，输入 $0.25–0.42/百万 token、输出免费。**[文献]**
   但它对本项目有三个硬伤：**闭源托管、只能联网调用、以英文为训练主语言（中文可用但准确度低于英文）**。因此**不建议把 Jev 云 API 作为主链路**。

2. **该换的不是"全部"，而是"动作选择"这一层。** 动作空间只有 8 个、边界由系统提示词固定、变化极慢，属于"窄域稳定 schema"，正是微调小模型全面胜出的场景（ATIS：微调 RoBERTa 95.9% vs 零样本大模型 84.1%）**[文献]**。

3. **地名语义对齐不要换。** 「放乐器的那间」「上物理课的地方」这类**零字面重叠**的匹配依赖世界知识，是向量检索最脆弱、大模型最强的环节（CLINC150 上 embedding kNN 75.1% vs 微调 89.1%）**[文献]**。本项目只有 55 个 POI，全量塞进 prompt 完全可行 **[实测-本项目]**，换成检索反而多一层误差。

4. **现有分层已经不够用，根因是延迟不是准确率。** 实测云端大模型 TTFT：P50 **3033ms**、P90 **5391ms**、最大 **10452ms**（n=95）**[实测-本项目]**，而项目文档要求端到端首字发声 ≤ 800ms **[项目文档 docs/26 §6]**。也就是说大模型每命中一次，就已经超预算 4–13 倍。**要保延迟，只能让大模型变成"稀有路径"。**

5. **推荐分层（四层，大模型只在最后一层）**：
   `客户端规则/别名` → `服务端 POI 精确 + 拼音模糊` → `8 类动作本地小模型` → `大模型兜底（零召回/低置信/需生成）`。
   相比现状，新增的只有第 3 层；第 1、2 层是纯工程收益，风险最低、收益最大，应最先做。

6. **不建议现在上的**：Jev 云 API（离线/中文/合规）、4B 级本地函数调用模型（无 GPU 时 CPU 推理 3–8s/次 **[估算]**，无法满足 800ms）、以及任何"用向量替代大模型做最终决策"的方案。

7. **追加对象（火山引擎方舟「决策评估 beta」）的结论**：形态与 Jev 同构（`state`+`questions` → `choice/score/noul`，选项上限同为 255），但**中文原生、境内、可复用现有 Ark key**，是 Jev 的有效替代。它适合接在**「动作选择」这一层**，不适合做 POI 对齐（拿不到 top3 结构与澄清话术，且非流式）；**它是云端方案，解决不了局域网私有/离线，也解决不了 800ms 延迟——文档根本没给延迟指标**。结论：**值得接，接在第 3.5 层做加速器，先跑 E6/E7 两条影子实验**。

**对"是否记错"的判断**：Jev 是真实产品，指代基本可确认。若你原本想的是别的名字（如 JEPA 一类架构名），本文的结论不受影响——因为结论建立在"专用决策/路由/分类模型"这一类别上，而不是某一个具体产品。

**但要注意两条反证**：
- Jev 在中文、短句、含 ASR 错字的输入上缺少公开评测，且有一个第三方中文实测显示**空响应率 5.6%**、情绪激烈样本易误判 **[文献]**。对"说完必须有反馈"的视障场景，5.6% 静默是不可接受的。

## 三、四条专用小模型路线

### 3.1 意图分类微调小模型

做法：中文 BERT/RoBERTa/MacBERT-small 或 TF-IDF+LR 做 8 类（+OOS）分类头；标注不足时用 SetFit 类 few-shot 方案。

| 维度 | 表现 | 等级 |
|---|---|---|
| 窄域准确率 | ATIS（26 意图）微调 RoBERTa 95.9% vs Claude 零样本 84.1%，差 +11.8pt（p=2e-4） | **[文献]** |
| 宽域准确率 | CLINC150（150 意图）89.1% vs 88.5%，统计上打平 | **[文献]** |
| OOS 识别 | RoBERTa 召回 58.1% vs 大模型 85.6% | **[文献]** |
| schema 变化 | 换一套全新意图集后准确率 **0%**（分类头物理上无法输出未训练标签）；大模型 93.9% | **[文献]** |
| 延迟 | 小模型 ONNX 单句 5–20ms（笔记本 CPU） | **[估算]** |

**对本项目**：8 个动作的 schema 一年也不会变，属于"窄域稳定"；"换楼"只换 POI 词典、不换动作集，所以 CLINC150 那种"schema 全换 → 0%"的风险在本项目**不成立**。真正缺的是**标注数据**。

### 3.2 embedding + 向量检索式语义路由

做法：把每个 action 的描述、每个 POI 的名称+别名编码成向量，用户文本编码后取 top-k，过阈值即路由。

| 维度 | 表现 | 等级 |
|---|---|---|
| CLINC150 全量示例 kNN | 75.1%（微调 89.1%、大模型 88.5%） | **[文献]** |
| 5-shot kNN | 64.2% | **[文献]** |
| 延迟 | bge-small-zh + 55 条 POI 向量，单次 5–15ms | **[估算]** |
| 强项 | 便宜、可解释（能给出最相近的示例句）、易增量（加一条示例即生效） | — |
| 弱项 | 短句、口语、ASR 错字下 cosine 不稳定；零字面重叠时靠不住；阈值随语料漂移 | **[文献]** + **[估算]** |

**对本项目**：只适合做**粗筛/召回**（把 55 个 POI 缩到 5 个），不适合做最终决策。而 55 个 POI 本来就能全塞进 prompt，召回收益接近 0——**除非 POI 涨到千级或多楼合并**。现在上属于过度设计。

### 3.3 函数调用专用路由模型

做法：用经过 tool-use 微调的小模型（xLAM-2、Hammer 2.1、Qwen3-4B 等）直接输出 `{action, params}`。

| 模型 | 公开评测 | 等级 |
|---|---|---|
| Qwen3-4B-Instruct | BFCL 综合 ~86–87%（sub-7B 领先） | **[文献]** |
| xLAM-2-3b-fc-r | BFCL v4 综合 41.22 | **[文献]** |
| Hammer2.1-7B | ACEBench 部分子项 0 分，稳定性差 | **[文献]** |

**对本项目**：
- 通用 BFCL 比"8 选 1 + 55 选 1"难得多，榜分不能直接外推；但小模型在"工具缺失时乱调"上明显更差（有评测显示缺函数时 94–95 次误调用）**[文献]**，这对视障导航是**高危错误**（该说"没这个地点"却去导航）。
- **无 GPU 时 4B 模型 CPU 推理约 3–8s/次 [估算]，直接违反 800ms 预算**。有 GPU 或换 0.6–1.5B 才可能进入候选。

### 3.4 多标签 / 序列标注拆解

做法：把一次决策拆成多个头——`action` 多标签分类 + `POI span` 序列标注（NER）+ `是否 OOS` 二分类。

| 维度 | 表现 | 等级 |
|---|---|---|
| 多意图/"既说开始又说地点" | 比单标签更稳，不需要靠提示词规则兜 | **[估算]** |
| slot 抽取 | NER 抽地名比生成更不易编造；但抽到的 span 仍需映射到标准名 | **[估算]** |
| 训练成本 | 需要 span 级标注，标注成本最高 | — |

**对本项目**：动作只有 8 个且互斥性较强（唯一真冲突是 `start_navigation` vs `navigate_to_place`，已有提示词规则处理），多标签收益有限。**不值得为它单独付标注成本**，可作为 3.1 分类器的副产品（两个头共享编码器）。

### 4.4 与四条路线的定位差异

| 路线 | 决策依据 | 与火山决策评估的关系 |
|---|---|---|
| 微调小模型 | 训练出的分类头 | 火山**不需要训练**，改 criteria 即生效；但离线能力、延迟（5–20ms）小模型完胜 |
| 向量路由 | 余弦近邻 | 火山是**语义判别**而非检索，零字面重叠时更强；但贵、要联网 |

### 4.5 对本项目两件事的判断

**A. 8 类动作选择：合适度高，是当前最优的「云端快速路」**

- 契合点：`choice` + 8 条 criteria + 官方建议的「信息不足」兜底选项，几乎是为这个场景设计的；中文原生；复用 Ark key；输出免费。
- 卡点：
  1. **必须联网**——「局域网私有部署」这条硬约束不成立；
  2. **延迟无口径**，且非流式，需要实测能否落进 800ms 预算（扣掉 ASR 与 TTS，意图层大约只剩 300–500ms）**[估算]**；
  3. beta，无 SLA，单模型无备选；
  4. 只能选动作，**不能顺带产出澄清话术或 top3 理由**。

**B. 零命中时在地点清单里对齐 POI：只能部分承担，不建议单独用**

- 能做：`choice` 支持 55 个选项（≤255），选项名可以是「标准名+楼层」，返回全量概率，可自行排序取 top3。**[文档口径]** + **[估算]**
- 做不到 / 代价大：
  1. 没有 top3 的结构化字段，要自己按 `probabilities` 排；同名多实例（3 间领导办公）必须用唯一 key 拼楼层，映射回 `placeId` 仍要一层本地逻辑；
  2. **没有澄清问句**，要话术就再调一次 Chat API → 多一跳，直接违背「零静默 + 低延迟」；
  3. 55 个中文长名称会让 `state` 膨胀到 1.5–2.5k token，检索式方案在这里反而更省；
  4. beta 阶段是否会出现「答案缺失」没有承诺，视障场景不能赌。

**结论：POI 对齐继续用现有 Chat 大模型；火山决策评估只用在「选动作」这一层。**

### 4.6 值不值得接、接到第几层、先验证什么

**值得接，但只作为「第 3.5 层的可选加速器」，不作为私有化方案。**

- 第 3.5 层的含义：本地规则未命中后，先看这次是不是「只要能选对动作」——
  - 是 → 火山 `choice`（8 类 + 信息不足），拿到动作后由本地 skill 执行；
  - 否（还要对齐 POI、生成话术）→ 走现有 Chat API。
- 明确不做的事：不用它替代离线路径；不用它单独做 POI 对齐；不在 beta 期把它放在唯一链路上。

**上线前必须验证（在第十节 E1–E5 之外新增两条）**

| # | 实验 | 通过门槛 |
|---|---|---|
| E6 | 同一测试集上对比：火山 `choice`(8 类) / 现有 Chat API / TF-IDF 基线 | action 准确率不劣于 Chat API；「信息不足」选项 OOS 召回 ≥85%；**P95 ≤500ms**；异常/空答案 = 0 |
| E7 | 同一批零命中样本，比较火山 55 选项 `choice` top3 与 Chat API top3 | top3 recall 差距 ≤5pt 才考虑换；否则只做影子 |

> 注意：E6/E7 都要用**真机录制的带 ASR 错字样本**，不能用合成错字，否则会高估。

## 六、混合分层是否更划算

### 6.1 现状 vs 建议

```
现状：  快路径（正则） → 云端大模型（含全部 POI + 全部动作说明） → 规则降级
        └ 命中率低 ┘    └ 每次 3s+，且只在规则未命中时触发 ┘
```

```
建议：  ① 客户端规则/别名          （已有，保留）
        ② 服务端 POI 精确 + 拼音模糊 + 编辑距离   ← 新增，纯本地，最高性价比
        ③ 8 类动作本地小模型（ONNX）             ← 新增，可选
        ④ 大模型兜底（零召回 / 低置信 / 需生成话术）
```

**为什么这样分**：
- 第 ② 层解决的是**实测里最常见的失败**：日志中出现「行动办公室」（行政办公室）、「公式/公示」、「各班教室」、「近的教室」等，全是**同音字/近音字/口语省略**，用拼音 + 编辑距离就能吃掉一大半 **[实测-本项目]**。
- 第 ③ 层解决"动作判断"；只有 8 个互斥动作，小模型足够，且能把 3s 压到 20ms 内。
- 第 ④ 层保留"零字面重叠 + 需要生成播报"的能力，但调用频次从"每次未命中"降到"每周个位数"。

### 6.2 阈值怎么定（起始值，必须在自建集上标定）

| 层 | 判据 | 处置 | 备注 |
|---|---|---|---|
| ② 精确名/别名命中 | 完全相等 | 直接给候选，conf 0.95 | 与现有规则一致 **[实测-本项目]** |
| ② 拼音全等（声母韵母全同） | 拼音串相等 | 直接给候选，conf 0.85 | 覆盖"行动→行政" |
| ② 编辑距离 | 归一化距离 ≤0.2（2–4 字词允许 1 字差） | 给 top3 让用户选，conf 0.7 | 覆盖"公示/公式" |
| ② 类别词命中（教室/厕所） | 类别别名命中 | 给候选列表，conf 0.6 | 与现有类别逻辑一致 |
| ③ 动作分类 | P ≥ 0.80 且 top1-top2 ≥ 0.15 | 直接执行 | **保守**：视障场景执行错 > 多问一句 |
| ③ 动作分类 | 0.50 ≤ P < 0.80 或 margin < 0.15 | 追问/确认 | |
| ③ 动作分类 | P < 0.50 或判为 OOS | 交第 ④ 层 | |
| ④ 大模型 | ④ 仍低置信 | 模板兜底："没找到，请说房间名或附近标志物" | 已有话术 **[实测-本项目]** |

> 阈值不要拍脑袋：在第十节的测试集上扫 P-R 曲线，按"误执行成本 ≈ 5× 多问一句成本"加权取点 **[估算，需现场定]**。

### 6.3 划算吗

| 方案 | 相对现状的改动 | 预期收益 | 风险 |
|---|---|---|---|
| 只加第 ② 层（拼音模糊） | 小（纯函数） | 未命中率大幅下降，大模型调用次数下降 | 极低 |
| 加第 ③ 层（动作分类） | 中（需标注 + ONNX 部署） | 3s → 20ms；动作判断更稳 | 中（OOS 变差，需兜底） |
| 把 ④ 换成本地 4B | 大 | 离线 | **高（无 GPU 时延迟不可接受）** |
| 全换 Jev 云 API | 中 | 快、便宜 | **不可接受（离线/中文/空响应）** |

**结论：② 的收益/成本比最高，③ 次之，④ 的替换目前不划算。**

## 七、本项目约束下的判断

| 约束 | 实测/事实 | 对选型的含义 |
|---|---|---|
| 服务端 Windows 笔记本、**可能无 GPU** | 后端为 Python，LLM 走 OpenAI 兼容 HTTP **[实测-本项目]** | 只考虑 ≤0.5B 的 ONNX 级模型；4B 级不可行 |
| 局域网私有部署 | 但当前 LLM 实际指向**云端** OpenAI 兼容接口 **[实测-本项目]** | "离线可用"是未兑现的承诺；本地小模型是唯一能兑现的路径 |
| 中文 ASR 错字/口语 | 日志实测：`行动办公室`、`公式`、`公示`、`各班教室`、`近的教室`、`跑到各班教室请去` **[实测-本项目]** | 任何方案都必须先做**同音字归一**；纯向量方案对此最脆弱 |
| 地点数量百级 | 当前地图 `places` = **55** **[实测-本项目]** | 全量入 prompt 可行；向量召回暂无必要 |
| 延迟敏感 | TTFT P50 3033ms / P90 5391ms / max 10452ms（n=95）**[实测-本项目]**；目标 TTFA ≤800ms **[项目文档]** | 云端大模型只能作为低频兜底 |
| 有真实语料但很少 | 日志中可提取**完整语句 38 条、去重 32 条**，其中约 1/3 是 ASR 噪声/半截话 **[实测-本项目]** | **测试集目前不够**，必须先补埋点 |

**一句话**：这套约束组合（无 GPU + 离线 + 中文 ASR 噪声 + 强延迟约束）**天然指向"本地小模型做固定决策 + 大模型做开放语义"**，而不是"更强的通用大模型"。

## 八、明确结论：哪些换、哪些留

| 环节 | 建议 | 理由 | 优先级 |
|---|---|---|---|
| 快路径（"我在哪/再说一遍"） | **保持本地规则** | 已实现，<20ms | 不动 |
| POI 精确名/别名 | **保持 + 扩充本地规则** | 别名表是最便宜的知识 | P0 |
| POI 同音/近音/错字 | **新增本地拼音模糊 + 编辑距离** | 实测语料里这是主因 | **P0** |
| 8 类 action 选择 | **换本地小模型（先基线后 ONNX）** | 窄域稳定，3s→20ms | P1 |
| 8 类 action（云端加速版） | **火山决策评估作第 3.5 层，先影子验证** | 中文原生、复用 Ark key、输出免费；但延迟无口径 | P1.5（E6 通过后） |
| 零字面重叠 POI 对齐（"放乐器的那间"） | **继续用大模型** | 需世界知识；55 条全量入 prompt 可行 | 保留 |
| POI 对齐（火山 choice 版） | **不做主链路，只做 E7 对比** | 只给 1 个 choice + 概率，无 top3/话术，非流式 | 仅实验 |
| 澄清问句 / 播报文案 | **继续用大模型** | 生成类任务，小模型不划算 | 保留 |
| Jev 云 API | **不上，改用火山同类能力** | 闭源+联网+中文弱+5.6% 空响应+境外 | 否决 |
| Laya 等本地决策模型 | **列为 P2 候选，先自测再决定** | CPU 可跑、7–60ms，但中文未验证 | P2 |
| 向量召回 | **POI 涨到千级或多楼再上** | 55 条时无收益 | 暂缓 |

## 九、落地顺序

**P0（先做，不改模型，风险最低）**
1. **补埋点**：把用户原文、规则命中情况、最终 action、目标 POI、是否人工纠正落盘（当前日志只有 TTFT，没有可复盘的结构化样本）**[实测-本项目]**。
2. **同音字归一**：pypinyin 转拼音串，全等/编辑距离 ≤0.2 视为命中；在 55 个 POI + 别名上跑一遍，先量化能吃掉多少失败样本。
3. **扩别名表**：把现场真实说法（"行动办公室"、"合班教室"、"近的教室"）补进 `aliases`，一次投入长期收益。

**P1（1–2 轮迭代后）**
4. **动作分类基线**：先 TF-IDF+LR（几小时可跑通），再换中文小 BERT；只在"地点已解析、动作不明"与"控制类短句"上接管。
5. **ONNX 部署 + 影子模式**：小模型与云端大模型并行，只记录不执行，跑 2 周比一致率。
6. **阈值标定**：在测试集上扫 P-R，按"误执行成本 5×"取点。
7. **火山决策评估 E6 影子对比**：8 类 `choice` + 「信息不足」选项，与 Chat API 在同一测试集上比准确率、OOS 召回、P50/P95；**只在 P95 ≤500ms 且空答案 = 0 时才进主链路**，否则保持为备选加速器。

**P2（有数据支撑后再动）**
8. **本地决策模型自测**：用同一测试集评 Laya 322M 多语言 / Qwen3-0.6B，只在中性样本上比，重点看**中文 + ASR 噪声**下的准确率与空响应率。
9. **零重叠对齐成本优化**：把大模型结果按（归一化文本 → POI）做缓存，同类说法第二次直接命中。

**P3（触发式）**
10. POI 超过 ~300 条或合并多楼时，再引入向量召回做粗筛。

## 十、实验设计：怎么用现有日志构造测试集

### 10.1 现状（必须先承认的限制）
- 日志里能提取的完整用户语句只有 **38 条、去重 32 条**，且大量是"我在哪里/周边有什么"这类已被快路径覆盖的句子 **[实测-本项目]**。
- 样本中已能看到真实 ASR 错误（行政→行动、公示/公式），说明噪声形态是**同音字 + 半截话 + 口述指令混入**，不是随机字符替换。

### 10.2 构造方法
1. **先扩采（2 周）**：开启 LLM trace 落盘 + 现场录 10–15 人 × 每人 20 句；要求覆盖四类：位置查询、导航（含别名/类别/零重叠）、导航控制、无关闲聊。
2. **人工标注三件事**：① 正确 action；② 目标 POI 的 `placeId`（未找到则标 `not_found`）；③ 是否 OOS。
3. **切分**：按"说话人 + 日期"切分 train/val/test，禁止同一句话跨集；OOS 单独一份，不参与准确率平均。
4. **合成增广（只进 train）**：用同音字表/拼音混淆集生成错字变体，模拟 ASR；**验证集和测试集必须是真人真机录的**，否则会高估。

### 10.3 指标（不要只看准确率）
| 指标 | 为什么看 |
|---|---|
| action 准确率 | 基础 |
| POI top1 / top3 recall | 决定"直接走"还是"给候选" |
| **误执行率**（选错 POI 且直接开始导航） | 视障场景最贵错误，应作为主优化目标 |
| OOS 召回 | 决定会不会对无关话硬答 |
| 不必要追问率 | 追问太多会打断行走节奏 |
| TTFT P50/P95、端到端 TTFA | 硬约束 ≤800ms |
| 空响应率 | Jev 类模型的已知短板（5.6%）**[文献]** |

### 10.4 最小可判定实验（建议按此顺序做）
| # | 实验 | 通过标准 |
|---|---|---|
| E1 | 拼音模糊匹配在现有 55 POI 上的覆盖率 | 现有失败样本中 ≥50% 可被本地规则吃掉 |
| E2 | TF-IDF+LR 8 类动作（真实语料 300 条） | ≥90%，OOS 召回 ≥80% |
| E3 | 中文小 BERT vs TF-IDF vs 现提示词（同一测试集） | 小模型不劣于提示词，且 TTFT <50ms |
| E4 | Laya 322M / Qwen3-0.6B 中文自测 | 空响应 <1%，准确率不低于 E3 的 90% |
| E5 | 影子模式 2 周 | 与线上大模型一致率 ≥95%，无高危分歧 |

## 十一、风险与不确定项

| 风险 | 说明 | 缓解 |
|---|---|---|
| 标注数据不足 | 现有可用样本仅 38 条 **[实测-本项目]** | 先扩采再谈换模型；P0 埋点优先 |
| 小模型 OOS 差 | 文献里 58.1% vs 85.6% **[文献]** | 保留第 ④ 层；OOS 单独设类 + 阈值 |
| Laya/Jev 中文未验证 | 官方口径中文弱于英文；第三方横评结果矛盾 **[文献]** | 必须自测，不采信厂商指标 |
| 阈值过拟合 55 个 POI | 语料太少时阈值会"背答案" | 按说话人切分；留出未见过的说法 |
| Jev 云服务的可用性/合规 | 跨境调用、闭源、可能限流 | 不作为主链路；如要试，只做影子对比 |
| 火山决策评估是 beta | 无 SLA、仅 1 个模型、延迟无口径、非流式 | 只作加速器并保留 Chat API 回退；E6 不达标即不上 |
| 火山决策评估仍需联网 | 与「局域网私有部署」冲突，断网即失效 | 离线兜底永远由本地规则/小模型承担 |
| 过度工程 | 现在上向量库/4B 模型收益为负 | 按 P0→P3 触发式推进 |
