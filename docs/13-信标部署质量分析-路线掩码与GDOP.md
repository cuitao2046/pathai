# PathAI 信标部署质量分析：路线掩码与 GDOP 精度

> **本文档定位**：`fix-beacon-route-mask` 分支（2026-08-14）的分析结果与工程建议汇总，回答两个核心问题：
> 1. **补点信标要不要限制在测试路线附近？** —— 路线掩码（route-mask）方案的设计、实现与实验对比，结论：**6m 掩码即最优**。
> 2. **信标高/底比最小多少才能达到导航精度？** —— 三点定位 GDOP × 高/底比 的定量分析，结论：**推荐最小高/底 = 0.20（保守 0.25），< 0.05 为禁用区**。
>
> **关联文档**：[`docs/07-信标部署方案.md`](07-信标部署方案.md)（通用方法论）、[`docs/08-信标部署与指纹采集实施方案.md`](08-信标部署与指纹采集实施方案.md)（本项目落地，含路线三点定位 60→74 方案）。
> **涉及脚本**：`src/tools/refine_beacon_placement.py`（本次新增 `--route-mask` / `--route-spaces`）、`debug/check_beacon_7rules.py`（7 规则合规检查）。

## 一、背景：7 规则检查发现 [7] 违规（动机）

三点定位方案对测试路线做补点优化时，`refine_beacon_placement.py` 的补点候选遍历**全部走廊多边形**，导致 21 个 `BK-Q-*` 质量补点被部署在**与测试线路无关的空间**：

| 楼层 | 违规补点 | 距路线距离 |
|------|---------|-----------|
| F1 | 8 个（BK-Q-F1-001/002/003/007/008/012/013/019） | 9 ~ 34 m |
| F2 | 13 个（BK-Q-F2-001 ~ 013 全部） | 62 ~ 91 m |

**决定性证据**：剔除这 21 个路线外补点后，测试路线 ≥3 覆盖 **0 变化**（F1 98.61% → 98.61%、F2 100% → 100%）——纯冗余，且违反第 7 条合规要求「针对测试线路，不相关空间不部署信标」。

**根因**：`_unified_candidates` 的 R1/R3/R4 补点遍历 `model.corridors` 全部走廊多边形，质量指标（corridors_both / nn_cv / tri_degen）是**全局优化**，与「仅覆盖路线」的目标冲突。

## 二、方案 A：路线掩码（`--route-mask`，已实现）

### 2.1 设计

在 `refine_beacon_placement.py` 中增加路线掩码约束，**所有补点候选必须位于测试路线 6m 内**：

| 改动点 | 内容 |
|--------|------|
| 常量 | `ROUTE_MASK_M = 6.0`（与 `check_beacon_7rules.py` 的 `ROUTE_TOL` 同口径） |
| 几何索引 | `FloorModel` 增 `route_mask_m` 参数 + `route_tree`（由路线指纹点构建）+ `in_route_mask(x, y)` |
| 统一过滤 | `_unified_candidates.push()` 统一入口：R1/R3/R4/柱面四类补点候选距最近路线指纹点 > 6m 一律丢弃 |
| 移动约束 | `relax_pass` 移动候选也加掩码约束（优化性移动不得推出路线空间） |
| CLI | 新增 `--route-mask M`（默认 0 = 不启用） |

### 2.2 效果（重跑：60 基础信标 → 74 refined）

| 指标 | 修复前（95） | 修复后（74） |
|------|-------------|-------------|
| 信标总数 | 95（F1 75 + F2 20） | **74（F1 67 + F2 7）** |
| 补点数 | 35 | 14（全部在掩码内） |
| [7] 路线外违规 | 21 | **0 ✅（目标达成）** |
| F1 ≥3 覆盖 | 98.61%（707/717） | 98.61%（不变） |
| F2 ≥3 覆盖 | 100%（36/36） | 100%（不变） |
| [4] 三点面积 < 2m² | 21 | 16（既有残留，与掩码无关） |

> 其余既有残留（[3] 贴墙角 17 处含柱缝 1、[5] F1 < 2m 过密 9 处）为历史问题，与掩码无关，需人工评估。

## 三、实验对比：为什么 6m 圆缓冲是最优

### 3.1 实验一：空间掩码（`--route-spaces`）反而更差

用户提出替代方案——掩码改为「路线经过的公共空间（走廊/大厅/门厅/电梯厅/楼梯厅）墙面与开放柱」。实现 `--route-spaces` 后同输入（60 信标）对比：

| 掩码模式 | 信标数 | 补点 | tri_degen | [4] 面积小 |
|---------|--------|------|-----------|-----------|
| 纯 6m 圆缓冲（当前方案） | 74 | 14 | **4.97%** | 16 |
| 纯空间掩码 | 68 | 8 | 10.99%（更差） | 28 |
| 空间 + 6m 并集 | 74 | 14 | 4.97% | 16（与纯 6m 完全一致） |

**根因**：空间多边形是**窄条走廊**，反而丢失了 6m 缓冲内的衔接区墙面（F1 丢 1078 m² > 多出 710 m²）；大厅深处多出区域对路线覆盖无增益。**6m 圆缓冲已覆盖全部有效候选墙面。**

**结论：空间掩码不会更好，保留为可选（并集模式与 6m 等价）。**

### 3.2 实验二：6m vs 9m 无增量

| 指标 | 6.0m | 9.0m |
|------|------|------|
| 信标总数 | 74（F1 67 + F2 7） | 74（F1 67 + F2 7） |
| 补点 | 14 | 14 |
| tri_degen | 4.97% | 4.97% |
| [4] 面积小 | 16 | 16 |
| [7] 违规 | 0 | 0 |

**逐坐标比对：两方案坐标集合完全一致**——距路线 6~9m 区间信标 **0 个**。补点收益全部来自 6m 内（退化三角修复候选都在路线附近），扩大缓冲无任何增量。

**结论：主方案维持 `--route-mask 6.0`。**（注：两方案均有 1 处跨层重复坐标 BK-01-001 / BK-02-001 @ (-28.955, -74.887)，电梯上下对应位，属既有基础信标正常现象。）

## 四、GDOP × 高/底比 定位精度分析（核心结论）

### 4.1 机制

三点定位误差 ≈ **GDOP × σ_range**，其中：
- **GDOP**（几何精度因子）= 三个信标与目标构成的几何形状对误差的放大系数，理论下界 **1.155**（等边三角 + 目标在内部）；
- **σ_range** = BLE 测距误差（典型 1.0 ~ 1.5 m，取决于路径损耗模型校准与多径环境）。

**达标判据：GDOP × σ_range ≤ 目标精度**（如 3m 精度 @ σ=1.5m，或 2m 精度 @ σ=1.0m）。

### 4.2 高/底比与 GDOP 的**非单调**关系（关键认知）

| 目标位置 | 高/底影响 |
|---------|----------|
| 三角形**内部 / 中垂线对称位** | GDOP ≈ 1.16 ~ 1.70，**与高/底无关**（理论模拟证实） |
| 三角形**延长线方向**（底 8m、目标在延长线 2m 处） | **高/底决定性**：0.05 → GDOP 18.4；0.20 → 4.75；0.50 → 2.21；0.866 → 1.62 |

**高/底的作用不是直接压低 GDOP，而是控制"目标落三角形外"的概率与恶化速度**——高/底越小的等腰三角形越"扁"，目标稍微偏离中垂线就滑出三角形进入 GDOP 陡增区。

### 4.3 实测数据（74 信标方案，695 个 ≥3 覆盖点）

| 分组 | GDOP 中位数 | 最大 GDOP |
|------|------------|-----------|
| 全体 | ≈ 1.28（持平理论下界附近） | — |
| 高/底 < 0.05 | — | **11.85** |
| 高/底 ≥ 0.50 | — | **1.89** |

### 4.4 工程判据（达标率 = GDOP×σ ≤ 精度）

| 判据 | 3m 精度 @ σ=1.5m（≡ 2m 精度 @ σ=1.0m） |
|------|----------------------------------------|
| 全体 | 90.2% |
| 高/底 ≥ 0.20 | **94.7%** |
| 高/底 ≥ 0.25 | 95.9% |
| 高/底 ≥ 0.40 | 100% |

**推荐（写入 08 文档 §2.3）：**
- **最小高/底比 = 0.20**（保守取 0.25）；
- **高/底 < 0.05 为禁用区**——该区间最大 GDOP 达 11.85，误差放大近 12 倍，必须避免把信标布成近共线扁三角；
- 若目标精度为 **2m @ σ=1.5m：无解**（高/底 ≥ 0.50 也仅 80.4% 达标），须降 σ_range ≤ 1.06m 或加密信标。

### 4.5 退化点判据缺陷与建议

现有 `EPS_AREA = 0.6` 退化点判据（33 个退化点）仅命中 GDOP>3 的 22 个点中的 **2 个**——面积判据抓得住"三角形面积塌陷"，抓不住"**目标在三角形外**"造成的 GDOP 恶化。

**建议（后续独立分支实施）**：退化判据升级为 **GDOP > 3** 或「目标在三角形内」检查，替换面积判据。
