# 32 本地后端守护化启动说明

> 适用：Windows 本机开发/联调（监听 `0.0.0.0:8000`，UDP 发现 `39001`）。
> 目标：后端常驻后台、脱离启动终端、可自启/自停/崩溃自恢复；**始终调用 `backend/.local/start-local.ps1`**，不绕过其中的环境变量注入、alembic 迁移与 uvicorn 启动。

## 1. 为什么不用“前台窗口别关”

本项目的后端依赖 `start-local.ps1` 注入 `PATHAI_ENV` / `PATHAI_WECHAT_FAKE` / `PATHAI_OPENID_SALT` / `PATHAI_DATABASE_URL`、讯飞与 LLM 密钥，再执行 `alembic upgrade head` 后启动 uvicorn。绕过该脚本会复现“缺密钥、登录 500、地图加载失败”。

实测结论（同一台机器、同一代理会话）：

| 方案 | 结果 | 原因 |
| --- | --- | --- |
| `Start-Process` / `powershell -File ...` 在工具会话内启动 | 会话结束后进程被回收 | 子进程挂在发起会话的进程/Job 下，会话结束即整棵树被终止 |
| WMI `Win32_Process.Create` | 当轮可用，下一轮消失 | 仍受代理会话的作业对象/生命周期约束 |
| **计划任务（Task Scheduler）** | **存活，父进程为 `svchost.exe`** | 任务由系统服务托管，不挂在任何终端/代理 Job 下 |
| Windows 服务（`nssm` / `sc`） | 未采用 | 注册服务需要管理员权限，本机当前不具备；且要额外引入第三方工具 |
| `DETACHED_PROCESS` + `CREATE_BREAKAWAY_FROM_JOB` | 未采用 | 能否脱离取决于当前 Job 是否允许 breakaway，实测不可靠，仍会被回收 |

选定方案：**计划任务 `PathAI-Backend` → `daemon-runner.ps1` → `start-local.ps1` → `alembic` + `uvicorn`**。计划任务由 `svchost.exe` 托管，因此脱离发起终端；注册计划任务使用当前用户身份，**无需提权**。

## 2. 脚本一览（`backend/.local/`）

| 脚本 | 作用 |
| --- | --- |
| `start-local.ps1` | **唯一启动入口**：注入全部环境变量 → `alembic upgrade head` → `uvicorn --host 0.0.0.0 --port 8000`；失败返回非 0 |
| `daemon-runner.ps1` | 计划任务的动作：创建日志/PID 目录、单实例预检、**循环调用 `start-local.ps1`**，退出后 15 秒重试（崩溃自恢复） |
| `daemon-start.ps1` | 幂等启动：已在跑则提示并展示状态；否则注册/校正计划任务并等待 `/healthz` 通过；端口被非本项目进程占用时明确报错 |
| `daemon-stop.ps1` | 优雅停止：`Stop-ScheduledTask` → 等端口释放 → 本项目残留按 PID 强制终止；非本项目进程只报警不误杀 |
| `daemon-status.ps1` | 状态：任务状态/上次结果、runner PID、uvicorn PID 与**父子链**、8000/39001 owner、`/healthz`、地图版本、`/admin/` |
| `daemon-logs.ps1` | 查看最新日志末尾 N 行（`-Follow` 持续跟踪） |

日志：`backend/.local/logs/backend-YYYYMMDD.log`（**追加写**，不覆盖）；PID 文件：`backend/.local/run/backend.pid.json`。

## 3. 常用命令

```powershell
# 启动（幂等）
powershell -ExecutionPolicy Bypass -File backend\.local\daemon-start.ps1

# 状态（含父子链与接口结果）
powershell -ExecutionPolicy Bypass -File backend\.local\daemon-status.ps1

# 停止（幂等）
powershell -ExecutionPolicy Bypass -File backend\.local\daemon-stop.ps1

# 日志
powershell -ExecutionPolicy Bypass -File backend\.local\daemon-logs.ps1 -Lines 80
powershell -ExecutionPolicy Bypass -File backend\.local\daemon-logs.ps1 -Follow
```

预期父子链（`daemon-status.ps1` 会逐层打印）：

```text
python(uvicorn) ← python(WindowsApps 启动器) ← powershell(start-local.ps1)
              ← powershell(daemon-runner.ps1) ← svchost.exe(Task Scheduler)
```

只要最上层是 `svchost.exe`，就说明它不挂在启动终端/代理会话下。

## 4. 计划任务策略

- 触发器：`AtLogOn`（当前用户登录后自启）。
- 设置：`MultipleInstances=IgnoreNew`（单实例）、`ExecutionTimeLimit=0`（不限时）、
  `StartWhenAvailable`、允许电池运行、`RestartOnFailure` 999 次 / 1 分钟（兜底）。
- **崩溃恢复的实际实现**：`daemon-runner.ps1` 内循环，`start-local.ps1` 退出后 15 秒重新调用。
  实测 Task Scheduler 的 `RestartOnFailure` 在“外部杀死子进程”场景返回 `-1` 且不触发重启，
  因此不能只依赖它；runner 内循环可以稳定复现“杀掉 uvicorn 后 45 秒内 `/healthz` 恢复 200”。

## 5. 排错

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| 启动报“TCP 8000 被非本项目进程占用” | 输出已给出 PID/名称/命令行 | 确认用途后手动结束，或改用其他端口（脚本固定 8000/39001） |
| 启动后 `/healthz` 不通 | `daemon-logs.ps1 -Lines 40` | 先看 alembic/uvicorn 报错；`python` 是否在 PATH；密钥是否完整 |
| 脚本执行后环境变量不生效 | 用编辑器检查文件是否 **UTF-8 with BOM** | PowerShell 5.1 对无 BOM 的 `.ps1` 按 ANSI 解析，中文注释会吞掉紧随的赋值 |
| 任务状态 `Ready` 且端口无人监听 | `Get-ScheduledTaskInfo` 看上次结果 | 重新执行 `daemon-start.ps1`（会重新注册并拉起） |
| 关闭终端后服务消失 | `daemon-status.ps1` 看父子链 | 若父进程不是 `svchost.exe`，说明是通过会话脚本直接启动的，请改用 `daemon-start.ps1` |

## 6. 已知边界

- 计划任务在当前用户**登录后**生效；开机未登录不会启动（如需开机即启，需要改服务或管理员权限）。
- 任务动作固定为 `daemon-runner.ps1`，runner 固定调用 `start-local.ps1`；不要修改动作去直接调 `python`/`uvicorn`。
- `start-local.ps1` 含密钥，仍由 `.gitignore` 忽略；`daemon-*.ps1` 已放行入库。
