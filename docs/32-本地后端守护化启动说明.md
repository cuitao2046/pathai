# 32 本地后端守护化启动说明

> 适用：Windows 本机开发/联调（监听 `0.0.0.0:8000`，UDP 发现 `39001`）。
> 目标：后端常驻后台、脱离启动终端、可自启/自停/崩溃自恢复；**始终调用 `backend/.local/start-local.ps1`**，不绕过其中的环境变量注入、alembic 迁移与 uvicorn 启动。

## 1. 为什么不用“前台窗口别关”

本项目的后端依赖 `start-local.ps1` 注入 `PATHAI_ENV` / `PATHAI_WECHAT_FAKE` / `PATHAI_OPENID_SALT` / `PATHAI_DATABASE_URL`、讯飞与 LLM 密钥，再执行 `alembic upgrade head` 后启动 uvicorn。绕过该脚本会复现“缺密钥、登录 500、地图加载失败”。

实测结论（同一台机器、同一代理会话）：

| 方案 | 结果 | 原因 |
| --- | --- | --- |
| `Start-Process` / `powershell -File ...` 在工具会话内启动 | 会话结束后进程被回收 | 子进程挂在发起会话的进程/Job 下，会话结束即整棵树被终止 |
| WMI `Win32_Process.Create` | 当轮可用，下一轮消失 | 仍受代理会话的作业对象/生命周期约束 |
| **计划任务（Task Scheduler，交互式 `Interactive`）** | 进程能起，但**会话结束即被终止** | 任务实例挂在交互式控制台；控制台关闭时收到控制事件，任务结果 `0xC000013A`（`STATUS_CONTROL_C_EXIT`） |
| **计划任务（Task Scheduler，`S4U`）** | **稳定存活，uvicorn `SessionId=0`，父进程为 `svchost.exe`** | 任务在会话 0 由系统服务托管，不挂在任何终端/控制台 |
| Windows 服务（`nssm` / `sc`） | 未采用 | 注册服务需要管理员权限，本机当前不具备；且要额外引入第三方工具 |

选定方案：**计划任务 `PathAI-Backend`（S4U，会话 0）→ `daemon-runner.ps1` → `start-local.ps1` → `alembic` + `uvicorn`**。计划任务由 `svchost.exe` 托管，注册使用当前用户身份，**无需提权**。

## 2. 脚本一览（`backend/.local/`）

| 脚本 | 作用 |
| --- | --- |
| `start-local.ps1` | **唯一启动入口**：注入全部环境变量 → `alembic upgrade head` → `uvicorn --host 0.0.0.0 --port 8000`；失败返回非 0 |
| `daemon-runner.ps1` | 计划任务的动作：创建日志/PID 目录、单实例预检（回环探测）、**循环调用 `start-local.ps1`**，退出后 15 秒重试（崩溃自恢复） |
| `daemon-start.ps1` | 幂等启动：已在跑则提示并展示状态；否则注册/校正 **S4U** 计划任务（动作注入真实 Python 目录）并等待 `/healthz` 通过；端口被非本项目进程占用时给出 PID/命令行并退出 1 |
| `daemon-stop.ps1` | 停止：`Stop-ScheduledTask` → **`Disable-ScheduledTask`（防看门狗 1 分钟内拉起）** → 等端口释放 → 本项目残留按 PID/命令行清理；非本项目进程只报警不误杀 |
| `daemon-status.ps1` | 状态：任务状态/上次结果、runner PID、uvicorn PID 与**父子链/SessionId**、8000/39001 owner、`/healthz`、地图版本、`/admin/` |
| `daemon-logs.ps1` | 查看最新日志末尾 N 行（`-Follow` 持续跟踪） |

日志：`backend/.local/logs/backend-YYYYMMDD.log`（**追加写**，不覆盖）；PID 文件：`backend/.local/run/backend.pid.json`。

## 3. 常用命令

```powershell
# 启动（幂等）
powershell -ExecutionPolicy Bypass -File backend\.local\daemon-start.ps1

# 状态（含父子链、SessionId 与接口结果）
powershell -ExecutionPolicy Bypass -File backend\.local\daemon-status.ps1

# 停止（幂等；会同时禁用任务，避免看门狗把服务重新拉起）
powershell -ExecutionPolicy Bypass -File backend\.local\daemon-stop.ps1

# 日志
powershell -ExecutionPolicy Bypass -File backend\.local\daemon-logs.ps1 -Lines 80
powershell -ExecutionPolicy Bypass -File backend\.local\daemon-logs.ps1 -Follow
```

预期父子链（`daemon-status.ps1` 会逐层打印）：

```text
python(uvicorn) ← powershell(start-local.ps1)
              ← powershell(daemon-runner.ps1) ← cmd.exe ← svchost.exe(Task Scheduler)
```

同时应看到 uvicorn 的 `SessionId=0`。只要最上层是 `svchost.exe`，就说明它不挂在启动终端/代理会话下。

## 4. 计划任务策略（S4U，会话 0）

- 主体：`New-ScheduledTaskPrincipal -UserId "<域或计算机名>\<用户名>" -LogonType S4U -RunLevel Limited`。
  S4U 允许任务在无密码、无交互登录的情况下以当前用户身份运行于**会话 0**，注册不需要管理员权限。
- 动作：`cmd.exe /c set "PATH=<真实 Python 目录>;%PATH%" && powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<daemon-runner.ps1>"`。
  **必须注入真实 Python 目录**：会话 0 下无法通过 WindowsApps 的 `python.exe` 别名启动（别名只对交互式用户可用）。
  动作里不直接调用 python/uvicorn，固定链路仍是 runner → `start-local.ps1`。
- 触发器：
  - `AtLogOn`：当前用户登录后自启。
  - `Once` + `RepetitionInterval=1 分钟`（**不设 `RepetitionDuration`**，表示无限重复）：**看门狗**。
- 设置：`MultipleInstances=IgnoreNew`（单实例）、`ExecutionTimeLimit=0`（不限时）、`StartWhenAvailable`、
  允许电池运行、`RestartOnFailure` 999 次 / 1 分钟（仅兜底）。
- **两层恢复，互不冲突**：
  1. runner 内循环：`start-local.ps1`（uvicorn）退出后 15 秒重新调用。实测杀掉 uvicorn 到 `/healthz` 重新 200 约 **23 秒**（15 秒等待 + 约 8 秒 alembic/uvicorn 启动）。
  2. 看门狗：每分钟尝试启动任务；任务仍 `Running` 时被 `IgnoreNew` 正常拒绝，runner 被外部强杀后 1 分钟内会被重新拉起。
     注意：任务运行中 `上次结果` 可能显示 `2147946720`（`0x800710E0`，启动请求被拒绝），这是看门狗被 `IgnoreNew` 拒绝的**正常现象**，以 `状态=Running` 与端口/`/healthz` 为准。
- 停止语义：`daemon-stop.ps1` 会 `Disable-ScheduledTask`，否则 1 分钟内看门狗会把服务重新拉起；再次执行 `daemon-start.ps1` 会 `Enable-ScheduledTask` 并重新注册。

## 5. 端口归属判断（会话 0 下的特殊现象）

会话 0 中 `Get-NetTCPConnection` / `Get-NetUDPEndpoint` 有两个实测坑：

1. `State` 字段可能为空（`-State Listen` 过滤不到任何行）。
2. 会出现 `127.0.0.1:8000`、`OwningProcess=0` 的**幻影行**（`netstat -ano` 里没有对应 `LISTENING`），进程退出后短时间内也可能残留。

因此脚本的判定顺序为：

- **是否在监听**：先做 `127.0.0.1:<port>` 的 TCP 连接探测（400ms 超时，能连上才算监听）；再用 CIM 行兜底，且**只认 `State=Listen` 或 `OwningProcess != 0` 的行**，忽略 `owner=0` 的幻影行。
- **PID 归属**：TCP owner（非 0）→ UDP `39001` owner（非 0）→ 进程命令行（`python.exe` 且含 `uvicorn` 与 `pathai_backend`）。
- **误杀保护**：只有能确认是本项目（命令行含 `pathai_backend`，或 `/healthz` 200 且命中 `pathai_backend` 进程）才强制终止；否则只打印 PID/名称/命令行并退出 1。

排查时可交叉验证：

```powershell
netstat -ano | findstr :8000
Get-NetTCPConnection -LocalPort 8000 | Select LocalAddress,LocalPort,State,OwningProcess
Get-CimInstance Win32_Process -Filter "ProcessId=<pid>" | Select ProcessId,SessionId,CommandLine
```

## 6. 排错

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| 任务 `Ready`、`上次结果=3221225786`（`0xC000013A`），端口无人监听 | 任务主体是否为 `Interactive` | 重新执行 `daemon-start.ps1`，脚本会以 **S4U** 重新注册；`0xC000013A` 表示任务随交互式控制台关闭被终止 |
| 任务 `Running` 但 `上次结果=2147946720`（`0x800710E0`） | `daemon-status.ps1` 的端口/`/healthz` | 正常：看门狗每分钟尝试启动被 `IgnoreNew` 拒绝；只要 `/healthz` 200 即无需处理 |
| 启动报“TCP 8000 / UDP 39001 被非本项目进程占用” | 输出已给出 PID/名称/命令行 | 确认用途后手动结束，或改用其他端口（脚本固定 8000/39001） |
| 启动后 `/healthz` 不通 | `daemon-logs.ps1 -Lines 40` | 先看 alembic/uvicorn 报错；会话 0 下 python 必须是**真实路径**（见 §4 动作）；密钥是否完整 |
| 日志里 `python` 找不到/立刻退出 | 任务动作的 `PATH` 前缀 | WindowsApps 别名在会话 0 不可用，必须注入 `C:\Users\<用户>\AppData\Local\Python\pythoncore-3.14-64` 等真实目录 |
| 停止后端口重新被占 | 任务是否被重新启用 | `daemon-stop.ps1` 会禁用任务；若手动 `Enable-ScheduledTask`，看门狗 1 分钟内会拉起 |
| 脚本执行后环境变量不生效 | 文件是否 **UTF-8 with BOM** | PowerShell 5.1 对无 BOM 的 `.ps1` 按 ANSI 解析，中文注释会吞掉紧随的赋值 |
| `daemon-status.ps1` 显示 `PID来源=UDP/进程命令行兜底` | 会话 0 下 TCP owner 可能为 0/幻影行 | 属正常兜底；结合 `SessionId=0` 与父子链判断归属 |
| 关闭终端后服务消失 | `daemon-status.ps1` 看父子链 | 父进程不是 `svchost.exe` 说明是会话内直接启动，请改用 `daemon-start.ps1` |

## 7. 已知边界

- **登录自启**：`AtLogOn` 在当前用户登录后生效；开机未登录不会启动（如需开机即启，需要改服务或管理员权限）。
- **会话 0 的外网调用**：后端在会话 0 运行，讯飞 TTS/LLM 等真实外网调用**未在本轮实测**；会话 0 可能受系统代理、用户级网络策略或证书存储差异影响。当前仅验证本地 HTTP/UDP 接口；接入真实外网前应在该任务环境下单独验证。
- 任务动作固定为 `daemon-runner.ps1`，runner 固定调用 `start-local.ps1`；不要修改动作去直接调 `python`/`uvicorn`。
- 本机 WLAN IPv4 变化后，小程序编译期 `API_BASE_URL` 需同步；UDP 39001 发现可作为兜底（本机 `192.168.1.28` 与客户端常量一致时直接连通）。
- `start-local.ps1` 含密钥，仍由 `.gitignore` 忽略；`daemon-*.ps1` 已放行入库。
