## ADR-01 门不合并（铁律）

- 状态：**已生效（用户铁律）**，2026-08-08 起
- 背景：同一物理开口常被识别为多条门记录（swing + fire + opening），早期实现提供 `dedupe_doorways`、`_merge_nearby_doors` 等合并逻辑。
- 决策：**每扇门独立成 TD 节点，禁止任何形式门合并**。用户明确同一物理开口只允许一扇门，且门洞与普通门不去重合并。
- 影响：
  - `dedupe_doorways`（parse_cad_pdf.py）：不再被任何调用链使用，保留仅供 git 历史参考。
  - `_merge_nearby_doors`（topology.py 与 pipeline.py 各一份）：不再被 `build_floor_topology` / `build_skeleton_topology` 调用，保留仅为历史参考。
  - 校验（validate_geojson.py）按「每扇门独立成 TD」设计，注释已同步。
- 恢复条件：必须征得用户明确确认后方可重新启用；恢复时需同步两处 `_merge_nearby_doors` 与 `dedupe_doorways`。

## ADR-02 手动骨架优先于自动中轴

- 状态：**已生效**，2026-08-08 起
- 背景：自动中轴骨架在复杂楼层会出现分支/缝隙问题，现场可人工标注 SVG 骨架。
- 决策：`skeleton_manual_parsed.json` 存在时跳过中轴提取（medial-axis），直接使用其 TI / TI-TI / 骨架线（含红色无填充矩形以闭合折线存入）；支持自动检测与 `--no-manual-skeleton` 强制自动。
- 影响：手动骨架 JSON 是拓扑生成的最高优先级输入；`import_manual_skeleton.py` / `apply_manual_skeleton.py` 构成标注闭环。
- 关联文档：`docs/项目迭代日志.md`（2026-08-08/08-09 条目）。
