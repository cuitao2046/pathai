# 实验数据分析与复核说明

本说明对应分析工具 `tools/analyze_field_experiment.py` 及其产出的审计包，目的是让第三人不依赖分析者的口头说明，也能核对「输入是否完整、口径是否一致、数字是否算对」。

## 1. 适用范围

- 输入：`GET /api/v1/export/experiment?include_trial=true` 导出的实验 ZIP。
- 可选输入：`tools/replay_all_field_runs.py` 生成的批量重放 JSON（A/B/C 准确性）。
- 输出：指标表、逐条中间数据、运行清单与 HTML 报告。
- 本说明以运行 `run_20261121` 为例；后续运行按同一目录结构归档。

## 2. 产物清单

```text
reports/field-experiment/run_20261121/
├── input/
│   └── export_20261121.zip          # 原始输入，只读，不复改
├── details/                         # 关键中间数据（逐条）
│   ├── segments.csv                 # 每个采集段的清单与真值绑定情况
│   ├── runs.csv                     # 每次采集运行的汇总
│   ├── exclusions.csv               # 被导出排除的段及原因
│   ├── accuracy_checkpoints.csv     # 重放检查点 × 方法（A/B/C）的逐条误差
│   ├── nav_estimates.csv            # 导航逐拍估计（位置、RTT、间隔、跳变）
│   └── timing_events.csv            # 转向播报 / 震动 / 到达的逐事件时差
├── metrics_20261121.json            # 指标完整结构（含分位数、分组）
├── metrics_20261121.csv             # 指标扁平表（便于透视与抽查）
├── manifest_20261121.json           # 运行清单：输入/输出哈希、参数、工具版本
└── report_20261121.html             # 人工阅读报告
```

各文件均由 `analyze_field_experiment.py` 一次运行生成（报告由指标自动汇总），不含手工修改的数字。

## 3. 数据链路

1. **原始段**：ZIP 内五类 `*_segments.jsonl` / `navigation_sessions.jsonl`，按 `manifest.counts` 校验行数。
2. **真值绑定**：ST / FP / CAL 按 `pointId` 绑定导出包 `manifest.plans` 中的勘测坐标；DY / NV 按检查点 `pointId` 绑定。绑不到时在 `segments.csv` 的 `truthNote` 写明原因。
3. **准确性中间数据**：批量重放返回的每个检查点 × 方法写入 `accuracy_checkpoints.csv`；同一批数据聚合为 `metrics` 的 `accuracy` 区。
4. **可用性中间数据**：NV 段的逐拍 `estimate` 事件写入 `nav_estimates.csv`；聚合为有效定位率、跳变、更新间隔、RTT。
5. **时效中间数据**：转向参考、播报、震动、到达事件写入 `timing_events.csv`；聚合为时差分位数。

## 4. 复现方式

```powershell
# 1) 批量重放（可选；T6/T7 需要冻结配置）
python tools/replay_all_field_runs.py reports/field-experiment/run_20261121/input/export_20261121.zip `
  --base-url http://<后端地址> --token <账号令牌> `
  --config-id <冻结配置> --out reports/field-experiment/run_20261121/replay_20261121.json

# 2) 生成指标、中间数据与运行清单
python -m tools.analyze_field_experiment reports/field-experiment/run_20261121/input/export_20261121.zip `
  --replay reports/field-experiment/run_20261121/replay_20261121.json `
  --json reports/field-experiment/run_20261121/metrics_20261121.json `
  --csv reports/field-experiment/run_20261121/metrics_20261121.csv `
  --details-dir reports/field-experiment/run_20261121/details `
  --manifest reports/field-experiment/run_20261121/manifest_20261121.json
```

`--details-dir`、`--manifest`、`--json` 均为可选参数；只跑指标时可省略。重跑后 `manifest` 中的哈希会更新，旧包应另存目录，不要覆盖。

## 5. 字段与口径

### 5.1 metrics CSV

列为 `dimension, task, method, view, metric, value`：

- `task` 为 `*` 表示跨任务汇总；`method` 为 `*` 表示跨方案汇总。
- `view`：`all` 为全体样本；`hitOnly` 仅 C 指纹命中；`replay` 为 C 回退统计。
- 准确性仅统计 `errorM` 非空的样本（跨层时后端不返回误差）；楼层正确率的分母是所有参与重放的检查点，无位置按不正确计。
- `validLocationRate = positionedEstimates / estimates`。
- `jumpCount`：同楼层相邻两拍均定位且距离超过 3.0 m 记一次。
- `updateIntervalMs`：导航段相邻 `estimate` 间隔，剔除大于 60 s 的空档。
- `requestRttMs`：`estimate` 事件中的 `requestMs`（客户端请求耗时）。
- `turnSpeechDeltaMs / turnHapticDeltaMs`：信号时刻 − 参考时刻，负值为提前、正值为滞后；仅统计两端都存在的事件。
- `arrivalDetectionDeltaMs`：系统判到达 − 人工标记；`distanceM` 仅作偏差参考。
- `fallbackRate = fallbacksToB / (fingerprintHits + fallbacksToB)`，分母为 0 时为空。

### 5.2 details 明细

| 文件 | 一行代表 | 关键列 |
|---|---|---|
| `segments.csv` | 一个采集段 | `planned`（是否有正式计划）、`hasTruth`、`truthX/Y/Floor`、`truthNote`、`durationS`、`rssiFrames` |
| `runs.csv` | 一次运行 | `segments`、`complete/suspect/aborted`、`plannedSegments/trialSegments`、`points` |
| `exclusions.csv` | 一个被排除段 | `segmentId`、`reason` |
| `accuracy_checkpoints.csv` | 检查点 × 方法 | `truthX/Y/Floor`、`errorM`、`floorCorrect`、`source`、`fallbackReason`、`rmseDb/overlap/marginDb/confidence`、`diagnostics` |
| `nav_estimates.csv` | 一次定位请求 | `positioned`、`x/y/floorId`、`requestMs`、`visibleBeaconCount`、`intervalMs`、`jump` |
| `timing_events.csv` | 一次转向/到达事件 | `kind`（speech/haptic/arrival）、`status`、`deltaMs`、`relativeM` |

说明：

- `accuracy_checkpoints.csv` 的 `truthX/Y/Floor` 是按 `pointId` 从导出包计划中关联的，属复核便利字段；关联不到时为空。
- `errorM` 为空表示跨层或该方案没有输出位置，不代表误差为 0。
- `diagnostics` 是 C 未命中时的服务端诊断 JSON（最佳候选、Top3、置信度、margin、原因），可直接定位回退原因。
- `nav_estimates.csv` 的 `intervalMs` 与指标同口径（剔除 > 60 s）；`jump` 为 1 的行数应与 `jumpCount` 一致。

### 5.3 manifest JSON

- `inputs.archive` / `inputs.replay`：文件大小与 SHA-256，用于确认分析的是同一份数据。
- `tool`：脚本 SHA-256、指标版本、Git 提交、工作区是否脏（`gitDirty`）、Python 版本。工作区脏时以 `scriptSha256` 为准。
- `parameters`：本次使用的跳变阈值，以及导出包自带的挂起半径、期望更新间隔、C 命中阈值。
- `outputs`：指标、明细、CSV 的路径与哈希。
- `detailRows`：各明细表行数，便于快速核对规模。

## 6. 人工复核清单

按顺序执行，全部通过即可认为本次分析可复现：

1. **校验输入**：`manifest.inputs.archive.sha256` 与 `Get-FileHash input\export_20261121.zip -Algorithm SHA256` 一致。
2. **校验输出**：`manifest.outputs` 中每个文件的哈希与实际文件一致。
3. **核对规模**：`details/segments.csv` 行数 = `manifest.counts` 各任务之和；各任务行数逐一对应。
4. **核对计划属性**：`segments.csv` 中 `planId` 为空的行数应等于报告里的「试采段」。
5. **核对真值缺口**：`hasTruth=0` 且 `pointId` 非空的行，`truthNote` 应能解释原因（无计划 / 计划缺点位）。
6. **抽查准确性**：取 `accuracy_checkpoints.csv` 一行，手算 `hypot(estimateX − truthX, estimateY − truthY)`，应与 `errorM` 一致（保留 3 位）。
7. **核对可用性分母**：`nav_estimates.csv` 行数 = `metrics` 的 `usability.estimates`；`positioned=1` 的占比 = `validLocationRate`。
8. **核对跳变**：`nav_estimates.csv` 中 `jump=1` 的行数 = `usability.jumpCount`。
9. **核对时效**：`timing_events.csv` 中 `deltaMs` 的样本数、P90 应与 `timeliness` 各分位数一致；`arrival` 行数 = `arrivalDetectionDeltaMs.n`。
10. **核对 C 回退**：`accuracy_checkpoints.csv` 中 `method=C` 的 `source` 计数 = `fingerprintHits / fallbacksToB`；`fallbackRate` 按 5.1 公式复算。
11. **核对报告**：HTML 中每个数字应能在 `metrics_20261121.csv` 找到同源行。

## 7. 本次运行（run_20261121）的已知限制

- 数据来自本地开发库，不是现场正式采集；仅用于验证工具链路。
- 没有冻结配置，因此未生成重放 JSON：`accuracy_checkpoints.csv` 仅有表头，准确性区为空。
- NV 段为 0：`nav_estimates.csv`、`timing_events.csv` 仅有表头，可用性与时效为空。
- ST/DY 段均为试采（无 `planId`），即使重放也没有真值，`segments.csv` 中 `truthNote` 已标注。
- 生成时工作区有未提交改动（`gitDirty=true`），复核请以 `manifest.tool.scriptSha256` 对应脚本内容为准。
