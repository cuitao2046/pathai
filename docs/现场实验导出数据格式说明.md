# 现场实验导出数据格式说明

适用版本为 `manifest.json` 中的 `schemaVersion: "1.0"`。本文覆盖小程序「现场实验」中的两种实验 ZIP 和单独导出的信标巡检台账。

## 导出入口与范围

| 小程序入口 | 文件 | 内容 |
| --- | --- | --- |
| 场记及导出 → 导出正式实验 ZIP | `experiment_export_YYYY-MM-DD.zip` | 已上报且有 `planId` 的正式采集记录 |
| 场记及导出 → 导出含试采的 ZIP | 同上 | 正式记录和已上报的试采记录，试采的 `planId` 为 `null` |
| 信标巡检 → 导出台账 | `beacon_inspections.csv` | 已上报的信标巡检记录 |

两种 ZIP 都包含后端保存的全部已发布清单、清单内的真值和冻结配置。场记会在 `runId` 为空或对应轮次已导出时纳入。按采集日筛选时，将 `startedAtEpoch` 转为北京时间的日期。按真值批次筛选时使用 `batch`。导出前确认「待补传」为 0。

两种 ZIP 在小程序中使用同一天的相同文件名，需要同时留存时请分别另存。`manifest.includeTrial` 可区分两种包。

## 文件清单

| ZIP 内文件 | 每条记录的含义 |
| --- | --- |
| `calibration_segments.jsonl` | T3 `CAL`，每点一段 120 秒原始标定数据，新记录 `part` 为 1。旧记录的 `part` 可为 1 至 3。拟合时服务端按时间切成 40 秒窗口，原始导出仍按采集段保存 |
| `fingerprint_segments.jsonl` | T4 `FP`，一个网格点的一个朝向。正式采集在 25 秒达标时结束，未达标延长至 30 秒 |
| `static_test_segments.jsonl` | T6 `ST`，一个测试点的一个朝向的静态采集 |
| `dynamic_trajectories.jsonl` | T7 `DY`，一次行走的 RSSI 和检查点打点 |
| `nav_sessions.jsonl` | T8 `NV`，一次导航的 RSSI、打点和在线导航事件 |
| `observer_records.csv` | 一条观察场记或跳过记录 |
| `ground_truth.csv` | 一份正式清单中的一个真值点 |
| `manifest.json` | 一份导出摘要，含清单、冻结配置、版本和计数 |

文件采用 UTF-8。JSONL 每行是一个完整 JSON 对象。无数据时 JSONL 为空，CSV 仍保留表头。CSV 用逗号分隔，空字段读为空值，布尔值写作 `True` 或 `False`。以 `=`、`+`、`-`、`@`、制表符或回车开头的 CSV 文本会加前置单引号，数值类型的负坐标和负 RSSI 正常输出。

## JSONL 采集记录

五个 JSONL 使用相同的顶层字段，适用任务之外的可空字段通常为 `null`，空事件列表为 `[]`。

| 字段 | 含义 |
| --- | --- |
| `segmentId` | 采集段唯一编号。按整串使用 |
| `runId` | 一轮采集或路线的编号。一轮可有多段，也是与场记关联的键 |
| `task` | `CAL`、`FP`、`ST`、`DY`、`NV` |
| `planId`、`batch` | 正式清单编号和批次号。新批次采用 `YYYYMMDD-序号`，如 `20261119-001`。试采的清单编号为空，小程序的试采批次通常形如 `trial-2026-11-19` |
| `pointId`、`orientation`、`part` | 点位、朝向、段序号。`FP`、`ST` 的 1 至 4 段依次为 `N`、`E`、`S`、`W`。路线记录按 `checkpoints` 查点位 |
| `startedAtEpoch`、`endedAtEpoch`、`durationS` | 开始、结束时刻和持续秒数。前两个字段是 Unix 毫秒时间戳 |
| `mapVersion`、`paramsVersion` | 地图版本和定位参数版本。按字符串读取 |
| `method`、`configId` | `RAW` 表示原始采集。T8 的 `A`、`B`、`C` 绑定冻结配置编号 `configId` |
| `deviceId`、`operatorUserId` | 小程序记录的设备标识、提交记录的账号标识 |
| `status`、`reason`、`retryOf` | `complete` 完成、`suspect` 可疑、`aborted` 中止。`reason` 为说明，`retryOf` 可指向重采前的 `segmentId` |
| `rssi` | 信标观测数组。每项如 `{"t":1795053600000,"beacon":"BK-01-001","rssi":-71}`，RSSI 单位为 dBm |
| `checkpoints` | 打点事件数组。每项含 `t`、`pointId`、`undo`。T8 的播报点 P 和普通 CP 使用同一数组，顺序与正式清单一致。`undo: true` 撤销上一次对应打点 |
| `navigation` | T8 在线导航事件数组，见下一节 |

`rssi[].t`、`checkpoints[].t` 和 `navigation[].t` 均为 Unix 毫秒时间戳。现场对照时按北京时间（UTC+8）显示。`suspect` 和 `aborted` 会保留在导出文件中，统计正式有效样本时筛选 `planId` 有值且 `status == "complete"`。

### T8 导航事件

每个事件都有 `kind` 和 `t`。`t` 是小程序写入事件的时刻。使用以下字段对齐路线、估计位置和实际播报。

| `kind` | 特有字段与用途 |
| --- | --- |
| `session` | `sessionId`、`route`，记录会话与初始路线 |
| `route` | `route`，记录路线更新。`route.polyline` 为按顺序排列的地图坐标，`route.segments` 为导航指令列表 |
| `estimate` | `position`、`source`、`paramsVersion`、`fallbackReason`、`observedAt`、`quality`、`confidence`。`position` 可为空，`observedAt` 是定位观测时间的 ISO 8601 字符串 |
| `unavailable` | `code`，表示定位请求不可用的错误码 |
| `instruction` | `instruction`、`turn`。使用 `instruction.instructionId`、`action`、`text` 和 `trigger` 追踪指令，`turn` 为可解析时的触发节点坐标 |
| `speech_requested`、`speech_started`、`speech_finished` | `source`、`text`。`speech_started.t` 为实际开始播报的时间。来源形如 `nav:instruction:<instructionId>` 时可关联指令 |
| `end` | `reason`、`byArrival`。当 `byArrival` 为真，`t` 是手机收到系统到达判定的时刻 |
| `arrival_manual` | `t` 是学生在终点参照线点击「确认实际到达」的时刻，每轮最多记录一次 |
| `turn_reference` | `announcementId` 为播报参照点，`pointId` 为转角 CP，`nodeId` 为转角拓扑节点，`position` 为播报点坐标 |
| `announcement_mark` | 旧版播报点打点，含 `announcementId`、`pointId` 和 `t`。分析仍兼容此事件，新版从 `checkpoints` 读取 P 点时间 |
| `turn_haptic` | `instructionId`，`t` 为小程序调用转弯长震的时刻 |

分析报告中的 `turnTiming` 按转角 CP 输出两项毫秒偏差。语音实际开始时刻减去 P 打点时刻，长震触发时刻减去 CP 打点时刻。负值为提前，正值为滞后。缺少参照打点、缺少提示事件和未开启长震分别标记。

分析脚本以系统到达时刻减去人工确认时刻，输出 `arrival.deltaMs`。负数表示提前，正数表示滞后。已有人工确认、结束时仍无系统判定的轮次标记为 `not_detected`。

坐标对象用 `x`、`y`、`floorId` 表示，坐标为地图局部米制坐标。计算平面距离前先核对地图版本和楼层。

## CSV 表字段

### `ground_truth.csv` 真值坐标

| 字段 | 含义 |
| --- | --- |
| `planId`、`task`、`pointId` | 所属清单、任务、点位。以 `planId + pointId` 关联采集点和检查点 |
| `floorId`、`x`、`y` | 楼层编号及该次发布固定的真值坐标，单位为米 |
| `surveyVersion`、`candidateX`、`candidateY` | 真值版本和原始候选坐标。`base` 的两组坐标一致；实测更新用 `v1`、`v2` 等。旧记录这三列可能为空 |
| `measuredOn`、`operatorUserId` | 测量日期（`YYYY-MM-DD`）和清单发布账号 |

同一个点位可能出现在多份清单中。关联时使用采集记录实际引用的清单。参考墙、距离和备注在 `manifest.json` 的 `plans[].points[]` 中。

### `observer_records.csv` 场记

| 字段 | 含义 |
| --- | --- |
| `runId`、`pointId`、`planId` | 关联轮次、点位、清单，均可能为空 |
| `t`、`day` | 观察或记录时刻（Unix 毫秒）和可选日期（`YYYY-MM-DD`）。跳过记录包含日期和点位 |
| `kind`、`isArrival` | `observer` 为观察场记，`skip` 为跳过点位。`isArrival` 表示是否记录了现场到点时刻 |
| `note`、`turnRating` | 文字场记或跳过原因。转向评价可为空，取值 `on_time`（及时）、`early`（提前）、`late`（滞后）、`missed`（漏报） |
| `cleared`、`operatorUserId` | 是否已清场、提交账号 |

### `beacon_inspections.csv` 信标巡检台账

| 字段 | 含义 |
| --- | --- |
| `beaconId`、`mapVersion` | 信标编号和巡检时所用地图版本 |
| `t`、`lastSeen` | 保存时刻和最近收到广播的时刻，均为 Unix 毫秒。`lastSeen` 可为空 |
| `action` | `installed`（贴装）、`checked`（复核）、`removed`（拆除）、`issue`（异常） |
| `location`、`mount` | 安装位置、固定方式 |
| `rssi`、`note`、`operatorUserId` | 最近信号强度（dBm，可为空）、备注、提交账号 |

## `manifest.json` 导出摘要

| 字段 | 含义 |
| --- | --- |
| `schemaVersion`、`exportedOn`、`includeTrial` | 格式版本、后端导出日期、是否包含试采 |
| `counts` | `CAL`、`FP`、`ST`、`DY`、`NV` 各 JSONL 的总行数，含可疑和中止记录 |
| `excluded` | 本包内非 `complete` 的采集段清单，每项含 `segmentId`、`reason`。段原文仍在对应 JSONL 中 |
| `mapAndParamVersions` | 本包内采集段使用过的版本组合，每项为 `[mapVersion, paramsVersion]` |
| `cEstimateCounts` | 已完成 C 轮次的事件计数。`fingerprintHits` 计 `estimate` 的 `source: fingerprint`，`fallbacksToB` 计 `source: trilateration`，`unavailable` 计独立的不可用事件 |
| `plans` | 已发布清单，含 `planId`、`task`、`day`（生效日期）、`batch`、`mapVersion`、`operatorUserId` 和有序的 `points`。每个点另含 `anchorA/B`（参考墙）、`distanceA/B`（实测距离）、`checkA/B`（复测距离）和 `note`。距离单位为米 |
| `frozenConfigurations` | 按 `configId` 查冻结配置，含 `mapVersion`、`frozenAt`（Unix 毫秒）、`operatorUserId`、`arrivalRadiusM` 和 `turnPromptDistanceM`。`A`、`B` 含 `rssiAt1m`、`pathLossN`、`reliableM`、`degradedM`、`paramsVersion`；`C` 含 `libraryVersion`、`fallback`、`minOverlap`、`maxRmse`、`confidenceRmse`、`minConfidence`、`minMargin` |
| `analysisConfig` | 分析口径：`metricVersion`、`suspendRadiusM`（T6/T8 挂起库半径）、`jumpThresholdM`（位置跳变阈值）、`expectedUpdateIntervalMs`（待命/预览/导航三档）与 `matchThresholds`（C 命中阈值） |

## 分析时怎么关联

1. 用 `planId` 找生效日期、批次和地图版本，再用 `planId + pointId` 找发布时的真值。多日采集可以共用一份清单，实际采集日期从采集段时间戳读取。路线检查点使用 `checkpoints[].pointId`。
2. 用 `runId` 关联场记，用 `t` 对齐 RSSI、检查点和导航事件。统计实际播报时使用 `speech_started`。正式动态对比使用 T8 的原始 RSSI 和打点，通过「重放 A/B/C」按路线编号生成配对误差。
3. T8 的 A 用默认参数三点定位，B 用标定参数三点定位。C 优先用指纹，未命中时回退 B，整轮仍计为 C。按项目分析脚本的口径，回退率为 `fallbacksToB / (fingerprintHits + fallbacksToB)`，同一分母下纯指纹命中率只计 `fingerprintHits`。`unavailable` 单列报告，分母为零时比例留空。
4. 要核对 ZIP 文件齐全、行数和 T8 结果，可在项目根目录运行下面的命令。

```powershell
python -m tools.analyze_field_experiment path/to/experiment_export_2026-11-19.zip
```

5. 如需 A/B/C 准确性对比，先用批量重放脚本把各轮原始 RSSI 送回后端（`--config-id` 对 T6/T7 必填），再让分析脚本读取结果：

```powershell
python tools/replay_all_field_runs.py experiment_export_2026-11-19.zip --base-url http://<后端地址> --token <账号令牌> --config-id <冻结配置> --out replay.json
python -m tools.analyze_field_experiment experiment_export_2026-11-19.zip --replay replay.json --csv metrics.csv
```
