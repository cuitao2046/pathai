# AEGIS 定位算法实现差距评审

> 评审基准：《AEGIS 技术详解：BLE 指纹网格定位的工作原理》
> 评审范围：`backend/pathai_backend/fingerprint_library.py`、`location_solver.py`、`routers/location.py`、`routers/nav.py`、`client/core/ble/scan-window.ts`、`client/core/position/location-pipeline.ts`、`client/pages/map/map.ts`、`client/core/nav/nav-session-controller.ts`、`src/tools/generate_fingerprint_grid.py`、`client/core/collection/*`
> 评审日期：2026-11-20
> 修订：2026-11-20 依据现场实验实现（`field.py`）与客户端扫描链路复核，修正 A4/A7/D2/D3/D4，并将 A2 的结论降级为待验证假设。

## 结论先行

当前实现是「**1-NN 指纹匹配 + 三点定位兜底**」的最小闭环，只覆盖了文档五段式流程中的第 1、2 段（扫描、匹配），第 3、4 段（IMU/滤波融合、地图匹配）**完全没有实现**；且第 2 段也不是文档描述的 KNN/WKNN，而是「取单个最相似点 + 四条阈值否决」。

需要验证的疑点：**「与次优差距 ≥ 3 dB」门槛可能与 1–2 m 网格的物理事实相冲突**——若相邻网格点的指纹只差 1–2 dB，`margin < 3 dB` 就会判为 `ambiguous` 并降级到三点定位。但该门槛比较的是同一帧观测对两个候选点的 RMSE 差值，仅凭网格间距推不出触发回退的比例；当前也还没有完成的 T8 记录。因此「长走廊系统性拒答」应作为**待验证假设**，用 T6/T8 同一批样本测 C 的回退率、命中点 P90 与错走廊率。

全仓库检索确认：没有任何 KNN / WKNN / 卡尔曼 / EKF / 粒子滤波 / 步行模型的实现或注释（仅 `location.py` 明确注明「IMU 仅回显 heading，第一阶段不解算惯性」）。

## 差距清单

### A. 指纹匹配层（文档 §三）

| # | 差距 | 代码证据 | 影响 |
|---|---|---|---|
| A1 | 只有 1-NN，无 KNN/WKNN 加权平均；输出恒为网格点中心坐标 | `fingerprint_library.py` L842–L885 只维护 `best` 单点，没有 K 集合与权重求和 | 位置在 1–2 m 网格间离散跳变，无法得到连续坐标；相邻两格之间无法表达 |
| A2 | 用「与次优差距 ≥ 3 dB」作为硬门槛 | `fingerprint_library.py` L817–L880：`second_rmse` 对全部候选统计（含紧邻格点） | **待验证假设**：相邻格点若只差 1–2 dB，正常匹配可能被判 `ambiguous`；须实测 C 回退率后再决定是否改为空间去重候选或 K 点决策。当前无 T8 数据，不能直接断言「系统性拒答」 |
| A3 | 缺失信标零惩罚；无「出现率」维度 | 交集 `common` 之外的 stored 信标完全不计分；`coverage = len(common)/min(len(live),len(stored))` 在常见情形恒为 1.0（L848–L854） | 「此处本应收到 B3 却收不到」是强位置线索，现在完全丢失；遮挡造成的判错无法被约束 |
| A4 | 同信标重复观测时后端取最强值 | 正常链路：客户端 2 s 窗口中位数（`scan-window.ts` L81）→ 后端建库/重放中位数（`field.py` L627、L679）；`_live_vectors` 的最强值只在同一请求内出现重复信标时生效（L794–L805） | 实测链路两端口径已基本一致；剩余偏置只存在于重复信标场景，量级需数据验证，不应作为系统性正偏 |
| A5 | 只用中位数入向量，std / 出现率 / 有效样本数 n 全部丢弃 | T4 建库已带 `n`（`field.py` L626–L631，schema 1.3.0 L235–L241），但 `_aggregate_points` 仍只做 median | 文档要求的 4 项统计只落地「中位数 + n」；std、出现率未入库，无法做按稳定性加权的 WKNN |
| A6 | 训练点坐标取第一条记录，多次采集坐标不一致时静默忽略 | `x, y = items[0]["coordinates"]`（L415）；T4 建库已在 `field.py` L620–L622 增加跨清单真值一致性校验 | 现场建库链路已防冲突；直接导入旧格式导出文件时仍会静默取第一条 |
| A7 | 方向已采集但未进入指纹库 | 采集段已保存朝向并按 part 校验四向（`field.py` L131、L155–L159），但建库按 fpId 聚合时合并为一个方向无关向量（`field.py` L617–L631），`FpRecord` 无 orientation 字段 | 文档 §五.2 的「四方向采集」已具备；缺口在**建库与在线匹配不利用朝向**，人体遮挡差异被平均掉 |
| A8 | 无设备偏差 / 机型校正 | 库中与在线都是原始 dBm 直接相减 | 换机型后系统偏差可达数 dB，与最大的位置差异同量级 |
| A9 | 楼层判定依赖客户端楼层提示，不跨层比较 | `floors = {floor_hint}`（L833–L836） | 提示错时指纹侧无法自纠正（三点定位侧有楼层投票）；跨层误匹配不会被发现 |

### B. 滤波与融合层（文档 §四）

| # | 差距 | 代码证据 | 影响 |
|---|---|---|---|
| B1 | 完全没有状态估计滤波（卡尔曼/EKF/粒子）、没有步态模型 | 全仓库无实现；`location.py` L7 明示不解算惯性 | 逐拍独立估计，抖动直接进入导航 |
| B2 | 客户端位置零平滑、零跳变剔除 | `map.ts` L2977–L2989 直接 `navPosition = position` 并 `followPosition()`；只有航向做了 `HeadingSmoother`（`nav-arrow-angle.ts` L106） | 文档所述「1 秒移动 5 米应被拒绝」完全不存在 |
| B3 | 服务端同样没有速度/连续性校验 | `nav.py` L578–L648：只要 `quality` 可信、时间新鲜即直接推进进度 | 单拍异常会直接推动转弯指令或触发重规划（除 `OFF_ROUTE_M` 外无迟滞） |
| B4 | 置信度只用于分档，不参与导航决策 | `FINGERPRINT_RELIABLE_CONFIDENCE = 0.75`（`location.py` L44–L45），`trusted = reliable or degraded`（`nav-session-controller.ts` L517–L580） | 置信度 0.56 与 0.99 在导航上等价；误差半径不进入到达半径/播报提前量 |
| B5 | 置信度公式本身未标定 | `confidence = max(0, 1 - rmse/20) * coverage`（L864–L872） | `CONFIDENCE_RMSE=20 dB` 与 `MAX_RMSE=8 dB` 组合下，4 dB 残差仍得 0.8 分，数值与物理误差无对应关系 |

### C. 地图约束（文档 §四、§七）

| # | 差距 | 代码证据 | 影响 |
|---|---|---|---|
| C1 | 没有真正的「地图匹配」：无穿墙/可达性校验，只做重规划 | `nav.py` L617–L629 仅按 `OFF_ROUTE_M` 判断离路线 | 平行走廊无法消歧；异常估计直接触发重规划 |
| C2 | 无「穿墙、不可达」后处理，也无「吸附到最近走廊」 | `snap_to_node` 只用于路径图搜索（`nav_service.py` L95） | 文档警告的误吸附风险尚未遇到，但相应的保护（可达区域过滤）也未建立 |
| C3 | 指纹网格与导航网格分离 | 网格生成独立于拓扑（`generate_fingerprint_grid.py` L456–L597） | ✅ 与文档一致，不算缺口 |

### D. 实验与评估（文档 §五、§六）

| # | 差距 | 代码证据 | 影响 |
|---|---|---|---|
| D1 | 0.5 m 网格档无法生成 | 固定 `NORMAL_SPACING_M=2.0`、`SPLIT_SPACING_M=1.0`（L51–L59、L183–L227），无 spacing 参数注入 | 文档三组对照实验里的「网格密度 0.5/1/2 m」实际只能跑 1/2 两档 |
| D2 | 独立测试流程已有，但缺少「测试点与建库坐标重叠」核对 | T6 静态对比 18 点 × 4 朝向、T8 路线 12 检查点独立采集（`docs/现场测试方案.md` L115–L127）；`field.py` 无测试点与 FP 建库点的距离/重合校验 | 若测试点与建库点重合，精度会被高估且不可发现；网格间距本身不能作为误差下界 |
| D3 | 已有逐点误差重放，缺汇总指标 | `POST /field/replay` 返回 A/B/C 每个检查点的 `errorM`（`field.py` L645–L697）；`tools/analyze_field_experiment.py` 仍只算转向播报/震动时序 | 缺自动汇总：平均误差、P90、跳变次数、有效定位率、错走廊率；这些是文档 §六的核心因变量 |
| D4 | 阈值可冻结，但缺「多组合对比」入口 | 方法 C 冻结库版本与 5 项阈值（`field.py` L413–L446），重放读取 `config["C"]`（L685）；`query` 支持 `frozen` 与 `min_margin_db` 覆盖 | 同一批样本只能跑单一冻结配置，无法比较不同阈值组合；做敏感性实验需要新增入口 |
| D5 | 无环境稳定性维度 | 无繁忙/空旷标记进入指纹库（`trafficWindow` 仅存在于静态标定会话） | 第三组实验缺少数据支撑 |

## 已有且与文档一致的部分

- 2 s 滑动窗口逐信标中位数 + `[-100,-20]` 截断 + 未登记三元组丢弃不虚构（`scan-window.ts` L55–L108）。
- 指纹优先、异常不影响主链路、失败原因回传用于解释降级（`location.py` L163–L188）。
- 库版本化、幂等入库、墓碑删除、不把「本批未出现」当删除（`fingerprint_library.py` L491–L665）。
- 缺失安装高度信标 fail-safe 排除、未知信标进 `ignoredBeaconIds`（`location_solver.py` L239–L257）。
- 指纹网格与导航网格解耦、按可通行区与覆盖交集选点（与文档 §五.3 一致）。

## 建议的改动顺序（按投入产出）

1. **先验证 A2，不要先改判据**：用同一批 T6/T8 样本比较「当前 3 dB 门槛」与「空间去重后的候选判据」，看 C 回退率、命中点 P90、错走廊率，再决定是否引入 WKNN。
2. **A3（缺失信标惩罚）** 可与 A2 验证并行准备：缺失信标是独立于门槛判据的信息损失，但同样应先量化影响。
3. **A1 → KNN/WKNN**：命中取 K=3~5，按 `1/(D+ε)` 加权输出连续坐标，并把 K、权重纳入冻结配置。
4. **A4/A5**：重复信标统一取中位数；聚合时把 `std`、出现率、`n` 一并入库并参与权重；A7 在建库与匹配中按朝向拆分或增加朝向特征。
5. **B1–B3**：最小可行版本——客户端速度门控 + 一维位置低通（或匀速卡尔曼），服务端加「单拍位移/楼层突变」拒收，不改导航协议。
6. **D1–D4**：网格生成器暴露 spacing 参数（0.5/1/2）；补测试点与建库点重合校验、P90/跳变/有效定位率汇总、多阈值组合重放入口。
7. **C1**（地图可达性约束）放在滤波之后做；**E1** 建议在 D3 汇总前统一传播参数。

## 确定性说明

- **确定性结论**（代码可直接核验）：A1、A3、A5、A6、A8、A9、B1–B5、C1–C2、D1、D5、E1–E4。
- **已修正的表述**：A4 不再是「系统性正偏」，正常链路两端口径一致；A7 的缺口是「建库/匹配不用朝向」而非「无法四向采集」；D2/D3 已有独立 T6/T8 与逐点重放，缺口是重合校验与汇总指标；D4 阈值已可冻结，缺口是多组合对比入口。
- **待验证假设**：A2 的拒答比例、A8 的机型偏差量级、B5 的置信度与真实误差映射、E1 中两套参数各自的误差，必须用同一批 T6/T8 数据（不同机型、朝向、人流）标定后才能给出数值结论，不能用当前代码常量反推。
