# 标定链路说明：采集动作、拟合建模、参数落地

> 版本：1.0 ｜ 2026-11-09 ｜ 面向：现场采集执行者、参数拟合执行者
> 关联：`docs/28`（定位参数现场标定方案）、`docs/24` §4/§6、`docs/31`（动态标定）、
> `specs/field-collection-integration/spec.md`、`specs/phase-1-indoor-navigation/spec.md`
>
> 本文只解释关系与边界，不替代上述规范。所有数值以现场实测与最终冻结的 `paramsVersion` 为准。

---

## 0. 结论先行

| 概念 | 本质 | 输入 | 输出 | 算不算「标定」 |
|---|---|---|---|---|
| 静态标定采集页 | **采集动作**（传感器 + 计时 + 落盘 + 导出） | 人工到点确认 + 现场 BLE 广播 | `static_samples.json`（原始观测的逐信标统计） | **不算**。它是标定的取数环节，产出样本，不产出参数 |
| 对数等距采集 | **采样设计**（布点方案） | 一枚参考信标 + 可通行直线 + 卷尺/图纸 | 一份「在哪些距离上采」的现场作业清单 | **不算**。它决定样本质量，不参与计算 |
| RSSI@xm 标定 | **拟合/建模 + 参数冻结** | `static_samples.json` + `ble_deployment.json` + 地图包 | `A`、`n`（可选按楼层分组）、残差阈值建议、`paramsVersion` | **算**。这是真正意义上的「标定」 |

三者的关系一句话：

```
对数等距采集（怎么布点）
        ↓ 指导
静态标定页（去哪儿、站多久、采几次、怎么落盘）
        ↓ 产出 static_samples.json
fit_location_params.py（拟合 A / n / 阈值）
        ↓ 人工审核后写入
后端 PATHAI_LOCATION_* + paramsVersion
        ↓ 同步
客户端常量、指纹网格可采集判定、文档口径
```

**最容易犯的错**：把采集页当成「标定工具」，以为导出文件里应该有 `A` 和 `n`。导出文件里没有，也不应该有——单点单次的 RSSI 中位数不是 `A`，几何距离也不是拟合结果。

## 1. 静态标定采集页到底做什么

### 1.1 现场动作

1. 设置页打开「现场采集工具」→ 首页左上角工具条第 4 颗「采集」→「静态标定」。
2. 走到目标点位，**用现场参照物（门牌、墙角、柱子、地面标记）人工确认到达**。App 不做位置门禁，页面上的定位蓝点只是辅助。
3. 点地图上的点位（或长按空白处补标一个新点）→ 确认卡 → 确认。
4. 倒计时开始（可选 30 / 60 / 120 秒，默认 60 秒），期间累积该点收到的全部广播；页面实时显示前几个信标的样本数与中位数。
5. 倒计时结束自动落盘为**一条会话**，点位变绿并显示次数角标。
6. 同一点重复 3–5 次、跨人流高峰/低谷；全部采完后导出 JSON。

### 1.2 实际采集与导出的字段

导出的顶层结构（`schemaVersion 1.0` / `type positioning_calibration_static`）：

| 层级 | 字段 | 实际含义 / 现场注意 |
|---|---|---|
| 顶层 | `venueId`、`operator`、`device`、`appVersion`、`mapVersion` | 追溯用；`appVersion` 当前写死 `1.0.0` |
| 顶层 | `windowMs: 2000` | **契约字段**，见 §1.3 的口径差异 |
| 顶层 | `beaconLedgerSha256` | **当前恒为 `null`**（页面未计算台账摘要），不要指望用它校验台账 |
| 点 | `pointId`、`floor`、`truth[x,y]`、`scene`、`envNote`、`markType` | 预置点 20 个（F1 16 / F2 4）；`markType` 当前恒为 `map_tap` |
| 会话 | `sessionIndex`、`startedAt`、`durationS`、`trafficWindow` | `trafficWindow` **当前恒为 `false`**，跨时段信息只能靠 `startedAt` 人工判断 |
| 会话 | `estimateAtStart` / `estimateAtEnd` | 采集起止时的定位快照（仅可信估计时存在），供分析，不参与门禁 |
| 观测 | `beaconId`、`n`、`rssiMedian`、`rssiMin`、`rssiMax`、`rssiStd` | 每个信标一条；`n` 是本次会话内被采纳的原始样本数 |
| 观测 | `truthDistanceM` | 真值点到信标的**三维斜距**，见 §1.4 |

**没有的东西**（重要）：没有原始逐帧广播、没有 `uuid/major/minor`、没有 IMU、没有 `txPower`、没有 `A/n`、没有峰值/低谷标记、没有「标称米数」字段。

### 1.3 采样窗口：实现与文档表述不一致，以代码为准

- `docs/28` §4.2 与 `spec` §3.4 写的是「2 s 滑窗、逐信标中位数」。
- **静态标定页的实际实现**（`client/core/collection/static-sampler.ts`）是：**整段倒计时内累积全部原始样本**（截断到 `[-100, -20]` dBm），结束时对每个信标的全部样本算中位数、最小值、最大值、总体标准差。它**没有**走 `ScanWindowAggregator` 的 2 s 滑窗。
- 同一个页面上的 2 s 滑窗只服务于**定位估计**（`LocationPipeline` → 蓝色定位点）和**网格指纹页**的快照；不参与静态标定的统计。
- 因此：导出里的 `windowMs: 2000` 是契约字段，不代表 `rssiMedian` 是按 2 s 窗口算出来的。`n` 也不是「窗口个数」，而是原始样本条数。

对现场的影响：一次 60 s 停留、信标 10 Hz 广播，一个信标很容易积累几百条样本。中位数抗抖动能力足够，但**不要把 `n` 当作独立环境次数**——同一次停留内的高相关样本不能当多次实验。

### 1.4 真值从哪来，是否包含三维斜距

- **预置 20 点**：坐标由脚本从 `result/fingerprint_grid_routes.json` 与地图包拓扑派生（`client/data/calibration_points.ts`），本质是**地图坐标**，不是每点都用激光测距现场量出来的。
- **补标点**：长按地图取点，真值就是**地图拾取坐标**，精度取决于地图数字化精度与手指落点。
- 两者都不是严格的「图纸 + 激光测距 ≤0.2 m」真值。现场必须用参照物核对；发现明显偏差时，优先补标一个经过核实的新点，而不是硬用预置点。
- `truthDistanceM` 确实是三维斜距：

```
d = √((x−xᵢ)² + (y−yᵢ)² + (installHeightM − 1.2)²)
```

  信标高度取地图包/台账的 `installHeightM`（当前 2.5 m），手机高度固定按 1.2 m；`installHeightM` 缺失时退化为平面距离。**信标这一端永远以台账为准**，PC 侧还会按台账坐标重算并做 ±0.05 m 校验。

### 1.5 所以它「算不算标定」

不算。它是**标定实验的数据采集器**。页面名字里的「静态标定」描述的是任务（为标定做静态停留采集），不是产出物。真正的标定发生在 PC 脚本里。

## 2. 「对数等距采集」是什么、不是什么

### 2.1 它是什么

一种**采样设计（experiment design）**：以某一枚信标为起点，沿可通行直线按近似几何级数布点，例如：

```
水平距离：0 / 1 / 1.5 / 2 / 3 / 4.5 / 6.5 / 9 / 13 / 18 m
每点停留：60–120 s，重复 3 次（最好跨时段）
```

目的不是「多采」，而是让 `log10(d)` 轴上的样本**分布均匀**。因为拟合是在 `x = log10(d)` 上做直线回归：

- 如果 90% 的点都挤在 1–3 m，`x` 的跨度很小，斜率（也就是 `n`）的置信区间会非常宽，外推到 10 m 以外基本不可信；
- 近距点还会被 `A` 主导，远距点被 `n` 主导，样本失衡会让两者互相抵消，出现「R² 看起来还行，但外推全错」。

### 2.2 它不是什么

- 不是标定方法：它不产生参数，也不改变拟合公式。
- 不是页面功能：静态标定页不知道「等距」这件事，它只负责在**你给的坐标**上采一段停留样本。布点靠人，页面不约束。
- 不是仓库里已有的脚本或清单：截至本文，仓库内没有「对数等距」的布点生成器或执行文档；它是现场执行层面的方法约定，需要用补标点/预置点手动落地。
- 不能替代 20 点场景配额：两者回答的是不同问题（见 §2.4）。

### 2.3 与静态标定页的关系：工具与用法

| | 静态标定页 | 对数等距采集 |
|---|---|---|
| 回答的问题 | 在这个坐标上，各信标的 RSSI 统计是多少？ | 应该把坐标选在哪些距离上？ |
| 谁执行 | 现场采集者操作小程序 | 采集方案设计者提前规划 |
| 产出 | `static_samples.json` | 一张点位清单（可用地图长按补标实现） |
| 两者关系 | **工具** | **用法** |

换句话说：页面是「录音机」，对数等距是「录音脚本」。换一个布点方案（比如 20 点场景覆盖），页面照样能用。

### 2.4 与预置 20 点方案的关系

| 方案 | 设计目标 | 强项 | 弱项 |
|---|---|---|---|
| 预置 20 点（F1 16 / F2 4） | **场景覆盖**：走廊中段、交叉口、门洞、电梯厅、大厅、靠窗、弱信号 | 能回答「全场一套参数够不够、要不要按楼层分组」 | 距离跨度不可控，可能缺少 10 m 以上样本 |
| 对数等距 | **距离覆盖**：让 `log10(d)` 均匀 | 能稳定反演 `A`、`n` | 不覆盖场景异质性，不能单独支撑分组判定 |

严谨做法是**先对数等距拿 `A/n`，再用 20 点做场景验证与分组判定**。如果只能出一趟现场，20 点也能拟合，但必须接受 `n` 的不确定性，并在报告里说明距离覆盖不足。

### 2.5 现场必须注意的三个坑

1. **标称米数 ≠ 模型距离**。模型用的是三维斜距：手机高 1.2 m、信标高 2.5 m，`dz = 1.3 m`。水平 0 m 处的真实 `d` 是 1.3 m，水平 1 m 处是 1.64 m，水平 3 m 处是 3.27 m。
   - 所以「0 m 点」测到的不是 `A`（`A` 是回归截距，对应 `log10(d)=0`，即 `d=1 m` 的理想参考）；
   - 近距段被 `dz` 压缩得最厉害，布点时不要以为 0/1/1.5 是三个线性等距点。
2. **`A` 不是某个点的实测值**。即使你采了 1 m 点，它也只是回归中的一个样本；`A` 是整条直线的截距。只用一个点当 `A`，等价于默认 `n` 已知或 `d` 无误差，不可取。
3. **穿墙点必须单列**。对数等距线应尽量走 LOS 直线；如果中途穿墙、隔玻璃、贴金属，必须记录并单列，不能混进全局 `LOS` 拟合，否则 `n` 会被 NLOS 衰减系统性抬高。

### 2.6 与静态标定页导出数据的配合：RSSI@xm 标定实操闭环

对数等距设计要变成拟合可用的数据，必须经过静态标定页的导出契约。两者在**三个接口点**上咬合：

**接口一：布点 → 页面点位（坐标怎么进）**

- 对数等距清单里的每个距离档，用静态标定页的**长按补标**落成点位，命名带距离（如 `CAL-F1-LOS-D01`、`-D1.5`、`-D18`），真值坐标即长按处的地图坐标。
- 页面不认识「等距」概念，不做任何距离校验——布点质量完全由录入者负责。点位名带距离是现场唯一能事后核对「采没采对档」的凭据。

**接口二：采集 → 导出（每档产出什么）**

- 每档 60–120 s × 3 次会话；导出后**每条会话 × 每个可见信标 = 一个观测对 `(truthDistanceM, rssiMedian)`**。
- 虽然布点是围绕参考信标的等距线，但页面会记录**所有**可解析信标——参考信标那组对负责铺满 `log10(d)` 轴，其余信标对按各自距离自动补充样本，全部进入拟合（脚本不去重、不挑信标）。
- 3 次重复会话在同一距离档给出 3 个独立观测，可用来评估同距离下的 RSSI 离散度（多径/人体/朝向影响），也是脚本「不去重不平均」设计的用意。

**接口三：水平米数 → 模型距离（拟合用的 d 是哪个）**

脚本按台账重算的 `d` 是**三维斜距**，不是布点时的水平米数。`dz = 2.5 − 1.2 = 1.3 m` 固定不变，换算如下（现场布点可直接对照）：

| 水平布点 h (m) | 模型距离 d (m) | log10(d) | 备注 |
|---:|---:|---:|---|
| 0 | 1.30 | 0.114 | 近距档；**不是 A** |
| 1 | 1.64 | 0.215 | |
| 1.5 | 1.99 | 0.298 | |
| 2 | 2.39 | 0.377 | |
| 3 | 3.27 | 0.514 | |
| 4.5 | 4.68 | 0.671 | |
| 6.5 | 6.63 | 0.821 | |
| 9 | 9.09 | 0.959 | |
| 13 | 13.06 | 1.116 | |
| 18 | 18.05 | 1.256 | 远距档；接近 -85 dBm 可用边界 |

注意三点：

1. 上述 10 档铺满约 1.14 个十进制位（log10 跨度），这就是等距设计的价值——n 的斜率置信度直接取决于这个跨度；
2. `h=0` 点的 `d=1.30 m`，离 `A` 的定义点（d=1 m）最近但**不相等**，`A` 仍只能由回归截距给出；
3. 近距档受 `dz` 影响最大（水平 1 m 被抬到 1.64 m），不要为了「贴近 1 m」把点移到 h≈0.2 m 处硬凑——脚本有 `d<0.5 m` 报错保护，且贴信标站立的遮挡效应会污染样本。

**闭环核对清单（导出后、跑拟合前）**：

- [ ] 每个距离档都有 ≥3 条会话，且 `pointId` 命名可对回布点清单；
- [ ] LOS 线上无混入的穿墙点（穿墙点已单列命名）；
- [ ] 导出顶层 `mapVersion` 与当前台账/地图包一致；
- [ ] 每档观测对的 `rssiMedian` 未触及 -100/-20 截断边界（触及说明样本不可信）；
- [ ] 远距档（13/18 m）参考信标仍有 ≥3 枚可见信标，否则该档实际无效。

满足以上，即可直接执行 §4 第 4 步的 `fit_location_params.py`——脚本消费的就是这份导出，无需任何中间转换。

## 3. RSSI@xm 标定到底产出什么

### 3.1 模型与反演

```
rssi = A − 10·n·log10(d)
```

令 `x = log10(d)`、`y = rssi`，就是直线回归：**截距 = A**，**斜率 = −10n**。`fit_location_params.py` 用普通最小二乘反演。

- 真值距离 `d` **一律按台账坐标重算**，不信任样本里的 `truthDistanceM`（后者只做 ±0.05 m 交叉校验）。
- 当前实现是**等权 OLS**：`n`（样本条数）不参与加权。`static-sampler.ts` 注释里「PC 侧拟合以此为权重」与现状不符；如需按样本数加权，要先改脚本。
- 硬门槛：至少 3 个观测对；`d < 0.5 m` 直接报错（疑似真值录错）；`rssiMedian` 必须是 `[-100,-20]` 内的整数；schema / type / 台账信标引用任何一项不自洽，脚本**非零退出**，不会静默出参。

### 3.2 产出清单

| 产物 | 含义 | 是否必须冻结 |
|---|---|---|
| `rssiAt1m` | 1 m 参考 RSSI（`A`） | 是 |
| `pathLossExponent` | 路径损耗指数 `n` | 是 |
| `groups` | 可选按楼层分组参数；仅当每组 ≥50 对且 RMSE 相对全局下降 >30% 才启用，禁止逐信标分组 | 视判据 |
| `thresholds.residualReliableM` / `residualDegradedM` | 残差门限，决定 `reliable/degraded` | 是 |
| `thresholds.originMinConfidence` | 置信度原点 | 是 |
| `fit` / `metrics` | 样本对数、`R²`、RMSE、各楼层指标 | 随文件保存 |
| `metrics.staticReplay` | 用生产解算回放静态会话得到的 CEP50/75/90、质量分布 | 随文件保存 |
| `paramsVersion` | 参数版本号，写日志、API-05、导航会话 | 是 |
| `sourceStaticSamplesSha256` / `beaconLedgerSha256` / `mapVersion` | 可追溯性绑定 | 是 |

注意：**阈值不是「标定 A/n 顺带就有」**。阈值是用拟合参数回放静态点、按 CEP90（目标 3 m）反推出来的，依赖点位数量与会话数量。点位太少时，`A/n` 可能可算，但阈值建议不可信。

### 3.3 参数分别被谁消费

| 消费方 | 消费方式 | 当前取值来源 | 标定后要做什么 |
|---|---|---|---|
| 后端生产解算 `location_solver.py` | `rssi_to_distance`、`quality` 判定、`confidence` | `PATHAI_LOCATION_*` 环境变量；默认 `A=-71`、`n=2.0`、残差 `1.5/4.0` | 写入实测值，重启后端，递增 `paramsVersion` |
| 后端 API / 会话 | `POST /locations/estimate` 返回 `paramsVersion`；导航会话固化 | `config.py` | 无需改代码，随环境变量生效 |
| 客户端 mock 信标源 | 合成 RSSI | `client/config/env.ts` 的 `BEACON_RSSI_AT_1M_DBM=-71`、`PATH_LOSS_N=2.0` | **手工同步**为新 `A/n`，否则 mock 与生产不一致 |
| 客户端网格指纹采集 | `FpBeaconObs.txPower`、`accuracy` 反推 | 同上，来自 `BEACON_RSSI_AT_1M_DBM` | 同步；否则采集页显示的距离与生产解算不一致 |
| 指纹网格可采集判定 | 预测 RSSI、可采集点数量 | `generate_fingerprint_grid.py` 内置 `A=-52`、`n=3.5` + 墙衰减 | **独立决策**：是否采用实测值重算（见 §5） |
| 分析脚本 / 交互渲染 | 覆盖仿真 | `src/tools/refine_beacon_placement.py`、`src/rendering/render_interactive.py` 等内置 `-52/3.5` | 与网格口径同步，避免图与表互相矛盾 |

### 3.4 为什么生产 `A/n` 与规划网格 `A/n` 是两套口径

- 生产 `A/n` 要回答「这台手机在这个时刻离信标多远」，必须用**实测**值，且只用于 RSSI→距离。
- 规划网格 `A=-52 / n=3.5` 要回答「这个点理论上能收到几枚信标、值不值得派人去采」，是**覆盖可行性预测**，还叠加了材质墙衰减（partition/brick/concrete = 8/12/15 dB，门 2 dB）。它是工程假设，不是实测标定值。
- 两者可以最终收敛到同一套数，但**不能默认相同**。如果现场实测 `A/n` 与 `-52/3.5` 差异显著，说明「哪些点可采」的结论会整体漂移，必须重新生成网格并重新发布客户端数据。

## 4. 端到端链路：现场按这个顺序走

### 第 0 步：前置条件（缺一不可）

- 信标已按真实部署台账完成**写入 → 重启 → 校验 → 上传**（先配置信标，再标定参数；否则测的是错配信标的信号）。
- 地图包与台账版本已冻结；手机与后端使用同一 `mapVersion`。
- 手机统一手持在约 1.2 m 高度，尽量同朝向，避免人体遮挡。
- 记录操作人、设备型号、时段（高峰/低谷）。

### 第 1 步：布点（采样设计）

二选一或组合：

- 场景覆盖：直接用预置 20 点；
- 距离覆盖：沿 LOS 直线布 1 / 1.5 / 2 / 3 / 4.5 / 6.5 / 9 / 13 / 18 m（0 m 点可作为核对点，但它不是 `A`），用地图长按补标落点并命名。

每点在地面做可复现标记（美纹纸/粉笔），记录实际水平米数与是否穿墙。

### 第 2 步：静态采集（采集动作）

设置 → 现场采集工具 → 采集 → 静态标定 → 逐点确认 → 60 s（或 120 s）→ 自动落盘。每点 3 次，跨时段；穿墙点单独命名（如 `CAL-F1-NLOS-01`）。

### 第 3 步：导出

页面「导出」→ 写 `USER_DATA_PATH` 文件 + 复制剪贴板 + 微信分享。取出后放到：

```
result/calibration/static_samples.json
```

该目录按仓库策略不入库（`result/calibration/` 为现场数据），参数版本文件才入库。

### 第 4 步：拟合（建模动作）

```powershell
python src/tools/fit_location_params.py `
  --samples result/calibration/static_samples.json `
  --ledger result/ble_deployment.json `
  --map-package backend/maps_data/<venue>/<mapVersion>.json `
  --params-version loc-20261109.1 `
  --out result/calibration/location_params_loc-20261109.1.json
```

脚本会输出：全局 `A/n`、`R²/RMSE`、是否启用楼层分组及理由、静态回放 CEP50/75/90、建议阈值。**它只写文件，不改任何配置。**

### 第 5 步：人工审核与冻结（参数落地）

- 检查 `R²`、RMSE、CEP90 是否可接受；检查分组判据是否真的成立。
- 写入后端环境变量（本地在 `backend/.local/start-local.ps1`，部署环境在对应配置）：

```
PATHAI_LOCATION_RSSI_AT_1M=<A>
PATHAI_LOCATION_PATH_LOSS_N=<n>
PATHAI_LOCATION_RESIDUAL_RELIABLE_M=<...>
PATHAI_LOCATION_RESIDUAL_DEGRADED_M=<...>
PATHAI_LOCATION_PARAMS_VERSION=loc-20261109.1
```

- 按规范脚本顺序重启本地后端（先 stop 再 start），确认 `/locations/estimate` 返回新的 `paramsVersion`。

### 第 6 步：客户端同步

- 修改 `client/config/env.ts` 的 `BEACON_RSSI_AT_1M_DBM` 与 mock 的 `PATH_LOSS_N`，与后端保持一致；
- 重新编译小程序，确认采集页 `accuracy`、mock 定位、导航定位口径一致。

### 第 7 步：决定是否重算指纹网格

只有当你决定把实测 `A/n` 用于**覆盖规划**时才做：

1. 更新 `src/tools/generate_fingerprint_grid.py` 的 `BEACON_RSSI_AT_1M_DBM` / `BEACON_PATH_LOSS_N`（以及墙衰减假设，如果现场有实测依据）；
2. 重跑生成器 → 新的 `result/fingerprint_grid.json`、F2 可采集清单、统计表；
3. 重新派生 `client/data/fingerprint_grid.ts` 与 `fingerprint-collector` 数据；
4. 同步交互渲染里的 `COV_RSSI_REF_1M / COV_N`；
5. 更新 `specs/field-collection-integration/spec.md` 的覆盖数字与网格版本号。

**这一步会改变「现场该采哪些点」**，必须当作一次独立发布处理，不能夹在参数冻结里顺手做。

### 第 8 步：回归与留痕

- 静态回放：看 CEP 是否达标；
- 动态路线回归（`docs/31`）：偏航/到达/跨层是否正常；
- 通过后冻结 `paramsVersion`，登记验收项；
- 地图、台账、信标位置任一变化，整条链路重跑。

## 5. 三组容易混淆的数字

| 数字 | 出处 | 含义 | 能不能当 `A` |
|---|---|---|---|
| `txPower = -12` dBm | `result/ble_deployment.json`、信标配置 | **发射功率档位**（E5 3 档） | **不能**。这是「发出去多强」，不是「1 m 处收到多强」；`A` 还包含天线增益、极化、人体遮挡等，通常比发射功率低几十 dB |
| `RSSI@1m = -71` dBm | 后端 `config.py` 默认值、客户端 `env.ts`、mock、后端测试 | 由 0 dBm 档典型 -59 dBm 减 12 dB 推算的**占位值**，`n=2.0` | **暂时能跑，但不是实测值**。`docs/28` 明确说精度未验证；它让 live 定位「能出坐标」，不代表误差达标 |
| `A = -52` dBm、`n = 3.5` | `generate_fingerprint_grid.py`、`refine_beacon_placement.py`、`render_interactive.py` | 覆盖规划用的**工程假设**：TX −12 dBm + 1 m 自由空间损耗约 40 dB，再叠加墙衰减 | **不能直接当生产 `A`**。它没有经过现场实测，且模型里还额外扣了墙衰减 |

补充两个常被误用的字段：

- **`rssiMedian` 不能当 `A`**：它是某个点、某次停留、某个信标的中位数，包含多径、人体、朝向、电量等全部现场因素；`A` 是跨距离回归的截距。
- **`truthDistanceM` 不能当「实测距离」**：它是由台账坐标与固定手机高度**算出来**的几何量，不是卷尺量出来的；它只用于交叉校验台账与真值是否自洽。

还有两个口径要记住：

- 台账 `txPower` 自 2026-10-28 起**不再参与测距**，不要试图用 `txPower` 反推距离；
- `beaconLedgerSha256` 在采集页导出里是 `null`，PC 侧实际依赖 `mapVersion` 与人工台账核对，不要把它当作完整性凭证。

## 6. 验收口径与重算触发条件

### 6.1 采集是否足够

- 距离覆盖：`log10(d)` 至少覆盖约 1.3–18 m（对应水平 0–18 m）；
- 每点 ≥3 次会话，且至少覆盖两个时段；
- 全局观测对达到数十对以上；若要启用楼层分组，每层 ≥50 对；
- 穿墙/NLOS 点已单列，未混入 LOS 拟合。

### 6.2 拟合是否可用

- `n > 0`，且量级合理（室内通常 2–5）；
- `R²`、RMSE 在报告里可解释；RMSE 过大时先检查点位真值与穿墙样本；
- 静态回放 CEP90 达到导航可接受范围（脚本默认目标 3 m）；
- 阈值建议落在脚本的安全区间（`reliable 0.5–4 m`、`degraded 4–10 m`）。

### 6.3 什么情况必须重跑整条链路

- `A/n` 或阈值变更；
- 信标增减、位置调整、发射功率/广播间隔变更；
- 地图包或台账版本变更；
- 指纹网格的覆盖口径参数（`A/n`、墙衰减）变更——即使生产 `A/n` 没变，也要重算网格。

## 7. 现场禁止事项（FAQ）

| 做法 | 为什么不行 |
|---|---|
| 在信标未配置/未校验时标定 | 测到的是错功率、错间隔的信号，拟合出的 `A/n` 不可用 |
| 把长按补标的地图坐标直接当激光真值 | 地图数字化有误差；补标点必须用现场参照物核对，必要时改标 |
| 把穿墙点混进 LOS 拟合 | NLOS 衰减会被误当成路径损耗，`n` 系统性偏大 |
| 期待采集页显示 `A/n` | 页面只采不算；统计在 PC 侧，确保可复算、可审计 |
| 用单点 `rssiMedian` 当 `A` | 等价于假设 `n` 已知且距离无误差，外推不可控 |
| 用 `txPower=-12` 当 `A` | 发射功率不是接收参考；会让 `rssi_to_distance` 得出量级错误 |
| 用规划 `-52/3.5` 当生产参数 | 未实测，且含墙衰减假设；只能用于覆盖预测 |
| 改完参数不递增 `paramsVersion` | 现场排障无法确认「这次定位用的是哪套参数」；会话也无法回溯 |
| 改完 `A/n` 不重算网格 | 可采集点数量会与实际覆盖脱节，现场白跑或漏采 |
| 只改后端不改客户端常量 | mock、指纹 `accuracy` 与生产解算不一致，出现「两套真相」 |
