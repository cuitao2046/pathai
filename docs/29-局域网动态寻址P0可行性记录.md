## 微信官方文档依据（非实测）

- [局域网通信](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/mDNS.html)：同网段、非本机 IPv4 的请求可以用 HTTP 且不进行安全域校验；局域网互访条件不满足时不可用。
- [UDPSocket.send](https://developers.weixin.qq.com/miniprogram/dev/api/network/udp/UDPSocket.send.html)：文档称基础库 2.9.0 起可向 `255.255.255.255` 广播，`setBroadcast` 选项从 2.24.0 起支持；当前项目配置高于该版本，**不能推断目标真机一定支持广播转发**。
- [UDPSocket.onMessage](https://developers.weixin.qq.com/miniprogram/dev/api/network/udp/UDPSocket.onMessage.html)：返回 `message: ArrayBuffer` 和 `remoteInfo.address/port`，候选 IP 应从真实来源提取，再做 HTTP 挑战验证。
- [UserCryptoManager.getRandomValues](https://developers.weixin.qq.com/miniprogram/dev/api/base/crypto/UserCryptoManager.getRandomValues.html)：基础库 2.17.3 起提供密码学安全随机字节；P0 探测轮次使用该接口，真机可用性仍待确认。

## 已实现的隔离探测原型

- 从独立 worktree 仓库根设置 `PYTHONPATH=backend` 后运行 `python -m pathai_backend.local_discovery_probe`，启动独立 UDP 39001 与 HTTP 39002。不会启动原业务 API，不返回设备身份/签名，也不读取数据库、配对密钥或微信凭据。
- 本新分支的 P0 测试构建只注册独立探测页 `pages/p0-probe/p0-probe`，移除了启动登录预热；不会加载地图、进入设置页业务自检或访问固定 `API_BASE_URL`。点击“开始探测”后仅广播 `pathai-p0-probe` 的随机轮次、接收 `P0_OFFER`，再访问响应源的无凭据 `/local/p0/probe`；结果区分 UDP+HTTP、仅 UDP、超时和接口不可用。**该响应无身份认证，不能用于设置业务地址，也不能给出可信服务的结论**。
- 客户端探测使用安全随机数且对随机数、UDP、HTTP 各阶段设有时限；重复应答不重复发起探测请求，结束时关闭 UDP socket。服务端限定有效端口、私网来源及有界应答记录，端口被占用会报错而不是另选端口。
- 自动化验证（2026-11-01）：`npx tsc --noEmit` 通过；`npx jest --runInBand` **32 套/260 用例通过，1 套跳过**；仓库根 cwd 下 `python -m pytest backend/tests -q` 通过（1 套既有跳过），`python -m pytest tests -q --import-mode=prepend` **140 通过、1062 subtests 通过**。本机私网地址 `192.168.100.103` 上以独立 UDP 39111、HTTP 39112 完成同机单播→HTTP 探测，HTTP 返回 200 且服务正常关闭；这**仅证明同一台 Windows 主机私网接口上的协议往返**，没有验证微信广播、手机到电脑或跨网络切换。
- 本轮测试准备（2026-11-01）：独立服务持续监听 `0.0.0.0:39001/UDP`、`0.0.0.0:39002/TCP`；Windows 当前 WLAN 为公用网络，IPv4 `192.168.100.103/24`，本机通过该地址请求 `/local/p0/probe` 返回 `{"protocol":"local-service-discovery","ready":true}`。经用户确认，临时规则 `PathAI-P0-Probe-UDP-39001-TEMP` 与 `PathAI-P0-Probe-TCP-39002-TEMP` 只允许公用配置下、WLAN 接口、来源 `192.168.100.0/24` 到本机 `192.168.100.103` 的对应入站端口；**测试结束必须撤销这两条规则**，切网后须核对新子网而非继续沿用旧规则。尚无来自手机的实测请求。

## Windows＋手机微信真机操作

1. Windows 与手机连接同一 Wi-Fi，确认 Windows 的 WLAN IPv4 为私网地址。当前测试电脑为 `192.168.100.103`（可能随 DHCP 改变），临时防火墙规则限定当前 WLAN 子网与探测端口；切网后重新核对 IPv4/子网与规则，测试结束删除临时规则，不复用旧地址。
2. 在新分支仓库根的 PowerShell 中运行 `$env:PYTHONPATH='D:\code\p-lsd\backend'; python -m pathai_backend.local_discovery_probe`，确认端口没有被占用。探测器独立于业务后端，**不启动** `backend/.local/start-local.ps1` 也可验证 P0；不要把探测器的 IP 当作业务服务器地址。
3. 在本次 P0 构建的微信真机入口打开小程序，应只看到“局域网连接能力探测”，点击“开始探测”；记录测试时间、手机/系统/微信版本、基础库版本、Wi-Fi 名称、Windows IPv4、网络类型（公用/专用）、防火墙规则与页面结果。出现“已收到 UDP 响应并连通 HTTP 探测端口”仅记为网络探测通过；不发送登录、定位或导航请求。
4. 若只收到 UDP，请检查 TCP 39002、局域网互访及系统权限；若未收到 UDP，分别检查 UDP 39001、广播转发、系统本地网络权限和热点客户端隔离。无法诊断时记为未知，不猜测根因。
5. 在第二个 Wi-Fi 和由**第三台手机**提供的热点重复步骤 1–4；记录每次 Windows IPv4 的变化。若是热点宿主手机运行小程序，单独标为未承诺组合，不与第三方热点混记。
6. **开发工具 `urlCheck=false` 不等于真机放行**。只在可实际验证的微信真机入口及无开发绕过环境下记录结果；如发布/体验版无法访问私网 HTTP，则明确记为阻塞，不将开发版的结果推广到发布版。

## 待目标真机执行的实验

1. 记录 Windows 版本、微信版本、手机型号/OS、微信基础库实际版本、Wi-Fi/热点型号、防火墙网络配置；关闭开发工具绕过后验证 `wx.createUDPSocket`、`bind`、广播发送和单播接收。
2. 对同网段 HTTP 使用无凭据隔离探测服务验证连接；在 Wi-Fi A/B 与第三台手机热点分别测 UDP 与 TCP，可达性拆开记录。
3. 核查 iOS 本地网络权限拒绝/恢复，以及 Windows 公用/专用防火墙状态；拒绝时不误报“服务器未启动”。
4. 选用受维护且兼容小程序的安全随机数、JCS 与 HMAC 能力并对照 Python 测试向量；未完成前不得启用配对/认证的业务模式。

**当前状态：** 无目标真机、无热点及权限测试记录，UDP 广播、HTTP 及密码能力的端到端结论均为**未验证**。隔离原型的本机自动化测试不构成 P0 真机门槛通过，不能开始 P1/P2 的可信业务连接验收。
