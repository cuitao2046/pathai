## 0. 问题的真实战场：建库精度 ≠ 在线精度

| 维度 | 建库 / 离线 | 在线实时 |
|---|---|---|
| 测距手段 | 激光测距已知信标 σ_d=2cm | 手机 BLE RSSI σ_d≈1~3m（多径/遮挡） |
| 已有验证 | `result/subregion_two_point.json`：子区域 **99.9% 网格点 ≤5cm** | 本方案重点 |
| 结论 | **建库非瓶颈**，两点/三点法轻松 ≤5cm | **真正的难点在在线测距噪声 + 墙体 NLOS 偏置** |

> 关键澄清：在 σ_d=2cm 建库假设下「三点定位 ≤1m」是已被证明的 trivial 结论。本方案要解决的，是**在线手机 BLE RSSI（米级 σ_d）条件下如何逼近 1m**——且**不依赖指纹采集**。

## 1. 误差传播模型

三边测量线性化后，位置 RMS 误差：

$$\sigma_{pos}=\sigma_d\cdot\mathrm{GDOP}_m,\quad \mathrm{GDOP}_m=\sqrt{\mathrm{tr}\big((\mathbf{G}^\top\mathbf{G})^{-1}\big)}$$

- $\mathbf{G}$ 为可见信标单位视线（LOS）向量矩阵；LOS 方向越均匀铺开（≈120° 分离），GDOP 越低。
- 2D 理想环形下界：$\mathrm{GDOP}_{2D}\approx 2/\sqrt{N}$（N=3→1.155，N=4→1.0）。
- **3D 解算**（信标高 2.2m + 手机高 1.2m，≈1m 垂直偏移）可打破平面图视图下的近似共线。

由 $\sigma_{pos}\le 1\text{m}$ 得硬约束 $\mathrm{GDOP}\le 1/\sigma_d$：

| 在线 σ_d | 允许 GDOP 上限 | 纯三点可行性（线性走廊） |
|---|---|---|
| 0.5m（乐观强 LoS） | ≤2.0 | ✅ 可行 |
| 1.0m | ≤1.0 | ⚠️ 走廊难达 |
| **2.0m（典型多径）** | **≤0.5** | **❌ 结构上不可达** |
| 3.0m | ≤0.33 | ❌ 不可达 |

→ **σ_d=1~3m 时，纯几何（GDOP）在线性走廊下无法独立达标**。瓶颈在**测距精度本身**，而非几何布局。

## 2. 误差优化杠杆仿真（方案 A：引入墙体几何）

参数：σ_d=2.0m、可见半径 18m、时序样本 N=20、手机高 1.2m、信标高 2.2m；1F 可行走区 2172 个网格点。

> ⚠️ 方法学修正：早期「随机 NLOS 注入」模型把主导误差错判为纯噪声（得出 2.10m 中位）。**本版用已知墙体几何真实注入 NLOS**——才发现真正的杀手是**墙体造成的恒定偏置**，而它恰好能被几何消除。下表为修正后的真实结果。

| 配置 | 中位误差 | P95 | ≤1m 占比 | 说明 |
|---|---|---|---|---|
| L0 基线（忽略 NLOS） | 5.76m | 19.6m | 6.3% | 噪声+偏置全吃 |
| L1 +3D 垂直分量 | 5.76m | 19.3m | 6.3% | 仍无效 |
| L3 +时序平均（√N 降 σ） | 5.12m | 19.0m | 11.6% | 只削零均值噪声 |
| L4 +地图约束投影 | 4.29m | 15.9m | 13.2% | |
| **L6 +墙体 NLOS 校正** | **0.38m** | 3.48m | **81.1%** | ← 决定性突破 |
| L7 +墙体 NLOS 加权（不校正） | 1.14m | 16.6m | 48.8% | 远差于校正 |
| L8 +校正+加权（hybrid） | 0.49m | 3.02m | 75.0% | |
| **L9 +EKF 跟踪（主走廊）** | **0.29m** | **0.60m** | **100%** | ← 走廊场景达标 |

三个关键洞察：
1. **墙体 NLOS 偏置才是真凶**：校正前 5.76m → 校正后 0.38m，单一杠杆贡献最大。
2. **「减偏置」远强于「加权降权」**（L6 0.38m vs L7 1.14m）：加权只是降低坏观测权重，偏置仍残留在距离里；必须从测距中把墙体等效附加距离**减掉**。
3. **EKF 跟踪把走廊场景推到完美**：时序运动模型 + 残差门控剔除 NLOS 离群，P95 压到 0.6m。

## 3. 时效性分析（亚秒级近实时）

算法侧实测（Python 原型，1F）：

| 模块 | 耗时 | 备注 |
|---|---|---|
| 建墙体索引 + 载信标 | ~195ms | 一次性，可缓存 |
| 单次 NLOS 射线检测（无预筛） | 8.8ms | shapely 几何判定 |
| 原版单帧（遍历 52 信标全做穿墙判定） | 65–414ms | 实现低效，**非算法下限** |
| **优化版单帧**（距离预筛后仅对 ~6–17 个可见信标 ray-cast） | **0.2–4.6ms** | 提速 ~100× |
| solve_gn 解算（15 信标×12 迭代） | 1.9ms | — |
| EKF 单步 | 8.9ms | 39 点轨迹共 0.35s |

**结论**：
- **计算侧**：优化后单帧 <5ms，支持 >200Hz 重算，亚秒级毫无压力（C++/移动端原生可 <1ms）。
- **端到端 = BLE 扫描周期**（真正约束）：iBeacon 广播间隔可配 100ms–1s；iOS 前台扫描回调通常 ~1Hz。典型部署 **1–2Hz（0.5–1s 刷新）= 近实时**；缩短广播间隔 + APP 前台持续扫描 → **5–10Hz（100–200ms）= 严格亚秒级**。
- **架构决胜点（EKF 递推）**：每收到 1 个新 RSSI 即 update+解算，刷新率=扫描率；**切勿「攒 N 个样本平均再解算」**（N=20@1Hz = 20s 滞后，完全不实时）。

## 4. 落地唯一缺口：在线 NLOS 分类器

仿真 L6/L9 用了 **oracle NLOS 判定**——即对每个信标做射线 `线段(真值位置 p_true → 信标)` 判定是否穿墙。这里「作弊」了两处：① 用了真值位置（线上根本没有）；② 判定 100% 准确。

**在线 NLOS 分类器**要做的，是把这两处换成线上可计算的东西——对每个信标判断「手机→信标视线是否被墙挡住」并给出偏置校正量。两条技术路线：

### 4.1 几何驱动（基于地图，推荐主力）
用**当前估计位置** `x̂`（上一帧 EKF 状态）代替真值去 ray-cast。墙体几何已知（`school_building_01_map_v9.geojson` 已是 STRtree），只要 `x̂` 大致对（误差 <3~5m），射线穿墙判定就基本正确。
- 输入：`x̂` + 信标坐标 + 墙体 STRtree
- 输出：每个信标的 `{is_nlos, bias}`
- 复用现有：`load_walls()`（STRtree）、`nlos_info()`、`ranged_bias()`

### 4.2 RSSI 模型驱动（信号启发式）
用已标定的「逐墙衰减路径损耗模型」预测期望 RSSI，与实际 RSSI 比对：
```
d_geo = |x̂ - b|;  rssi_pred = txPower - 10*n*log10(d_geo) - Σ墙衰减
residual = rssi_meas - rssi_pred
if residual < -阈值(如 -8dB): 判为 NLOS
```
无需真值/精确几何，但对多径波动敏感。

### 4.3 混合（落地推荐）
几何给「该不该穿墙」先验 + RSSI 残差交叉验证，两者一致才确认 NLOS。

## 5. 在线分类器实现：EKF 迭代闭合循环

分类器需要位置、定位也需要分类器（鸡生蛋问题），用 EKF 迭代解开：

```
初始化: x̂ = 全 LOS 粗解（冷启动，忽略偏置首解）/ 或地图匹配粗位
循环(每收到新 RSSI 帧):
  1. NLOS 分类: 用当前 x̂ ray-cast 每个可见信标 → {is_nlos, bias}   # 替换 oracle 的真值 ray-cast
  2. 测距校正:   d_corr = d_meas - bias（仅 NLOS 信标）
  3. WLS 解算 / EKF update: 用校正后测距更新 x̂（复用 solve_gn / EKFStep）
  4. 残差门控:   Mahalanobis 距离剔除仍离群的 NLOS 观测（EKF 已有）
  5. x̂ 收敛 → 下一帧用更准的 x̂ 重新分类
```
迭代 2~3 次即收敛。算法骨架（`nlos_info` / `ranged_bias` / `correct_nlos_bias` / `solve_gn` / `EKFStep`）全部已存在，只需新增 `classify_nlos_online(xhat, beacons)` 把 `p_true` 换成 `x̂`，再套一层迭代循环。

**两个落地要害**：
- **Bootstrap 冷启动**：首帧无 `x̂` → 先用「全 LOS 粗解」或「可行走区粒子滤波」（无需指纹，仅用 RSSI 与几何似然投影到走廊）给 ~3m 粗位，后续帧 EKF 残差门控自动剔除误判，2~3s 内收敛。
- **时效性**：距离预筛 + STRtree ray-cast 单帧 <5ms（已验证），分类器本身不成为瓶颈。

## 6. 闭环验证（oracle vs online）

> 本节约用 `trilateration_checker.py` 新增的「在线模式」对比 oracle 上界（L9）与在线分类器（L10）的误差退化。

### 6.1 验证设计
- **静态网格 bootstrap（L6b-online）**：每个网格点用「全 LOS 首解」冷启动，迭代 3 次（用估计位置 ray-cast → 校正 → 解算），对比最终 `x̂` 与真值。
- **轨迹在线（L10）**：沿主走廊轨迹，每步用**上一帧 EKF 估计位置**做 ray-cast 分类（而非真值），校正后 EKF 更新，对比 oracle L9。

### 6.2 实测结果

| 配置 | 中位误差 | P95 | ≤1m 占比 | 说明 |
|---|---|---|---|---|
| L9 oracle（真值 ray-cast，上界） | **0.29m** | 0.60m | **100%** | 性能上界（已知几何） |
| L10 在线分类器（轨迹，上一帧估计 ray-cast） | 1.33m | 6.76m | 35.9% | 轨迹 bootstrap 闭合 |
| L6b-online（网格迭代 bootstrap） | 2.73m | 19.94m | 24.7% | 静态网格冷启动 |

> 数据来源：`debug/trilateration_checker.py` 在线模式（L9/L10/L6b），1F 可行走区 2172 网格点 + 主走廊 39 点轨迹，σ_d=2.0m。

### 6.3 退化根因（诚实结论）

**在线分类器相对 oracle 上界严重退化，未达 ≤1m 目标。**

- **退化幅度**：oracle 轨迹 0.29m/100% → 在线轨迹 1.33m/35.9%；静态网格更差（2.73m/24.7%）。
- **根因不是算法，是分类准确率天花板**：
  - oracle 用「真值位置」ray-cast → 判定 100% 准确。
  - 在线用「估计位置 `x̂`」ray-cast → `x̂` 自身带误差（1–3m），射线方向偏移，把本该判为 NLOS 的误判为 LOS（漏检），或反向误判（虚警）。实测**单帧分类准确率仅 87–91%**。
  - 漏检的 NLOS 偏置残留在测距里 → 解算位置更偏 → 下一帧 `x̂` 更歪 → **误差沿轨迹累积发散**（naive 3 次迭代甚至跑出 36m，已记录为失败模式）。
- **鲁棒策略止血但无法达标**：改用 `shrink 0.7`（NLOS 偏置只减 70%）+ 降权，把轨迹中位压到 1.33m（不发散），但仍距 1m 目标有 33% 余量。
- **核心不等式**：`ray_cast 准确率 = f(x̂ 误差)`，而 `x̂ 误差` 又依赖「上一帧是否排除了 NLOS 偏置」——这是先有鸡还是先有蛋的固有耦合。**只要 bootstrap 粗位误差 >3m，几何闭环就无法稳定收敛到亚米级。**

### 6.4 达标路径（让在线也进 1m 区）

在线版要真正逼近 oracle 上界，必须把 `x̂` 的 bootstrap 误差压到 <1m 再进入几何闭环，三条补强路线（按性价比排序）：

1. **地图匹配粒子滤波 bootstrap（零指纹）**：用 RSSI 几何似然 + 走廊拓扑把粗位压到 <1m，再喂给 ray-cast。不依赖指纹，仅用已知平面几何与信号模型。最直接。
2. **几何 + RSSI 残差双校验（4.3 混合）**：仅当「射线穿墙」与「RSSI 残差 < -8dB」一致才确认 NLOS，把单帧准确率从 91% 顶到 >95%，直接削减累积发散。
3. **EKF 残差门控加严**：Mahalanobis 门限改用自适应（NLOS 越多越收），宁可丢观测不引入偏置。

> 结论：纯 BLE 三点定位的「亚米级」**在已知几何前提下已被证明可达**（oracle 0.29m）；**在线部署要在无真值条件下复现，必须先把粗定位做到 <1m 再进几何闭环**——这是第 5 节迭代设计尚未填平的 gap，优先级高于算法细节打磨。

## 7. 结论与下一步

1. **纯 BLE 三点定位（零指纹）在「已知墙面几何 + NLOS 偏置校正 + EKF 跟踪」下，走廊场景可稳定 ≤1m**（oracle 上界：中位 0.29m、P95 0.60m、100% 点 ≤1m）。**此结论的前提是「墙体几何已知」**——即离线已备好 `school_building_01_map_v9.geojson` 墙体 STRtree。
2. **瓶颈是墙体 NLOS 恒定偏置，不是几何也不是纯噪声**——必须用已知平面图几何消除，而非靠更多信标或平均。
3. **时效性达标**：计算侧 <5ms/帧（>200Hz），端到端取决于 BLE 扫描率（典型 1–2Hz 近实时；100–200ms 广播+前台扫描即严格亚秒），须用 EKF 递推架构。
4. **在线 vs oracle 存在硬性 gap（已闭环验证，见第 6 节）**：在线分类器（用估计位置 ray-cast）轨迹中位 1.33m、仅 35.9% 点 ≤1m，**未达亚米级**。根因是 bootstrap 粗位误差 → 单帧 NLOS 分类准确率天花板 ~87–91% → 误差沿轨迹累积。**因此「亚米级」在真实在线部署下不能直接照搬 oracle 数字**，须先解决粗定位 bootstrap（第 6.4 节三路线）再进几何闭环。
5. **后续**：优先实现「地图匹配粒子滤波 bootstrap + 几何/RSSI 双校验」（第 6.4 节路线 1+2），把在线粗位压到 <1m 后再接入 `classify_nlos_online` → EKF 流水；目标把在线版从中位 1.33m 拉进 1m 区。
