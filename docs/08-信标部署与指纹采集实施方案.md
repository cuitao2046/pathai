# PathAI 室内导航系统 · 信标部署与指纹采集实施方案

> **面向视障人士的室内导航落地文档。** 本文档基于 `gen_beacon_plan.py --mode route` 和 `generate_fingerprint_grid.py --mode route` 生成的部署方案，详细说明如何在初中 1# 教学楼 1~2 层实施 BLE 信标安装与指纹采集。

---

## 一、总体概述

### 1.1 部署范围

| 项 | 内容 |
|---|---|
| 建筑 | 初中学部 1# 教学楼 |
| 楼层 | 1 层（首层）、2 层 |
| 测试路线 1 | 1F 音乐教室（F1-TR-0015）→ 组织办公（F1-TR-0036），140.4m |
| 测试路线 2 | 跨层：教师办公室（F1-TR-0033）→ 历史教室（F2-TR-0018），146.3m（经电梯） |
| 信标数量 | **48 个**（F1: 44, F2: 4） |
| 指纹采集点 | **753 个**（F1: 717, F2: 36） |

### 1.2 关键指标

| 指标 | 值 | 说明 |
|---|---|---|
| 信标间距（走廊） | ≤ 6m | 视障导航连续覆盖 |
| 指纹间距（走廊面） | 1.0m | 2 步内感知偏离并纠正 |
| 指纹走廊覆盖宽度 | ≤ 6m（中心线 ±3m） | 覆盖走廊全截面（左/中/右） |
| 楼梯/电梯口加密 | 3m 半径 / 1m 间距 | 关键过渡点高密度 |
| 安装方式 | 100% 墙面附着 | 墙装/门套装/柱装，0 天花吊杆 |

### 1.3 信标协议参数

| 参数 | 值 |
|---|---|
| UUID | `B9407F30-F5F8-466E-AFF9-25556B57FE6D` |
| 协议 | iBeacon（Apple 标准） |
| 广播间隔 | 门口/交叉口 400ms；楼梯/电梯 300ms |
| 发射功率 | 门口 -10dBm；交叉口 -10dBm；楼梯/电梯 -10dBm（设备档位无 -8/-12，统一取最近档 -10；详见 §1.4 与用户手册） |
| 电池 | CR2477 / CR2450（可更换），预期续航 > 6 个月 |

> **📌 发射功率档位影响说明**：本方案原计划按区域分档（门口 -8 / 交叉口 -10 / 楼梯电梯 -12 dBm），但 RF-B-SR1（及多数同类信标）实际档位仅有 `-28/-20/-10/-5/-3/0/1/2/4/6`，无 -8/-12。统一取最近档 **-10 dBm** 对本项目**影响可忽略**：
> - **覆盖无空洞**：-10 dBm 室内可用距离约 15–20 m，远超 6 m 信标间距 + 3 m 走廊指纹缓冲；
> - **指纹精度无损**：本项目为指纹定位（靠原始 RSSI 指纹库 + 拓扑路由，非三角定位），统一功率反而更一致、更易复现，原分档梯度在指纹法下几乎无收益；
> - **跨层串扰可忽略**：统一 -10 较原 -12 仅强 2 dB，而混凝土楼板衰减 15–30 dB，2 dB 被完全淹没；且跨层归属由拓扑层（`route_rules` 盲模式 / 楼层约束）处理，不依赖 RSSI；
> - **唯一动作**：部署时在 -10 dBm 下实测各信标 1 m 处 RSSI，写回 iBeacon 帧的 `RSSI@1m`（Measured Power）字段，供帧内距离估计使用（指纹法用原始 RSSI，影响很小）。
>
> 仅当改为纯三角定位、或信标间距拉到 15–20 m 以上开阔区时，档位差异才会产生可感知影响。

### 1.4 推荐信标型号与选型

基于学生科研项目、路线验证阶段（48 个信标）、室内视障导航场景，推荐如下型号。

#### 首选：Minew I9（nRF52832 方案）

| 电池 | CR2477（1000mAh，可更换） |
| 续航 | 广播间隔 400ms → 约 14–18 个月（远超半年底线） |
| 配置 | BeaconSET App 蓝牙直连，修改 UUID/Major/Minor/TxPower/Interval |
| 防护 | IP65（室内足够） |
| 安装 | 自带挂孔 + 3M 背胶，支持墙装/门套装 |
| 单价 | 品牌 **¥38–48/个** |

#### 预算版：RF-STAR 信驰达 RF-B-SR1（✅ 已确认，依据用户手册 docs/reference/RF-B-SR1_user_manual.pdf）

| 项 | 详情 |
|---|---|
| 型号 | RF-B-SR1 |
| 芯片 | Silicon Labs EFR32BG22（**BLE 5.2**） |
| 电池 | **CR2477**（可更换，标称 5.9 年 @ 1s/0dBm） |
| 续航 | 按本方案 300–400ms/-10dBm 估算约 1.5–2 年（远超 6 个月底线） |
| 协议 | iBeacon（默认），可切 Eddystone |

| 配置方式 | **手机 App 经 BLE 连接，写 AT 指令 UUID 下发 AT+ 命令**（无需串口线） |
| 尺寸 | 51×51×21 mm，ABS 外壳 |
| 接口 | UART（二次开发/OTA），终端用户走 BLE |
| 单价 | **< ¥30/个** |
| ✅ 采购前验证 | 4 项均已由手册确认：① UUID 可写（AT+BEACON 第5参数 16 字节）；② Major/Minor 可设（AT+BEACON 参数 2/3，2 字节前补零）；③ TxPower/Interval 可设（AT+POWER / AT+ADS，Interval 200ms~10.24s）；④ 8m 外稳定扫描（0dBm 室外>50m） |

#### 不推荐更低价位的原因

| 候选 | 单价 | 不推荐原因 |
|---|---|---|
| nRF51822 白牌 | ¥12–18 | BLE 4.2，不支持 Eddystone，App 兼容性差 |
| CR2032 纽扣型 | ¥15–22 | 电池仅 220mAh，400ms 广播 ≈ 4 个月（临界半年，风险高） |
| 不可配置型 | ¥8–12 | UUID/Major 出厂固化，无法匹配部署方案的编号体系 |

#### 采购建议

- **稳妥路线**：先买 **2–3 个 Minew I9 样品**验证 App 配置流程与扫描稳定性，确认后批量采购。
- **经济路线（✅ 已确认可行）**：RF-B-SR1 已通过手册验证，可替换为批量采购型号：
  1. ✅ 写入 UUID `B9407F30-F5F8-466E-AFF9-25556B57FE6D`（AT+BEACON 第5参数为 16 字节自定义 UUID）
  2. ✅ 分别设置 Major（楼层号）、Minor（beaconId 编号）（AT+BEACON 参数 2/3，2 字节 hex 前补零，如楼层 1→`0001`）
  3. ⚠️ TxPower 档位无 -8/-12，采用最近档 **-10 dBm**；Interval 可设 300/400 ms（AT+POWER / AT+ADS）
  4. ✅ 手机 nRF Connect 在 8 m 外稳定扫描（0dBm 室外>50m 传输距离）

### 2.2 安装方式分布

| 安装方式 | 数量 | 说明 |

| **wall**（墙装） | 39 | 走廊侧墙、楼梯间墙、电梯厅墙、房间外墙 |

| ceiling_pendant（天花吊杆） | **0** | ✅ 无需天花部署 |

### 2.3 安装位置优先级

```
① 柱/门套（snap ≤ 2.5m）─ 最优先，结构柱或门框自然附着面
② 投影到最近墙线段（≤ 8m）─ 走廊侧墙、房间外墙
③ 天花吊杆 ─ 仅最后手段（当前方案 0 个）
```

### 2.4 各安装方式施工要点

#### 墙装（wall）— 39 个

- **安装高度**：地面以上 2.0–2.2m
- **位置要求**：
  - 走廊侧墙、楼梯前室墙、电梯厅侧墙、房间外墙
  - 距阴角（墙角转折处）≥ 0.3m
  - 避免正对消防栓、疏散指示灯、弱电箱正面（可靠近侧缘）
- **固定方式**：3M 建筑双面胶（VHB）直接粘贴，必要时加免钉胶加强，无需打孔
- **特殊要求**：若信标吸附到柱体，安装在**面向走廊一侧**，避免广告牌遮挡

#### 门套装（door_frame）— 9 个

- **安装高度**：门套侧面或门楣下方，2.0–2.2m
- **位置要求**：避开闭门器活动范围，选择门扇打开时不受撞击的一侧
- **固定方式**：优先 3M 建筑双面胶（门套表面不宜打孔），确保粘贴前清洁门套表面

#### 天花吊杆（ceiling_pendant）— 0 个（当前方案无需）

### 2.5 施工前准备清单

### 2.6 安装流程（逐层推进）

```
第 1 步 — 打印图纸与信标位置表
    │  将楼层平面图打印为 A3 尺寸，在每个信标位置标注 ID
    │
第 2 步 — 按楼层从 2 层开始（信标少，先练习）
    │  2F 共 4 个信标 → 1F 共 44 个信标
    │
第 3 步 — 在 BeaconSET App 中预配置信标参数
    │  为每个 beaconId 设置 UUID / Major / Minor / TxPower / Interval
    │  Major = 楼层号, Minor = beaconId 编号
    │
第 4 步 — 现场定位 + 标记
    │  根据 JSON 中的 coordinates / locationDesc / mountType
    │  用卷尺或激光测距仪在墙上标记精确位置（美纹纸+记号笔）
    │
第 5 步 — 安装固定
    │  按 mountType 选择安装方式（墙装贴胶 / 门套贴胶，均免打孔）
    │
第 6 步 — 安装后验证
    │  手机打开蓝牙扫描工具（如 nRF Connect 或 BeaconSET）
    │  确认：UUID 正确 / RSSI 在 1m 处为 -55~-65dBm / 广播间隔符合设定
    │
第 7 步 — 拍照存档
    │  每信标拍 1 张「安装位置整体照」+ 1 张「信标特写」
    │  命名规则：BK-{楼层}-{序号}.jpg
```

| 数据文件 | `fingerprint_grid_routes.json` | — | 精确坐标与采集点 ID |

### 3.4 采集流程

```
第 1 步 — 确认信标已全部部署并广播正常
    │  用手机在走廊两侧各扫一次，确认 48 个信标均可检测
    │
第 2 步 — 在地面标记采集网格点
    │  根据 fingerprint_grid_routes.json 中的 coordinates
    │  用卷尺从墙壁或柱体参考点定位，在地上贴标记贴纸
    │  标记格式：FP-{楼层}-R{序号}（如 FP-1-R001）
    │  按"列"推进：每列（走廊横向）标记完毕再移下一列
    │
第 3 步 — 逐点采集 RSSI 指纹
    │  手机置于标记点正上方，距地面约 1.2m（手持高度）
    │  面向走廊方向（统一朝向，减少人体遮挡偏差）
    │  静止 5 秒，采集期间手机位置不移动
    │  每点记录：扫描到的所有 beaconId + RSSI 值（通常取 3–5 次扫描的均值）
    │
第 4 步 — 采集记录格式
    │  每条指纹记录：
    │  {
    │    "fpId": "FP-1-R001",
    │    "floor": 1,
    │    "coordinates": [-41.065, 22.356],
    │    "timestamp": "2026-08-11T10:30:00+08:00",
    │    "scanDuration_ms": 5000,
    │    "rssi": [
    │      {"beaconId": "BK-01-010", "rssi": -58, "avg": -59.2},
    │      {"beaconId": "BK-01-011", "rssi": -65, "avg": -64.8}
    │    ]
    │  }
    │
第 5 步 — 逐层完成
    │  先完成 2F（36 点，约 15 分钟）作为热身
    │  再完成 1F（717 点，预计 2.5–3 小时）
    │
第 6 步 — 质量抽检
    │  随机选取 10% 的采集点（约 75 个）
    │  换一台手机重新采集，比对 RSSI 偏差
    │  若偏差 > 5dBm 的点超过 20%，检查环境干扰或信标状态
    │
第 7 步 — 数据导出与入库
    │  将采集结果导出为 JSON，放入 result/fingerprint_database.json
    │  导入到定位引擎（后续开发）
```

### 3.5 采集注意事项

| 注意事项 | 说明 |
|---|---|
| **朝向一致性** | 所有采集点统一面朝走廊方向（沿路线前进方向），避免人体朝向差异引入 RSSI 偏差 |
| **环境干扰** | 采集时走廊内避免人员走动；若无法清场，在采集记录中注明该点有人流干扰 |
| **金属干扰** | 电梯口、大型金属门附近 RSSI 波动较大（多径反射），每个点增加扫描时间到 8 秒 |
| **楼梯口加密点** | 7 个 safe 加密点位于楼梯间入口的**走廊侧**（非楼梯间内部），需确认标记位置在可站立区域 |
| **重叠点去重** | 若两个标记点间距 < 0.6m，按 JSON 中的 priority 字段优先保留 safe 点 |
| **设备校准** | 采集前后各选 1 个固定参考点，用同一手机在同一位置测 3 次 RSSI，确认设备未漂移 |

### 3.6 采集工作量估算

| 楼层 | 点数 | 预计时间 | 备注 |
|---|---|---|---|
| 2F | 36 | ≈ 15 min | 先做，熟悉流程 |
| 1F | 717 | ≈ 2.5–3h | 面积大但 1m 间距推进快 |
| **总计** | **753** | **≈ 3h** | 单人操作；双人可减半 |

## 四、施工与采集日程

### 建议分两阶段执行

```
阶段 1：信标安装（半天）
  ├── 上午 — 打印图纸、预配置 48 个信标参数
  ├── 下午 — 2F（4 信标）→ 1F（44 信标）逐层安装
  ├── 傍晚 — 全面扫描验收、拍照存档
```

## 七、常见问题

**Q: 为什么只在两条测试路线上部署，而非全楼？**
A: 这是科研项目的路线验证阶段。先在两条关键路线上验证信标 + 指纹的定位效果，方案成熟后可扩展到全楼（切换为 `--mode full` 即可生成全楼 264 信标 + 1442 指纹方案）。

**Q: 信标电池能用多久？**
A: 当前广播间隔 300–400ms、使用 CR2477 电池：Minew I9 预期 10–16 个月；RF-B-SR1 标称 5.9 年 @ 1s/0dBm，按本方案 300–400ms/-10dBm 估算约 1.5–2 年。均超过学生项目的半年最低要求。

**Q: 指纹采集为什么要统一手持高度 1.2m？**
A: 定位时用户手机也在手持高度；保持采集与定位高度一致可消除高度偏差引入的 RSSI 误差。

**Q: 有信标位置在 JSON 和图纸上与实际现场不对应怎么办？**
A: JSON 中的 `snapDist_m` 字段记录了信标从拓扑节点吸附到墙面/柱体的偏移量。若偏移 > 2m 导致实际位置不可用，记录偏差并在该走廊段两端的现有信标之间取中点补装一个替代信标（标注为现场调整），回写 JSON。

**Q: 设备不支持 -8/-12 dBm 档位、统一用 -10 dBm，对导航效果有何影响？**
A: **可忽略**，理由有四：① 覆盖——-10 dBm 室内可用距离约 15–20 m，远超 6 m 间距 + 3 m 走廊指纹缓冲，不会出死区；② 精度——本项目是指纹定位（原始 RSSI 指纹库 + 拓扑路由），统一功率更一致、更易复现，原分档梯度在指纹法下几乎无收益；③ 跨层——统一 -10 较原 -12 仅强 2 dB，混凝土楼板衰减 15–30 dB 将其淹没，且跨层归属由拓扑层处理而非 RSSI；④ 只需在 -10 dBm 下实测 1 m 处 RSSI 写回 iBeacon 帧的 Measured Power 字段。详见 §1.3 档位影响说明。
