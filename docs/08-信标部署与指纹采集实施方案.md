# PathAI 室内导航系统 · 信标部署与定位实施方案

> **面向视障人士的室内导航落地文档。** 本文档完整体现**两种定位体制**的部署方案：
> ① **指纹定位**（主选，48 信标 + 753 指纹点）；② **三点定位**（备选：沿路线 60 基础/74 精化 + 全楼层 324）。
> 基于 `gen_beacon_plan.py --mode route`、`generate_fingerprint_grid.py --mode route`、`gen_trilateration_plan*.py`、`refine_beacon_placement.py` 生成的部署方案与仿真结果，详细说明如何在初中 1# 教学楼 1~2 层实施 BLE 信标安装、指纹采集与三点定位部署。
>
> 通用部署方法论（选型标准、部署原则、台账、监控、验收）见 [docs/07-信标部署方案.md](07-信标部署方案.md)。

### 1.3 信标协议参数

| 参数 | 值 |
|---|---|
| UUID | `B9407F30-F5F8-466E-AFF9-25556B57FE6D` |
| 协议 | iBeacon（Apple 标准） |
| 广播间隔 | 门口/交叉口 400ms；楼梯/电梯 300ms |
| 发射功率 | **统一 -10 dBm**（设备档位无 -8/-12，取最近档；详见下方档位说明） |
| 电池 | CR2477 / CR2450（可更换），预期续航 > 6 个月 |

> **📌 发射功率档位影响说明**：本方案原计划按区域分档（门口 -8 / 交叉口 -10 / 楼梯电梯 -12 dBm），但 RF-B-SR1（及多数同类信标）实际档位仅有 `-28/-20/-10/-5/-3/0/1/2/4/6`，无 -8/-12。统一取最近档 **-10 dBm** 对本项目**影响可忽略**：
> - **覆盖无空洞**：-10 dBm 室内可用距离约 15–20 m，远超 6 m 信标间距 + 3 m 走廊指纹缓冲；
> - **指纹精度无损**：本项目主选指纹定位（靠原始 RSSI 指纹库 + 拓扑路由），统一功率反而更一致、更易复现；原分档梯度在指纹法下几乎无收益；
> - **三点定位必须同功率**：距离公式直接吃 TxPower，统一 -10 正好满足三点定位的功率一致性硬约束；
> - **跨层串扰可忽略**：统一 -10 较原 -12 仅强 2 dB，而混凝土楼板衰减 15–30 dB，2 dB 被完全淹没；且跨层归属由拓扑层（`route_rules` 盲模式 / 楼层约束）处理，不依赖 RSSI；
> - **唯一动作**：部署时在 -10 dBm 下实测各信标 1 m 处 RSSI，写回 iBeacon 帧的 `RSSI@1m`（Measured Power）字段，供帧内距离估计使用（指纹法用原始 RSSI，影响很小）。
>
> 仅当改为纯三角定位且信标间距拉到 15–20 m 以上开阔区时，档位差异才会产生可感知影响。

## 二、定位体制决策：指纹定位 vs 三点定位

### 2.1 两种体制的原理与部署要求对比

| 维度 | 指纹定位（Fingerprint） | 三点定位（Trilateration） |
|---|---|---|
| 在线原理 | 手机收到 RSSI 向量 → 与离线指纹库匹配最近点 | 手机收到 ≥3 信标 RSSI → 路径损耗模型算距离 → 三边求交得坐标 |
| 离线建库 | **753 点人工采集**（约 3h） | **不需要**（仅信标标定） |
| 覆盖约束 | 每点 **≥1 个信标**可见即可（越多指纹区分度越高） | 每点必须 **≥3 个信标**可见（几何求交最低条件） |
| 功率一致性 | 不敏感（指纹库是实测值） | **必须一致**（统一 -10 dBm，距离公式直接吃 TxPower） |
| 抗多径/穿墙 | **强**（直接存真实信号） | 弱（穿墙使模型距离算错） |
| 在线算力 | 全指纹库向量匹配 | 解三边方程（更轻量） |
| 新区域扩展 | 难（需重新踩点） | 易（补几个信标坐标） |
| 信标硬件成本（预算版） | 48 个 ≈ ¥1,296 | 路线 60/74 个 ≈ ¥1,620/¥1,998；全楼 324 个 ≈ ¥8,748 |

### 2.2 三种候选方案总览

| 方案 | 覆盖范围 | 信标数 | ≥3 覆盖（仿真） | 指纹采集 | 适用场景 |
|---|---|---|---|---|---|
| **A 指纹定位（§三）** | 两条测试路线 | **48** | 不适用（≥1 即可） | 753 点 | 视障精度优先、预算最省 |
| **B 三点定位·沿路线（§四）** | 两条测试路线 | **60 基础 / 74 精化** | F1 92.5%/F2 86.1%（基础 60）；F1 92.6%/F2 86.1%（精化 74） | 0（可选双模 753） | 不采指纹、仅路线定位 |
| **C 三点定位·全楼层（§五）** | 全楼 walkable | **324** | F1 96.6% / F2 98.1% | 0 | 全楼实时坐标、无采集条件 |

### 2.3 ⭐ 推荐结论：优先指纹定位（48），可升级 74 双模

1. **主选指纹定位（48 信标）**：视障复杂室内对抗多径/穿墙最鲁棒，预算最低（预算版整项目 ≈ ¥1,691），符合本项目"路线验证阶段"的定位。
2. **若想"一套硬件、两种定位都能跑"**：部署 **74 精化三点信标**（§四 4.4），在同一组 753 个点上采集指纹即同时得到 ①指纹无线电地图 ②≥3 几何约束——指纹 / 三点 / 混合随意切换，比 48 纯指纹仅多 26 个信标（预算版约 ¥702）。
3. **仅当需要全楼坐标**时才上 324 方案（§五）。

> **注意**：74/60 方案的 ≥3 覆盖为 **F1 92.5% / F2 86.1%**（基础 60，仿真值），并非 100%——残余缺口点位于房间贴墙角等需第三信标穿墙的位置（详见 §4.3），属工程可接受范围，可通过局部微调或对该类点降级为"走廊级覆盖"处理。若对覆盖有更高要求，可加大补点配额重新生成（见 §4.6 再生成命令）。

## 三、方案 A：指纹定位（48 个信标 + 753 个指纹点）

> **体制前提**：指纹定位只需每点 ≥1 信标可见，48 个路线信标即满足；753 个指纹点构成离线无线电地图。

### 3.1 信标安装方案（48 个）

#### 3.1.1 分布概览

| 1F | 3 | 32 | 7 | 2 | **44** |
| 2F | 1 | 2 | 1 | 0 | **4** |

#### 3.1.2 安装方式分布

| 安装方式 | 数量 | 说明 |
|---|---|---|
| **wall**（墙装） | 39 | 走廊侧墙、楼梯间墙、电梯厅墙、房间外墙 |

#### 3.1.3 安装位置优先级

```
① 柱/门套（snap ≤ 2.5m）─ 最优先，结构柱或门框自然附着面
② 投影到最近墙线段（≤ 8m）─ 走廊侧墙、房间外墙
③ 天花吊杆 ─ 仅最后手段（当前方案 0 个）
```

#### 3.1.4 各安装方式施工要点

##### 墙装（wall）— 39 个

- **安装高度**：地面以上 2.0–2.2m
- **位置要求**：
  - 走廊侧墙、楼梯前室墙、电梯厅侧墙、房间外墙
  - 距阴角（墙角转折处）≥ 0.3m
  - 避免正对消防栓、疏散指示灯、弱电箱正面（可靠近侧缘）
- **固定方式**：3M 建筑双面胶（VHB）直接粘贴，必要时加免钉胶加强，无需打孔
- **特殊要求**：若信标吸附到柱体，安装在**面向走廊一侧**，避免广告牌遮挡

##### 门套装（door_frame）— 9 个

- **安装高度**：门套侧面或门楣下方，2.0–2.2m
- **位置要求**：避开闭门器活动范围，选择门扇打开时不受撞击的一侧
- **固定方式**：优先 3M 建筑双面胶（门套表面不宜打孔），确保粘贴前清洁门套表面

#### 3.1.6 安装流程（逐层推进）

```
第 1 步 — 打印图纸与信标位置表
    │  将楼层平面图打印为 A3 尺寸，在每个信标位置标注 ID
    │
第 2 步 — 按楼层从 2 层开始（信标少，先练习）
    │  2F 共 4 个信标 → 1F 共 44 个信标
    │
第 3 步 — 在 BeaconSET App 中预配置信标参数
    │  为每个 beaconId 设置 UUID / Major / Minor / TxPower / Interval
    │  Major = 楼层号, Minor = beaconId 编号
    │
第 4 步 — 现场定位 + 标记
    │  根据 JSON 中的 coordinates / locationDesc / mountType
    │  用卷尺或激光测距仪在墙上标记精确位置（美纹纸+记号笔）
    │
第 5 步 — 安装固定
    │  按 mountType 选择安装方式（墙装贴胶 / 门套贴胶，均免打孔）
    │
第 6 步 — 安装后验证
    │  手机打开蓝牙扫描工具（如 nRF Connect 或 BeaconSET）
    │  确认：UUID 正确 / RSSI 在 1m 处为 -55~-65dBm / 广播间隔符合设定
    │
第 7 步 — 拍照存档
    │  每信标拍 1 张「安装位置整体照」+ 1 张「信标特写」
    │  命名规则：BK-{楼层}-{序号}.jpg
```

> **预算版（RF-B-SR1）逐信标配置**：本方案已依据 `beacon_deployment_plan_routes.json` 生成完整的 AT 指令清单
> `docs/reference/beacon_at_commands_routes.md`（含 48 个信标的 `AT+NAME` / `AT+BEACON` / `AT+POWER=-10` / `AT+ADS=,1,300`）。
> 现场用 **nRF Connect** 连接每个信标，按清单逐条发送（AT 指令大写、不带回车换行、MTU≥128）；`AT+ADS` 模式务必保持 **1（可连接）**。

#### 3.2.4 采集流程

```
第 1 步 — 确认信标已全部部署并广播正常
    │  用手机在走廊两侧各扫一次，确认 48 个信标均可检测
    │
第 2 步 — 在地面标记采集网格点
    │  根据 fingerprint_grid_routes.json 中的 coordinates
    │  用卷尺从墙壁或柱体参考点定位，在地上贴标记贴纸
    │  标记格式：FP-{楼层}-R{序号}（如 FP-1-R001）
    │  按"列"推进：每列（走廊横向）标记完毕再移下一列
    │
第 3 步 — 逐点采集 RSSI 指纹
    │  手机置于标记点正上方，距地面约 1.2m（手持高度）
    │  面向走廊方向（统一朝向，减少人体遮挡偏差）
    │  静止 5 秒，采集期间手机位置不移动
    │  每点记录：扫描到的所有 beaconId + RSSI 值（通常取 3–5 次扫描的均值）
    │
第 4 步 — 采集记录格式
    │  每条指纹记录：
    │  {
    │    "fpId": "FP-1-R001",
    │    "floor": 1,
    │    "coordinates": [-41.065, 22.356],
    │    "timestamp": "2026-08-11T10:30:00+08:00",
    │    "scanDuration_ms": 5000,
    │    "rssi": [
    │      {"beaconId": "BK-01-010", "rssi": -58, "avg": -59.2},
    │      {"beaconId": "BK-01-011", "rssi": -65, "avg": -64.8}
    │    ]
    │  }
    │
第 5 步 — 逐层完成
    │  先完成 2F（36 点，约 15 分钟）作为热身
    │  再完成 1F（717 点，预计 2.5–3 小时）
    │
第 6 步 — 质量抽检
    │  随机选取 10% 的采集点（约 75 个）
    │  换一台手机重新采集，比对 RSSI 偏差
    │  若偏差 > 5dBm 的点超过 20%，检查环境干扰或信标状态
    │
第 7 步 — 数据导出与入库
    │  将采集结果导出为 JSON，放入 result/fingerprint_database.json
    │  导入到定位引擎（后续开发）
```

#### 3.2.5 采集注意事项

| 注意事项 | 说明 |
|---|---|
| **朝向一致性** | 所有采集点统一面朝走廊方向（沿路线前进方向），避免人体朝向差异引入 RSSI 偏差 |
| **环境干扰** | 采集时走廊内避免人员走动；若无法清场，在采集记录中注明该点有人流干扰 |
| **金属干扰** | 电梯口、大型金属门附近 RSSI 波动较大（多径反射），每个点增加扫描时间到 8 秒 |
| **楼梯口加密点** | 7 个 safe 加密点位于楼梯间入口的**走廊侧**（非楼梯间内部），需确认标记位置在可站立区域 |
| **重叠点去重** | 若两个标记点间距 < 0.6m，按 JSON 中的 priority 字段优先保留 safe 点 |
| **设备校准** | 采集前后各选 1 个固定参考点，用同一手机在同一位置测 3 次 RSSI，确认设备未漂移 |

| 楼层 | 点数 | 预计时间 | 备注 |
|---|---|---|---|
| 2F | 36 | ≈ 15 min | 先做，熟悉流程 |
| 1F | 717 | ≈ 2.5–3h | 面积大但 1m 间距推进快 |
| **总计** | **753** | **≈ 3h** | 单人操作；双人可减半 |

## 四、方案 B：三点定位·沿测试路线（60 基础 / 74 精化）

> **体制前提**：三点定位要求每个目标点被 **≥3 个信标**稳定接收。以 48 个路线信标为基础做缺口填补，得到 60 个（基础版）；再做放置质量精化，得到 74 个（精化版，推荐用于正式部署）。

### 4.1 设计思路

- **目标点** = `generate_fingerprint_grid.py --mode route` 生成的 753 个路线点（F1 717 / F2 36），即指纹网格与三点目标完全一致。
- **基础** = `beacon_deployment_plan_routes.json`（48 个路线信标）。
- 对每个目标点做射线穿墙 RSSI 仿真，标记可见信标 <3 的缺口，贪心补点（吸附最近走廊墙，保证 LOS）。
- 全部信标统一 **`txPower=−10 dBm`**、**`broadcastInterval=300 ms`**（功率一致性硬约束）。

### 4.2 部署结构（60 基础）

| 楼层 | 基础路线信标 | 走廊补点 | 合计 |
|---|---|---|---|
| F1 | 44 | 9 | **53** |
| F2 | 4 | 3 | **7** |
| **合计** | **48** | **12** | **60** |

- **基础 48 个**：即 §3.1 路线部署方案中的 `wall` / `door_frame` 信标（2.2 m）。
- **补点 12 个**：`mountType=wall`，贴走廊墙 2.2 m，非天花板；beaconId 前缀 `BK-TR-F1-xxx` / `BK-TR-F2-xxx`。
- 补点候选 15 个，其中 3 个无法放置（`no_wall_within_4.0m` / `snapped_within_1.5m_of_existing`），已在仿真报告中记录。

### 4.3 覆盖仿真结果（基础 60）

物理模型：TxPower −10 dBm、RSSI@1m 参考 −50 dBm、路径损耗指数 n=3.5、穿墙衰减 brick 12 / concrete 15 / partition 8 dB，可见阈值 −85 dBm。目标点为 753 个指纹网格点：

| 楼层 | 填补前 ≥3 覆盖 | 填补后 ≥3 覆盖 | 路径点 |
|---|---|---|---|
| F1 | 83.54% | **92.47%** | 717 |
| F2 | 66.67% | **86.11%** | 36 |

- 填补后 F1 大多数走廊点可见 4~5 个信标（冗余充足），拐角/端点可见 3 个。
- **残余缺口**：F1 有 54 点 <3（其中 14 点仅 1 个、40 点 2 个），F2 有 5 点 <3（均 2 个）——位于房间贴墙角等需第三信标穿墙才能到达的位置，属工程可接受范围；可通过局部微调信标，或对该类点降级为"走廊级覆盖"（用 ≤2 信标 + 拓扑约束定位）。

### 4.4 放置质量精化（74 精化版，推荐）

对 60 基础方案执行 `refine_beacon_placement.py` 的 4 条放置质量规则（R1 走廊两侧分开部署 / R2 避开墙角障碍物 / R3 三角部署非共线 / R4 部署均匀），并**限定补点候选在测试路线 6m 掩码内**（`--route-mask 6.0`，确保不相关空间不部署信标），新增 **14 个质量补点**（全部在 F1），得到 **74 个**精化方案：

| 楼层 | 基础 60 | 质量补点 | 精化 74 |
|---|---|---|---|
| F1 | 53 | +14 | **67** |
| F2 | 7 | 0 | **7** |
| **合计** | **60** | **+14** | **74** |

**合规性验证（7 项规则，`debug/check_beacon_7rules.py`）**：

| 规则 | 结果 |
|---|---|
| [1] 无天花板安装 | 0 ✅ |
| [6] 无悬空/无封闭空间内 | 0 / 0 ✅ |
| [7] 路线 6m 掩码外信标 | **0 / 74 ✅**（修复前为 21 个违规，route-mask 后全部归位） |

> **口径说明**：上述覆盖率为 `refine_beacon_placement.py` 正式射线穿墙口径（穿一堵墙扣满衰减 brick 12 / concrete 15 / partition 8 dB）。调试脚本曾用简化衰减口径得出 F1 98.61% / F2 100%，系未按墙厚折算衰减的乐观估计，**不作为验收依据**；正式口径即本表数值。

## 九、常见问题

**Q: 为什么只在两条测试路线上部署，而非全楼？**
A: 这是科研项目的路线验证阶段。先在两条关键路线上验证信标 + 指纹 / 三点定位效果，方案成熟后可扩展到全楼：指纹法切 `--mode full`（264 信标 + 1442 指纹点），三点法用 §五 的 324 全楼方案。

**Q: 信标电池能用多久？**
A: 当前广播间隔 300–400ms、使用 CR2477 电池：E5领航型预期约 10–18 个月；RF-B-SR1 标称 5.9 年 @ 1s/0dBm，按本方案 300–400ms/-10dBm 估算约 1.5–2 年。均超过学生项目的半年最低要求。

**Q: 指纹采集为什么要统一手持高度 1.2m？**
A: 定位时用户手机也在手持高度；保持采集与定位高度一致可消除高度偏差引入的 RSSI 误差。

**Q: 有信标位置在 JSON 和图纸上与实际现场不对应怎么办？**
A: JSON 中的 `snapDist_m` 字段记录了信标从拓扑节点吸附到墙面/柱体的偏移量。若偏移 > 2m 导致实际位置不可用，记录偏差并在该走廊段两端的现有信标之间取中点补装一个替代信标（标注为现场调整），回写 JSON。

**Q: 设备不支持 -8/-12 dBm 档位、统一用 -10 dBm，对导航效果有何影响？**
A: **可忽略**，理由有四：① 覆盖——-10 dBm 室内可用距离约 15–20 m，远超 6 m 间距 + 3 m 走廊指纹缓冲，不会出死区；② 精度——指纹定位靠原始 RSSI 指纹库 + 拓扑路由，统一功率更一致、更易复现；③ 跨层——统一 -10 较原 -12 仅强 2 dB，混凝土楼板衰减 15–30 dB 将其淹没，且跨层归属由拓扑层处理而非 RSSI；④ 三点定位反而**要求**同功率，统一 -10 正好满足。详见 §1.3。

**Q: 三点定位路线方案（60/74）的 ≥3 覆盖为什么不是 100%？**
A: 仿真结果显示 F1 92.5% / F2 86.1% 的路径点 ≥3 覆盖，残余缺口位于房间贴墙角等需第三信标穿墙才能到达的位置。这类点可通过局部微调信标、或降级为"走廊级覆盖"（≤2 信标 + 拓扑约束）处理。若需更高覆盖，可增大 `--fill-cap` 配额重新生成（见 §4.6），或直接采用 §五 全楼 324 方案（F1 96.6% / F2 98.1%）。

**Q: 能否用三点定位替代指纹定位，省掉采集人工？**
A: 可以，两种量级可选：**沿路线（§四）** 74 精化信标 ≈ ¥2,393，覆盖两条测试路线；**全楼层（§五）** 324 信标 ≈ ¥9,363，覆盖全楼 walkable。代价是信标数量与预算上升（约为指纹方案的 1.5~7 倍），且抗多径/穿墙能力弱于指纹法。若想"省采集又不放弃指纹"，部署 74 双模后在同样 753 点上采指纹即可两体制通吃。

**Q: 74 双模方案比 48 纯指纹方案多花的钱值吗？**
A: 74 精化（预算版整项目 ¥2,393）比 48 指纹（¥1,691）多约 ¥702，换来：① 三点定位硬约束满足（≥3 覆盖）；② 放置质量达标（墙角违例 16.4%、三角退化 5.0%）；③ 一套硬件指纹/三点/混合随意切换，不必在部署时锁定算法。若确定只用指纹且预算极敏感，48 纯指纹即可。

## 附录：E5 蓝牙信标「进口 Nordic 芯片版」vs「国产 BLE 芯片版」核心差异

> 对应 §1.4 两档采购：**E5领航型定位信标（¥45/个）＝ Minew 原厂标准版（Nordic nRF52 芯片）**；**E5 国产芯片版（¥35/个）＝ 渠道特供/降本改版（BK / Telink 等国产芯片）**。
> 先说明：**Minew 原厂标准 E5 标配是 Nordic nRF52 系列（非国产）；市面上国产芯片版本一般是渠道特供/降本改版，常用博通集成 BK、泰凌微 Telink 芯片**。

### 一、核心硬件基线

- **非国产（标准版）：Nordic nRF52810 / nRF52832**（挪威）
- **国产改版：BK3432 / BK3633 / Telink TLSR825x**（国内厂商）

### 二、逐项关键差异（针对 iBeacon 室内定位场景）

#### 1. RF 射频 & RSSI 稳定性【定位项目最关键】

✅ **Nordic nRF 版本（原版）**
1. 接收灵敏度更高（典型 -97~-99dBm）；
2. **RSSI 波动小**，多遮挡、复杂室内（货架、墙体、金属环境）信号一致性更好；
3. 发射功率线性度优秀：-40 ~ +4dBm 档位实际输出和设置值偏差小；
4. 同功率下有效通信距离更稳定，不容易出现"远近跳变"。

⚠️ **国产芯片版本**
1. RSSI 抖动普遍更大；仓库、商超多干扰环境下测距误差上升；
2. 高低温环境下射频指标漂移相对明显；
3. 标称距离参数好看，但复杂环境有效覆盖缩水更明显。

> 结论：**做室内高精度定位（RTLS）、资产盘点优选 Nordic 版本；单纯消息推送、近场营销可以用国产版。**

#### 2. 功耗 & 电池续航（E5 使用 2400mAh 锂电池）

✅ **Nordic 优势**
- 广播休眠电流、单次发射功耗控制成熟；
- 官方固件优化完善，相同广播间隔、发射功率下，**续航普遍长 15%~30%**。
> 举例：同样 1s 广播间隔、0dBm，原版标称续航可达 3~5 年；同参数国产改版通常 2.5~4 年。

⚠️ 国产芯片：芯片理论功耗参数接近，但**原厂固件优化水平差距明显**，实际续航普遍低于 Nordic 方案。

#### 3. 系统兼容性（iOS / Android）

✅ **Nordic 版本**
全球 BLE 生态标杆，对新旧 iOS、安卓机型兼容性几乎无坑；iBeacon/Eddystone 广播兼容性完美，极少出现部分手机搜不到、丢包。

⚠️ **国产芯片版本**
极少数老旧安卓/定制终端存在扫描丢包；极少数 iOS 低版本偶有广播帧识别异常；大批量部署时偶发个别设备失联。

#### 4. 认证（出口项目重点）

✅ **Nordic 原版 E5**
完整拥有 **BQB 蓝牙认证、FCC、CE-RED**，芯片层认证齐全，直接出口欧美无风险。
⚠️ **国产改版 E5**
很多渠道改版**复用外壳，并未重新做全套 BQB/RED 认证**；大批量出口海关存在扣货风险；正规外销项目一定要向供应商索要完整证书核对芯片型号。

#### 5. 功能拓展与固件能力

- Nordic：片上 Flash/RAM 更大，后期需二次开发（增加传感器、Mesh、自定义广播包）空间充足；支持更丰富高级功能。
- 国产芯片版本：大多固件被锁死，仅支持基础 iBeacon/Eddystone，几乎不支持二次开发；部分无法同时并发 iBeacon+Eddystone。

#### 6. 价格与供货

- **Nordic 原版**：成本更高，芯片受海外供应链波动影响；
- **国产芯片改版**：单价低 15%~30%，供货不受海外芯片缺货影响，国内大批量采购交期更稳定。

#### 7. 工作温区可靠性

E5 标称 -30℃ ~ +60℃：
- Nordic 芯片宽温特性经过海量工业项目验证；
- 国产芯片常温表现差距不大；**高低温极限场景（冷库、露天暴晒）故障率相对更高**。

### 三、一张简表汇总

| 对比项 | Nordic nRF52（原版 E5） | 国产 BLE 芯片改版 E5 |
| ---- | ---- | ---- |
| RSSI 稳定性 | 优秀，适合室内定位 | 一般，复杂环境测距误差变大 |
| 实际续航 | 更长 | 同等参数下偏短 |
| 手机兼容性 | 极佳，全机型兼容 | 基本可用，少量机型偶发丢包 |
| 出口认证 | 全套 BQB/FCC/CE（原厂） | 很多改版缺少完整认证 |
| 二次开发 | 支持，资源充足 | 大多固件封闭，无法拓展 |
| 抗干扰/宽温 | 更强 | 常温够用，极限环境偏弱 |
| 采购价格 | 较高 | 便宜 15%~30% |

### 四、选型建议

1. **选 Nordic 原版（非国产芯片）**：室内定位、高精度资产追踪、项目需要出口欧美、要求稳定运行 3 年以上、复杂商超/工厂金属多干扰场景。
2. **可选国产芯片版本**：仅近场推送、客流粗略打卡、室内遮挡少、预算严格受限、只在国内使用、3 年内计划批量轮换设备。

### 五、避坑提醒

很多商家只卖外壳 E5，不会主动说明芯片改版；收货可以两种方式核验：
1. 索要规格书，查看芯片型号；
2. 拆机看丝印：印有 nRF52xx 即为原版；BK / TLSR 开头是国产芯片。

> 现场鉴别（可选）：批量通电连续 72 小时记录 RSSI 波动、丢包率，可快速区分两种版本的实际稳定性差异。
