### 2.2 安装方式分布

| 安装方式 | 数量 | 说明 |
|---|---|---|
| **wall**（墙装） | 39 | 走廊侧墙、楼梯间墙、电梯厅墙、房间外墙 |
| **door_frame**（门套装） | 9 | 门口侧套或门楣下 |
| ceiling_pendant（天花吊杆） | **0** | ✅ 无需天花部署 |

### 2.3 安装位置优先级

```
① 柱/门套（snap ≤ 2.5m）─ 最优先，结构柱或门框自然附着面
② 投影到最近墙线段（≤ 8m）─ 走廊侧墙、房间外墙
③ 天花吊杆 ─ 仅最后手段（当前方案 0 个）
```

### 2.4 各安装方式施工要点

#### 墙装（wall）— 39 个

- **安装高度**：地面以上 2.0–2.2m
- **位置要求**：
  - 走廊侧墙、楼梯前室墙、电梯厅侧墙、房间外墙
  - 距阴角（墙角转折处）≥ 0.3m
  - 避免正对消防栓、疏散指示灯、弱电箱正面（可靠近侧缘）
- **固定方式**：3M 双面胶（临时验证）→ 确认位置后打膨胀胶塞 + 自攻螺钉
- **特殊要求**：若信标吸附到柱体，安装在**面向走廊一侧**，避免广告牌遮挡

#### 门套装（door_frame）— 9 个

- **安装高度**：门套侧面或门楣下方，2.0–2.2m
- **位置要求**：避开闭门器活动范围，选择门扇打开时不受撞击的一侧
- **固定方式**：优先 3M 建筑双面胶（门套表面不宜打孔），确保粘贴前清洁门套表面

#### 天花吊杆（ceiling_pendant）— 0 个（当前方案无需）

### 2.6 安装流程（逐层推进）

```
第 1 步 — 打印图纸与信标位置表
    │  将楼层平面图打印为 A3 尺寸，在每个信标位置标注 ID
    │
第 2 步 — 按楼层从 2 层开始（信标少，先练习）
    │  2F 共 4 个信标 → 1F 共 44 个信标
    │
第 3 步 — 在 BeaconSET App 中预配置信标参数
    │  为每个 beaconId 设置 UUID / Major / Minor / TxPower / Interval
    │  Major = 楼层号, Minor = beaconId 编号
    │
第 4 步 — 现场定位 + 标记
    │  根据 JSON 中的 coordinates / locationDesc / mountType
    │  用卷尺或激光测距仪在墙上标记精确位置（美纹纸+记号笔）
    │
第 5 步 — 安装固定
    │  按 mountType 选择安装方式（墙装打孔 / 门套贴胶）
    │
第 6 步 — 安装后验证
    │  手机打开蓝牙扫描工具（如 nRF Connect 或 BeaconSET）
    │  确认：UUID 正确 / RSSI 在 1m 处为 -55~-65dBm / 广播间隔符合设定
    │
第 7 步 — 拍照存档
    │  每信标拍 1 张「安装位置全景」+ 1 张「信标特写」
    │  命名规则：BK-{楼层}-{序号}.jpg
```

## 三、指纹采集方案（753 个点）

### 3.1 分布概览

| 楼层 | 普通点（走廊面） | 安全加密点（楼梯/电梯口） | 合计 |
|---|---|---|---|
| 1F | 710 | 7 | **717** |
| 2F | 29 | 7 | **36** |

### 3.2 采集参数

| 参数 | 值 | 说明 |
|---|---|---|
| 走廊面间距 | 1.0m | 视障导航标准：用户走 2 步跨越 1 个指纹点 |
| 楼梯/电梯口加密间距 | 1.0m | 关键过渡点高密度 |
| 加密半径 | 3.0m | 以楼梯/电梯节点为圆心的可通行区域 |
| 去重最小间距 | 0.6m | 小于此距离的点合并 |

### 3.3 采集前准备

| 类别 | 物品 | 数量 | 用途 |
|---|---|---|---|
| 采集工具 | 智能手机（Android/iOS）+ BLE 扫描 App | 1–2 部 | 采集 BLE RSSI 指纹 |
| 扫描 App | nRF Connect（Nordic）或自研采集 App | 1 | 支持 RSSI 批量采集和导出 |
| 标记工具 | 地面标记贴纸 / 粉笔 / 美纹纸 | 若干 | 在地面标记采集点位置 |
| 测量工具 | 5m 卷尺 | 1 | 辅助定位网格点 |
| 图纸 | 楼层平面图 + 指纹采集点地图 | 各 2 份 | 现场定位依据 |
| 记录表单 | 采集记录 checklist（纸质或电子） | 各 1 | 记录每个点的采集状态 |
| 信标 | **确认 48 个信标全部安装到位并正常广播** | — | 指纹采集前必须信标已部署 |
| 数据文件 | `fingerprint_grid_routes.json` | — | 精确坐标与采集点 ID |

### 3.4 采集流程

```
第 1 步 — 确认信标已全部部署并广播正常
    │  用手机在走廊两侧各扫一次，确认 48 个信标均可检测
    │
第 2 步 — 在地面标记采集网格点
    │  根据 fingerprint_grid_routes.json 中的 coordinates
    │  用卷尺从墙壁或柱体参考点定位，在地上贴标记贴纸
    │  标记格式：FP-{楼层}-R{序号}（如 FP-1-R001）
    │  按"列"推进：每列（走廊横向）标记完毕再移下一列
    │
第 3 步 — 逐点采集 RSSI 指纹
    │  手机置于标记点正上方，距地面约 1.2m（手持高度）
    │  面向走廊方向（统一朝向，减少人体遮挡偏差）
    │  静止 5 秒，采集期间手机位置不移动
    │  每点记录：扫描到的所有 beaconId + RSSI 值（通常取 3–5 次扫描的均值）
    │
第 4 步 — 采集记录格式
    │  每条指纹记录：
    │  {
    │    "fpId": "FP-1-R001",
    │    "floor": 1,
    │    "coordinates": [-41.065, 22.356],
    │    "timestamp": "2026-08-11T10:30:00+08:00",
    │    "scanDuration_ms": 5000,
    │    "rssi": [
    │      {"beaconId": "BK-01-010", "rssi": -58, "avg": -59.2},
    │      {"beaconId": "BK-01-011", "rssi": -65, "avg": -64.8}
    │    ]
    │  }
    │
第 5 步 — 逐层完成
    │  先完成 2F（36 点，约 15 分钟）作为热身
    │  再完成 1F（717 点，预计 2.5–3 小时）
    │
第 6 步 — 质量抽检
    │  随机选取 10% 的采集点（约 75 个）
    │  换一台手机重新采集，比对 RSSI 偏差
    │  若偏差 > 5dBm 的点超过 20%，检查环境干扰或信标状态
    │
第 7 步 — 数据导出与入库
    │  将采集结果导出为 JSON，放入 result/fingerprint_database.json
    │  导入到定位引擎（后续开发）
```

### 3.5 采集注意事项

| 注意事项 | 说明 |
|---|---|
| **朝向一致性** | 所有采集点统一面朝走廊方向（沿路线前进方向），避免人体朝向差异引入 RSSI 偏差 |
| **环境干扰** | 采集时走廊内避免人员走动；若无法清场，在采集记录中注明该点有人流干扰 |
| **金属干扰** | 电梯口、大型金属门附近 RSSI 波动较大（多径反射），每个点增加扫描时间到 8 秒 |
| **楼梯口加密点** | 7 个 safe 加密点位于楼梯间入口的**走廊侧**（非楼梯间内部），需确认标记位置在可站立区域 |
| **重叠点去重** | 若两个标记点间距 < 0.6m，按 JSON 中的 priority 字段优先保留 safe 点 |
| **设备校准** | 采集前后各选 1 个固定参考点，用同一手机在同一位置测 3 次 RSSI，确认设备未漂移 |

### 3.6 采集工作量估算

| 楼层 | 点数 | 预计时间 | 备注 |
|---|---|---|---|
| 2F | 36 | ≈ 15 min | 先做，熟悉流程 |
| 1F | 717 | ≈ 2.5–3h | 面积大但 1m 间距推进快 |
| **总计** | **753** | **≈ 3h** | 单人操作；双人可减半 |

## 六、常见问题

**Q: 为什么只在两条测试路线上部署，而非全楼？**
A: 这是科研项目的路线验证阶段。先在两条关键路线上验证信标 + 指纹的定位效果，方案成熟后可扩展到全楼（切换为 `--mode full` 即可生成全楼 264 信标 + 1442 指纹方案）。

**Q: 信标电池能用多久？**
A: 当前广播间隔 300–400ms、使用 CR2477 电池预期续航 10–16 个月，超过学生项目的半年最低要求。

**Q: 指纹采集为什么要统一手持高度 1.2m？**
A: 定位时用户手机也在手持高度；保持采集与定位高度一致可消除高度偏差引入的 RSSI 误差。

**Q: 有信标位置在 JSON 和图纸上与实际现场不对应怎么办？**
A: JSON 中的 `snapDist_m` 字段记录了信标从拓扑节点吸附到墙面/柱体的偏移量。若偏移 > 2m 导致实际位置不可用，记录偏差并在该走廊段两端的现有信标之间取中点补装一个替代信标（标注为现场调整），回写 JSON。
