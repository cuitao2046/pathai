## 4. 各脚本详解

### 4.1 解析与质检

#### `parsing/parse_cad_pdf.py` —— CAD PDF → GeoJSON 主解析器
- **功能**：PyMuPDF 按 OCG 图层提取矢量 → 坐标标定（`SCALE=0.0529 m/pt`，原点 `(2019.1,1154.8)pt`，Y 翻转，`set_rotation(0)` 处理 270° 旋转）→ 墙体矢量化 → 房间识别（OpenCV 栅格化+形态学+分水岭+标签探测）→ 门洞识别（window 摆弧 / DOOR_FIRE / DK 笔画）→ 门归属链 → 输出 v9 GeoJSON。
- **输出**：`result/school_building_01_map_v9.geojson`
- **用法**：
  ```bash
  python src/parsing/parse_cad_pdf.py [--use-skeleton | --no-skeleton] [--no-manual-skeleton]
  ```
  - `--use-skeleton` / `--no-skeleton`：强制使用/跳过骨架模式。
  - `--no-manual-skeleton`：忽略 `result/skeleton_manual_parsed.json`，强制自动骨架。
- **注意**：图层优先逻辑自动检测手工骨架；门不合并（同一物理开口仅一扇门）。

#### `qa/validate_geojson.py` —— 拓扑质量校验（T12）
- **功能**：校验 GeoJSON 拓扑完整性。核心指标「无门封闭房间数 = 0」；门节点 TD 须有 `TR↔TD` 边；孤儿门为信息项。
- **用法**：
  ```bash
  python src/qa/validate_geojson.py [geojson路径] [--verbose]
  ```
  - 位置参数默认 `result/school_building_01_map_v9.geojson`。

---

### 4.2 渲染

#### `rendering/render_interactive.py` —— 交互式网页楼层渲染
- **功能**：读取 v9 GeoJSON 生成自包含交互 HTML。支持图层开关、缩放/平移（触控板双指）、hover/点击详情、楼层跳转、拓扑联动高亮、导出选中图层 SVG、浏览器写回 GeoJSON、门节点编号 `TD-xxxx`、**前端 Dijkstra 路由**、以及**三点定位覆盖图层**（按指纹点可见信标数着色：≥3 绿 / 2 黄 / 1 橙 / 0 红，随 `--beacons` 动态计算）。
- **输出**：`result/floor_layout_v9_interactive.html`（默认）；路线版 `floor_layout_v9_interactive_routes.html`
- **用法**：
  ```bash
  python src/rendering/render_interactive.py \
      [--geo  result/school_building_01_map_v9.geojson] \
      [--beacons result/beacon_deployment_plan.json] \
      [--fingerprint result/fingerprint_grid.json] \
      [--out  result/floor_layout_v9_interactive.html]
  ```
  - 路线版典型：`--fingerprint result/fingerprint_grid_routes.json --beacons result/beacon_deployment_plan_trilateration_routes.json --out result/floor_layout_v9_interactive_routes.html`
  - 覆盖图层需 `shapely`（STRtree 加速墙体射线查询）。

#### `rendering/render_map.py` —— 静态 PNG 渲染
- **功能**：GeoJSON → 逐楼层静态 PNG。
- **用法**：
  ```bash
  python src/rendering/render_map.py [geojson路径] [--topology]
  ```
  - 位置参数为 GeoJSON 路径（默认 v9），PNG 输出到该 GeoJSON 同目录。
  - `--topology`：叠加拓扑节点/边。

---

### 4.3 拓扑与骨架

#### `topology/topology.py` —— 室内导航拓扑图构建
- **功能**：按 `docs/03-地图构建指南.md` 第五章规范构建导航拓扑。门节点（TD）生成规则 v9：同物理开口按两次合并为一个 TD，仅当归属 ≥1 封闭房间才建 TD（纯走廊通行门不建 TD）。
- **用法**：作为模块被 `parse_cad_pdf.py` 调用；`build_floor_topology` 为手动骨架不可用时的回退路径。
- **注意**：改拓扑须与 `skeleton/pipeline.py` 的 `build_skeleton_topology` 两处同步。

#### `topology/route_rules.py` —— 导航路线规则
- **功能**：后端导航规则模块（与前端 Dijkstra 同步）。门惩罚 `DOOR_PENALTY={swing:0, fire:0.5, opening:1}`；同层禁 facility 中转 / 门优先级 swing>fire>opening / room↔room 经门连公共空间 / 盲模式禁楼梯跨层；`shortest_path` 三层回退（最佳门→所有门→穿墙边）；`validate_wall_crossing` 穿墙校验。

#### `skeleton/pipeline.py` —— 骨架管线总装
- **功能**：Walkable → 中轴 → 剪枝 → 矢量化 → Junction/门投影 → 拓扑节点边。**手工骨架优先**：`build_skeleton_topology(manual_skeleton=...)` 有 `result/skeleton_manual_parsed.json` 时用其 TI/TI-TI/骨架线（跳过中轴提取），TR/TD/TF/TEN 仍自动挂接；F2 孤岛由软桥补边保 100% 连通。

#### `skeleton/medial_axis.py` / `skeleton_vectorize.py` / `junction_detector.py` / `door_projector.py`
- `medial_axis.py`（T3+T5）：Walkable Polygon → 栅格化中轴 + 悬挂分支剪枝。
- `skeleton_vectorize.py`（T4）：骨架像素 → NetworkX 图 + 矢量化 LineString。
- `junction_detector.py`（T6）：骨架交叉口（degree≥3）与端点检测，degree=2 路径简化。
- `door_projector.py`（T7）：门中心正交投影到骨架段（STRtree 加速）。
- 均为 `pipeline.py` 的子步骤，通常经管线总装调用，无需单独运行。

### 4.4 指纹与信标

#### `tools/generate_fingerprint_grid.py` —— 指纹采集网格生成
- **功能**：按 walkable 区域生成指纹采样点。
- **用法**：
  ```bash
  python src/tools/generate_fingerprint_grid.py [geo] \
      [--mode full|route] [--routes 路线JSON] [--spacing 1.0] [--out 输出JSON]
  ```
  - `--mode full`（默认）→ `result/fingerprint_grid.json`；`--mode route --routes <路线>` → `result/fingerprint_grid_routes.json`。
  - `--spacing`：路线模式采样间距（默认 1.0 m）。

#### `tools/gen_beacon_plan.py` —— 信标部署方案生成器
- **功能**：依据 `docs/07-信标部署方案.md`，从 v9 GeoJSON 生成可施工/可运维 ROI 蓝牙信标部署方案。
- **用法**：
  ```bash
  python src/tools/gen_beacon_plan.py \
      [--geo result/school_building_01_map_v9.geojson] \
      [--out 输出JSON] [--mode full|route] [--routes 路线JSON] [--route-spacing 6.0]
  ```
  - `--mode full` → `beacon_deployment_plan.json`；`--mode route --routes <路线>` → `beacon_deployment_plan_routes.json`。
  - `--route-spacing`：路线布点间距（默认 6.0 m）。

#### `tools/gen_beacon_at_commands.py` —— 信标 AT 命令清单
- **功能**：由部署计划 JSON 生成 RF-B-SR1 信标 AT 配置命令清单（markdown）。
- **用法**：
  ```bash
  python src/tools/gen_beacon_at_commands.py \
      [--src result/beacon_deployment_plan.json] \
      [--out 输出md] [--title-tag "路线部署 · 48 个"]
  ```
  - 已生成：`docs/reference/beacon_at_commands_trilateration.md`（324）、`beacon_at_commands_trilateration_routes.md`（66）、`beacon_at_commands_routes.md`（48）。
  - **注意**：清单中 RSSI@1m 为占位值 `C5(-59dBm)`，需现场实测替换。

#### `tools/analyze_trilateration_coverage.py` —— 三点定位覆盖率评估
- **功能**：用射线穿墙无线模型（RSSI_ref@1m=-50、路径损耗 n=3.5、墙衰减 brick12/concrete15/partition8/glass6、可见阈值 `VISIBLE=-85dBm`、信标偏移 0.25m、D_MAX=11m）评估全楼层信标方案对三点定位的逐点覆盖。
- **用法**：
  ```bash
  python src/tools/analyze_trilateration_coverage.py [--grid 1.0] [--threshold -85]
  ```
  - 输出聚合统计：`result/trilateration_coverage_analysis.json`（各层样本数、≥3 信标可见占比、直方图）。

#### `tools/gen_trilateration_plan.py` —— 全楼三点定位信标方案
- **功能**：在 `beacon_deployment_plan.json` 基础上用贪心补点达到三点定位覆盖，生成全楼 324 信标方案。
- **用法**：
  ```bash
  python src/tools/gen_trilateration_plan.py [--grid 1.0] [--fill-cap 120]
  ```
  - 输出：`result/beacon_deployment_plan_trilateration.json` + `result/trilateration_coverage_analysis.json`。

#### `tools/gen_trilateration_plan_routes.py` —— 路线三点定位信标方案
- **功能**：仅针对选定导航测试路径的三点定位信标部署（66 信标，100% 覆盖）。
- **用法**：
  ```bash
  python src/tools/gen_trilateration_plan_routes.py [--grid 1.0] [--fill-cap 120]
  ```
  - 输出：`result/beacon_deployment_plan_trilateration_routes.json` + `result/trilateration_coverage_routes_analysis.json`（基于 `fingerprint_grid_routes.json`）。

#### `tools/gen_trilateration_map.py` / `gen_trilateration_map_routes.py` —— 覆盖热力图
- **功能**：渲染三点定位覆盖热力图（PNG）。
- **用法**：
  ```bash
  python src/tools/gen_trilateration_map.py [--grid 1.5]        # 全楼 → trilateration_coverage_map_F{fl}.png
  python src/tools/gen_trilateration_map_routes.py [--grid 1.0] # 路线 → trilateration_coverage_routes_map_F{fl}.png
  ```

  - 分别读取 `beacon_deployment_plan_trilateration.json` / `beacon_deployment_plan_trilateration_routes.json` 与对应指纹网格。

## 5. 典型工作流

**A. 从 PDF 到可交互地图（端到端）**

## 6. 命名与协作约定

- **分支铁律（铁律 0）**：禁止直接在 `master` 上开发；所有功能/优化/bugfix 一律从最新 `master` 切**无斜杠名**新分支（如 `feature-xxx` / `fix-xxx`），合入后再删分支。禁止 `--force` 推送。
- **单需求单分支（铁律 0b）**：一个分支只含一个需求的改动。
- **目录纪律**：正式脚本仅在 `src/`（按 `parsing/qa/rendering/skeleton/topology/tools` 子目录）；调试脚本放 `debug/`；根目录不留 `.py`。
- **手工骨架入库**：`result/skeleton_manual_parsed.json` 属代码，每次重生成必须 `git add`+提交；严禁 `git checkout` 回退。
- **推送凭据**：远端用 SSH 格式 `git@github-cuitao:cuitao2046/pathai.git`（重克隆后需 `git remote set-url`）；沙箱无凭据时由用户终端执行 push，但需明确告知「待 push」。
