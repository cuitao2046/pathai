# PathAI 工具与脚本使用手册

> 适用范围：PathAI 初中学部 1# 教学楼 1~2 层室内导航项目。
> 本文档汇总 `src/` 下全部正式模块（**50 个，不含 `__init__.py`**；其中 `tools/` 26 个）的功能、命令行用法与产物路径，供开发与复现参考。
> 关联设计文档见 `docs/`：产品与架构 01~02、地图与算法 03~05、交互 06、部署 07~08、识别方案 09~11、质量与优化 13/16~19、建图方案 20、汇报与预算 14/15/21；信标手册见 `docs/reference/RF-B-SR1_user_manual.pdf`。

## 1. 运行环境

- **推荐解释器**：托管版 Python venv（依赖已装入该隔离环境，请勿全局 `pip install` 污染用户环境）
  `C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe`
- **核心依赖**：`PyMuPDF`(fitz)、`opencv-python`、`shapely`、`networkx`、`scikit-image`、`matplotlib`、`numpy`、`Pillow`
- **约定**：所有脚本路径基于项目根目录 `__file__` 推导，请勿硬编码绝对路径；运行示例中的 `python` 均指上述托管解释器。
- **产物性质**：
  - `src/`、`tests/`、`docs/*.md` → 随仓库提交（代码/文档）。
  - `result/` → **默认 `.gitignore`，仅白名单入库**。当前白名单：`*.geojson`、`ble_deployment.json`、`fingerprint_grid.json`、`fingerprint_grid_routes.json`、`fingerprint_valid_region.json`、`fingerprint_coverage_compare.html|json`、`open_column_wraps.json`、`skeleton_manual_parsed.json`、`floor_layout_v9_interactive.html`。其余（热力图 PNG、临时分析 JSON）为可复现产物，不入库。

   ├─ 指纹网格   src/tools/generate_fingerprint_grid.py

## 4. 各脚本详解

### 4.1 解析与质检

#### `parsing/parse_cad_pdf.py` —— CAD PDF → GeoJSON 主解析器
- **功能**：PyMuPDF 按 OCG 图层提取矢量 → 坐标标定（`SCALE=0.0529 m/pt`，原点 `(2019.1,1154.8)pt`，Y 翻转，`set_rotation(0)` 处理 270° 旋转）→ 墙体矢量化 → 房间识别（OpenCV 栅格化+形态学+分水岭+标签探测）→ 门洞识别（window 摆弧 / DOOR_FIRE / DK 笔画）→ 门归属链 → 输出 v9 GeoJSON。
- **输出**：`result/school_building_01_map_v9.geojson`
- **用法**：
  ```bash
  python src/parsing/parse_cad_pdf.py [--use-skeleton | --no-skeleton] [--no-manual-skeleton]
  ```
  - `--use-skeleton` / `--no-skeleton`：强制使用/跳过骨架模式。
  - `--no-manual-skeleton`：忽略 `result/skeleton_manual_parsed.json`，强制自动骨架。
- **注意**：图层优先逻辑自动检测手工骨架；门不合并（同一物理开口仅一扇门）。

#### `qa/validate_geojson.py` —— 拓扑质量校验（T12）
- **功能**：校验 GeoJSON 拓扑完整性。核心指标「无门封闭房间数 = 0」；门节点 TD 须有 `TR↔TD` 边；孤儿门为信息项。
- **用法**：
  ```bash
  python src/qa/validate_geojson.py [geojson路径] [--verbose]
  ```
  - 位置参数默认 `result/school_building_01_map_v9.geojson`。

---

### 4.2 渲染

#### `rendering/render_interactive.py` —— 交互式网页楼层渲染
- **功能**：读取 v9 GeoJSON 生成自包含交互 HTML。支持图层开关、缩放/平移（触控板双指）、hover/点击详情、楼层跳转、拓扑联动高亮、导出选中图层 SVG、浏览器写回 GeoJSON、门节点编号 `TD-xxxx`、**前端 Dijkstra 路由**（规则常量经 `build_path_rules_js()` 注入，JS 内不嵌常量）、以及**三点定位覆盖图层**（按指纹点可见信标数着色：≥3 绿 / 2 黄 / 1 橙 / 0 红，随 `--beacons` 动态计算）。亦支持**部署模式**：拖拽/点选信标位置并导出 `ble_deployment.json`。
- **输出**：`result/floor_layout_v9_interactive.html`（默认）
- **用法**：
  ```bash
  python src/rendering/render_interactive.py \
      [--geo  result/school_building_01_map_v9.geojson] \
      [--beacons result/ble_deployment.json] \
      [--fingerprint result/fingerprint_grid.json] \
      [--out  result/floor_layout_v9_interactive.html]
  ```
  - 路线网格版：`--fingerprint result/fingerprint_grid_routes.json --beacons result/ble_deployment.json --out result/floor_layout_v9_interactive_routes.html`
  - 覆盖图层需 `shapely`（STRtree 加速墙体射线查询）。

#### `rendering/render_map.py` —— 静态 PNG 渲染
- **功能**：GeoJSON → 逐楼层静态 PNG。
- **用法**：
  ```bash
  python src/rendering/render_map.py [geojson路径] [--topology]
  ```
  - 位置参数为 GeoJSON 路径（默认 v9），PNG 输出到该 GeoJSON 同目录。
  - `--topology`：叠加拓扑节点/边。

---

### 4.3 拓扑与骨架

#### `topology/topology.py` —— 室内导航拓扑图构建
- **功能**：按 `docs/03-地图构建指南.md` 第五章规范构建导航拓扑。门节点（TD）生成规则 v9：同物理开口按两次合并为一个 TD，仅当归属 ≥1 封闭房间才建 TD（纯走廊通行门不建 TD）。
- **用法**：作为模块被 `parse_cad_pdf.py` 调用；`build_floor_topology` 为手动骨架不可用时的**回退路径**。
- **注意**：**实际生产拓扑由 `skeleton/pipeline.py` 的 `build_skeleton_topology` 生成**；改拓扑须两处同步。

#### `topology/route_rules.py` —— 导航路线规则
- **功能**：后端导航规则模块（与前端 Dijkstra 同步，唯一来源为 `common/constants.py`）。门惩罚 `DOOR_PENALTY={swing:0, fire:0.5, opening:1}`、未知门类型兜底 `DOOR_DEFAULT_PENALTY=9.0`；同层禁 facility 中转 / 门优先级 swing>fire>opening / room↔room 经门连公共空间 / 盲模式禁楼梯跨层；`shortest_path` 三层回退（最佳门→所有门→穿墙边）；`validate_wall_crossing` 穿墙校验。

#### `skeleton/pipeline.py` —— 骨架管线总装
- **功能**：Walkable → 中轴 → 剪枝 → 矢量化 → Junction/门投影 → 拓扑节点边。**手工骨架优先**：`build_skeleton_topology(manual_skeleton=...)` 有 `result/skeleton_manual_parsed.json` 时用其 TI/TI-TI/骨架线（跳过中轴提取），TR/TD/TF/TEN 仍自动挂接；F2 孤岛由软桥补边保 100% 连通。
- **注意**：**该函数是当前导航拓扑的实际来源**（`topology.build_floor_topology` 仅回退），见 `docs/20`。

#### `skeleton/medial_axis.py` / `skeleton_vectorize.py` / `junction_detector.py` / `door_projector.py`
- `medial_axis.py`（T3+T5）：Walkable Polygon → 栅格化中轴 + 悬挂分支剪枝。
- `skeleton_vectorize.py`（T4）：骨架像素 → NetworkX 图 + 矢量化 LineString。
- `junction_detector.py`（T6）：骨架交叉口（degree≥3）与端点检测，degree=2 路径简化。
- `door_projector.py`（T7）：门中心正交投影到骨架段（STRtree 加速）。
- 均为 `pipeline.py` 的子步骤，通常经管线总装调用，无需单独运行。

### 4.4 指纹与信标

#### `tools/generate_fingerprint_grid.py` —— 指纹采集网格生成
- **功能**：按 walkable 区域生成指纹采样点。
- **用法**：
  ```bash
  python src/tools/generate_fingerprint_grid.py [geo] \
      [--mode full|route] [--routes 路线JSON] [--spacing 1.0] [--out 输出JSON]
  ```
  - `--mode full`（默认）→ `result/fingerprint_grid.json`（1434 点）；`--mode route --routes <路线>` → `result/fingerprint_grid_routes.json`（647 点）。
  - `--spacing`：路线模式采样间距（默认 1.0 m）。

#### `tools/gen_beacon_plan.py` —— 信标部署方案生成器（历史方案）
- **功能**：依据 `docs/07-信标部署方案.md`，从 v9 GeoJSON 生成可施工/可运维 ROI 蓝牙信标部署方案。
- **用法**：
  ```bash
  python src/tools/gen_beacon_plan.py \
      [--geo result/school_building_01_map_v9.geojson] \
      [--out 输出JSON] [--mode full|route] [--routes 路线JSON] [--route-spacing 6.0]
  ```
  - 产出的 `beacon_deployment_plan*.json` **当前不在仓库**（现行台账为 `ble_deployment.json`）。

#### `tools/gen_beacon_at_commands.py` —— 信标 AT 命令清单
- **功能**：由部署计划 JSON 生成 RF-B-SR1 信标 AT 配置命令清单（markdown）。
- **用法**：
  ```bash
  python src/tools/gen_beacon_at_commands.py \
      [--src result/ble_deployment.json] \
      [--out 输出md] [--title-tag "路线部署 · 61 个"]
  ```
  - 已生成（**基于历史方案**）：`docs/reference/beacon_at_commands_trilateration.md`（324）、`beacon_at_commands_trilateration_routes.md`（66）、`beacon_at_commands_routes.md`（48）。
  - **注意**：清单中 RSSI@1m 为占位值 `C5(-59dBm)`，需现场实测替换。基于现行 61 枚台账的清单尚未生成。

#### `tools/validate_beacon_deployment.py` —— 信标台账合规校验
- **功能**：对 `result/ble_deployment.json` 执行 4 条规则：
  - **R1 [ERROR]** `sourceNodeId` 非空 → `coords↔sourceNodeId` 距离 > `T_SRC_DRIFT`（3.0m，与渲染图吸附阈值一致）；
  - **R4 [WARN ]** 距最近楼梯 ≤ 6.0m 或命中 `staircase`/`stair_lobby` 房间，却未声明楼梯关键词；
  - **R5 [ERROR]** 缺失 `beaconId`/`coordinates`/`floor`；
  - **R6 [ERROR]** 信标坐标 3.0m 内的房间未全部录入 `adjacentRooms`。
  > 原 R2（planned 脱节）/ R3（人工信标同步）已随 `plannedCoordinates`/`snapDist_m` 字段废弃而删除。
- **用法**：
  ```bash
  python src/tools/validate_beacon_deployment.py
  ```
- **现行结果**（2026-09-21）：**ERROR=0 / WARN=13**（13 条全部为 R4 楼梯语义缺失）。

#### `tools/inject_adjacent_rooms.py` —— 注入相邻房间
- **功能**：为每枚信标计算 3m 半径内几何命中的房间并写入 `adjacentRooms`（R6 的数据来源）。

#### `tools/fix_beacon_coords.py` —— 信标坐标修正
- **功能**：修正信标 `coordinates` 与挂靠节点/规划坐标的脱节（`docs/17` 问题一的数据修复工具）。

#### `tools/analyze_trilateration_coverage.py` —— 三点定位覆盖率评估
- **功能**：用射线穿墙无线模型（RSSI_ref@1m=-50、路径损耗 n=3.5、墙衰减 brick12/concrete15/partition8/glass6、可见阈值 `VISIBLE=-85dBm`、信标偏移 0.25m、D_MAX=11m）评估信标方案对三点定位的逐点覆盖。
- **用法**：
  ```bash
  python src/tools/analyze_trilateration_coverage.py [--grid 1.0] [--threshold -85]
  ```

#### `tools/gen_trilateration_plan.py` / `gen_trilateration_plan_routes.py` —— 三点定位信标方案（历史方案）
- **功能**：在 `beacon_deployment_plan*.json` 基础上用贪心补点达到三点定位覆盖（全楼 324 / 路线 66 信标）。
- **用法**：
  ```bash
  python src/tools/gen_trilateration_plan.py [--grid 1.0] [--fill-cap 120]
  python src/tools/gen_trilateration_plan_routes.py [--grid 1.0] [--fill-cap 120]
  ```
  - 产物当前不在仓库；现行覆盖评估直接用 `result/beacon_deployment_evaluation.json`。

#### `tools/gen_trilateration_map.py` / `gen_trilateration_map_routes.py` —— 覆盖热力图
- **功能**：渲染三点定位覆盖热力图（PNG，不入库）。
- **用法**：
  ```bash
  python src/tools/gen_trilateration_map.py [--grid 1.5]        # 全楼 → trilateration_coverage_map_F{fl}.png
  python src/tools/gen_trilateration_map_routes.py [--grid 1.0] # 路线 → trilateration_coverage_routes_map_F{fl}.png
  ```

#### `tools/refine_beacon_placement.py` —— 信标放置质量后处理（四规则）
- **功能**：对三点定位信标方案做放置质量后处理，强制满足 4 条部署规则（原贪心补点方案未约束）：
  - **R1 左右两侧分开部署**：每条走廊（沿长轴、质心参考判左右）双侧各 ≥1 信标，缺侧网格采样补点；
  - **R2 避开墙角/障碍物**：确定性修复 —— 距真墙角（非共线墙交点）<0.8m 的信标沿「墙角→信标」方向/沿墙滑离；压近柱体（<0.5m）的信标沿「柱心→信标」方向移开；
  - **R3 三角部署**：Lloyd 松弛打分含三角改善奖励（仅查退化点小半径，提速），对仍退化的点定向补点打破共线（自动去重，<1m 剔除）；
  - **R4 部署均匀**：relax 打分以 NN 间距贴近目标 3.5m 为准，间距过密惩罚；
  - **硬约束**：任意目标采样点可见信标数 ≥3 不下降（增量可见性缓存；移动被拒自动回退），`--max-new` 控制新增上限。
- **用法**：
  ```bash
  # 全楼方案（目标点 = walkable 1m 网格）
  python src/tools/refine_beacon_placement.py --plan result/beacon_deployment_plan_trilateration.json
  # 路线方案（目标点 = 指纹路线点）
  python src/tools/refine_beacon_placement.py --plan result/beacon_deployment_plan_trilateration_routes.json \
      --target result/fingerprint_grid_routes.json --out result/beacon_deployment_plan_trilateration_routes_refined.json
  # 只评审不修改
  python src/tools/refine_beacon_placement.py --plan <方案.json> --review-only
  ```
  - 输出：`<方案名>_refined.json`（原信标坐标更新 + `placementRefined: true`，新增信标 `semanticTag=placement_quality_fill`）+ `result/trilateration_placement_review.json`（四规则前后对比评审）。
  - **历史实测效果（针对已废弃的贪心方案，仅存档）**：全楼 324 → 336 信标，corner 38.2%→19.4% / 50.8%→28.8%，obstacle 11.3%→6.0% / 10.8%→6.1%，三角退化 13.9%→7.9% / 24.5%→8.4%，≥3 覆盖 97.6%/99.2% 保持；路线 66 → 89 信标，corner 41.4%→0% / 62.5%→0%，覆盖保持 100%。现行 61 枚台账为人工确认结果，未走此精化链。
  - 性能：全楼方案 <60s（三角奖励仅查退化点 + STRtree 找墙）。

## 5. 典型工作流

**A. 从 PDF 到可交互地图（端到端）**
```bash
python src/parsing/parse_cad_pdf.py
python src/qa/validate_geojson.py
python src/rendering/render_interactive.py
python -m unittest discover -s tests        # golden 回归
```

**B. 指纹网格 + 信标台账校验**
```bash
# 1) 生成/刷新指纹网格（全楼 2m / 路线 1m）
python src/tools/generate_fingerprint_grid.py --mode full
python src/tools/generate_fingerprint_grid.py --mode route --routes <路线JSON>

# 2) 信标台账校验（现行 61 枚）
python src/tools/validate_beacon_deployment.py

# 3) 覆盖评估 + 渲染（含 ≥3 信标覆盖图层）
python src/tools/analyze_trilateration_coverage.py
python src/rendering/render_interactive.py --beacons result/ble_deployment.json \
    --fingerprint result/fingerprint_grid_routes.json
```
> `--routes <路线JSON>` 需提供路线几何（导航测试路径）；仓库内没有该中间文件，路线网格可由 `src/tools/recover_fingerprint_routes.py` 从已提交的渲染 HTML 反解恢复。

**C. 手工骨架闭环**
```bash
python src/tools/export_skeleton_template.py        # 导出 SVG 底图
# 在渲染页/编辑器中手绘红线标注
python src/tools/import_manual_skeleton.py --input cr_skeleton.svg --apply
git add result/skeleton_manual_parsed.json          # 必须提交
```

**D. 重建历史三点定位方案（仅在需要时）**
```bash
python src/tools/gen_beacon_plan.py --mode route --routes <路线JSON>
python src/tools/gen_trilateration_plan_routes.py
python src/tools/refine_beacon_placement.py --plan result/beacon_deployment_plan_trilateration_routes.json \
    --target result/fingerprint_grid_routes.json \
    --out result/beacon_deployment_plan_trilateration_routes_refined.json
```

## 6. 命名与协作约定

- **分支铁律（铁律 0）**：禁止直接在 `master` 上开发；所有功能/优化/bugfix 一律从最新 `master` 切**无斜杠名**新分支（如 `feature-xxx` / `fix-xxx`），合入后再删分支。禁止 `--force` 推送。
- **单需求单分支（铁律 0b）**：一个分支只含一个需求的改动；开发严禁顺带修改不相关代码（铁律 0c），渲染产物按脚本再生不算越界。
- **目录纪律**：正式脚本仅在 `src/`（按 `common/parsing/geometry/semantics/qa/rendering/skeleton/topology/io/tools` 子目录）；调试脚本放 `debug/`；根目录不留 `.py`。
- **手工骨架入库**：`result/skeleton_manual_parsed.json` 属代码，每次重生成必须 `git add`+提交；严禁 `git checkout` 回退。
- **推送凭据**：远端用 SSH 格式 `git@github-cuitao:cuitao2046/pathai.git`（重克隆后需 `git remote set-url`）。
- **环境注意**：本机 Bash 工具的 coreutils（`ls`/`head`/`tail`/`dirname`）不可用，`git` 可用；PowerShell 的 stdout 不回显、`Remove-Item` 会静默失败。批量取数/校验请用 Python 脚本写 UTF-8 文件后再读取。
