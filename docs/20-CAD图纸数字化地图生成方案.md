# 基于 CAD 施工图的室内数字化地图生成方案

> 用途：项目阶段性汇报组成部分
> 范围：初中学部 1# 教学楼 1~2 层，从 CAD 图纸 PDF 到可导航室内地图的全链路
> 数据基线：`result/school_building_01_map_v9.geojson`（version 9.0.0），统计截至 2026-09-15

---

## 一、方案概述

### 1.1 要解决的问题

室内导航的前提是拥有一份**机器可理解、可计算**的室内地图。本项目面对的现实条件是：业主只提供建筑施工图的 **A0 幅面 CAD 导出 PDF**（首层、二层各一份），没有 BIM 模型、没有 GIS 数据、没有矢量的房间边界。

因此需要解决三个层次的问题：

| 层次 | 问题 | 难点 |
|------|------|------|
| 几何 | 从 PDF 的绘图指令中还原墙体、房间、门、楼梯、柱的几何 | PDF 只有线段与圆弧，没有"房间"这个概念 |
| 语义 | 判断每个多边形是教室、走廊还是卫生间，每扇门是摆弧门还是防火门 | 依赖图纸标注，标注与图形需关联 |
| 拓扑 | 把几何转成可寻路的图结构（节点-边），并支持跨层 | 房间之间必须通过门连通，不能穿墙 |

### 1.2 输入输出

```
输入：A20-002-II-首层平面图-A0.pdf   （CAD 导出，含 OCG 图层）
      A20-003-II-二层平面图-A0.pdf

输出：school_building_01_map_v9.geojson   （结构化室内地图，坐标系 local_meters）
      floor_layout_v9_interactive.html    （可交互可视化与人工校验界面）
```

### 1.3 总体策略

采用「**自动解析为主 + 人工标注闭环**」的策略：

- 墙体、门窗、柱等**几何要素**全自动提取（它们来自明确的图层与线型）；
- **走廊骨架**采用人工 SVG 标注（算法中轴提取在开放空间效果不佳，人工 30 分钟标注远优于反复调参）；
- 每个环节都产出**可人工校验与修正**的中间物（交互 HTML 支持边编辑写回、房间属性覆盖、骨架导入）。

## 二、总体技术路线

全流程分为 **10 个阶段**，构成一条可重跑的流水线：

```
① PDF 矢量提取与图层分离
        ↓
② 坐标系标定（pt → 米）
        ↓
③ 墙体矢量化与封闭处理
        ↓
④ 门窗与洞口识别
        ↓
⑤ 房间识别（栅格化 + 分水岭 + 标签播种）
        ↓
⑥ 语义分类与属性增强
        ↓
⑦ 骨架提取（人工标注优先）
        ↓
⑧ 拓扑图构建（TR → TD → TI）
        ↓
⑨ 质量校验（QA）
        ↓
⑩ 渲染输出（交互 HTML / PNG）
```

对应代码模块：

| ⑩ 渲染 | `src/rendering/render_interactive.py`、`src/rendering/render_map.py` |

## 三、各阶段技术方案

### ① PDF 矢量提取与图层分离

CAD 导出的 PDF 保留了矢量图元与 **OCG（可选内容组）图层**结构，这是本方案能成立的前提——我们可以按图层区分要素类别，而不是在像素上做图像识别。

- 解析 PDF 中的路径（`line` / `polyline` / `curve` / `quad`）与文本，保留其所属图层名。
- **仅解析默认开启的图层**。（图纸中部分图层默认关闭，其内容不参与成图。）
- 关键图层及其用途：

| 图层 | 内容 | 用途 |
|------|------|------|
| `WALL` 等结构层 | 墙体双线 | 墙体几何（分散在多个默认开启图层，取并集） |
| `window` | 窗、门摆弧、门编号（DK 块） | 摆弧门与门洞识别 |
| `DOOR_FIRE` | 防火门 | 防火门识别 |
| 轴网 / 尺寸标注 | 轴线、尺寸 | **比例尺校准依据** |
| 文字层 | 房间名称、编号 | 房间语义标签 |

### ② 坐标系标定

把 PDF 的 **pt 单位**图纸坐标转换为**物理米制**坐标，是后续一切几何计算的基准。

- **比例尺**：轴网间距 8400 mm 对应 158.8 pt（取众数），并用窗编号 `M2GW5924`（5900 mm = 111.5 pt）交叉验证，得

  ```
  SCALE = 0.0529 米/pt   （≈ 15.53 pt/米）
  ```

  > 早期版本采用 0.0644，偏大 22%，导致全楼尺寸失真，已废弃。双证据互证是必要的。

- **原点与方向**：`ORIGIN = (2019.1, 1154.8) pt`，并对 **Y 轴做翻转**（PDF 的 Y 轴向下，地图坐标 Y 轴向上）。
- 输出坐标系记为 `local_meters`（建筑局部米制），所有下游模块与信标坐标共用该坐标系。

### ③ 墙体矢量化与封闭处理

- 多个结构图层的线段取**并集**，得到墙体线集。
- **虚线墙处理**：虚线在图面上表现为"短段 + 大间隙"，按 30 pt 阈值无条件桥接，避免房间边界出现缺口。
- **墙体厚度**：CAD 中墙以双线表示，由线间距反推厚度并推断材质（当前实测 0.203 m → `brick`）。
- **开口封口**：窗、门洞、无摆弧开口处需要把墙线断开，并加**端头盖帽**（cap），使墙体形成闭合区域，供房间识别使用。

### ④ 门窗与洞口识别

这是几何还原中**最依赖图纸约定**的一步，门分三类，分别来自不同证据：

| 类型 | 证据来源 | 识别方法 | 数量（F1/F2） |
|------|----------|----------|---------------|
| **摆弧门** swing | `window` 层圆弧（门扇开启弧线） | 圆弧 + 门轴检测 | 69 / 35 |
| **防火门** fire | `DOOR_FIRE` 层 | 层内图元直接判定 | 54 / 32 |
| **门洞** opening | `window` 层的 **DK 矢量笔画**（非文字层）+ 墙缝几何 | 笔画字形识别（D/K 形判定）+ 墙缝定位 | 9 / 9 |

- **门洞几何优先级**：① DK 笔画 < 13 pt 时取真实轴；② 50 pt 内的墙缝；③ 吸附到最近墙（约 1.6 m）。
- **门不做合并**（明确约定）：同一物理开口只保留一扇门。早期版本做过 0.8 m / 1.0 m 合并，会把不同房间的门混叠（导致门同时归属两个房间），已禁用。
- **特殊规则**：卫生间防火门丢弃；卫生间/楼梯间中带 DK 标注的摆弧门与防火门重分类为门洞（F1、F2 各 4 处）。
- **门归属房间**：三级策略——① 铰链端贴墙归属；② 门轴两侧 ±6 pt 投票；③ 门中心距房间边界 4 pt 内兜底。

### ⑤ 房间识别（核心技术难点）

CAD 里**没有"房间"这个对象**，房间是墙体围合出来的空白区域。本方案采用「**栅格化 + 形态学 + 分水岭 + 标签播种 + 守卫式泛洪**」的组合算法（`build_rooms`）：

1. **栅格化**：把全部墙线（含封口）栅格化为占用图。
2. **形态学处理**：去噪、填补细缝，得到连通的空白区域。
3. **分水岭归属**：以墙体为分水岭，把空白区切分为候选单元。
4. **开放/封闭空间分治**：走廊、门厅、活动室、中庭属于**开放空间**（`OPEN_SPACE_TYPES`），单独扫描预排除，不与封闭房间混淆；二者重叠时取差集处理。
5. **标签播种**：图纸文字标签（如"音乐教室"）落在被隔断切碎的小单元时，以标签为种子归并相邻单元。
6. **守卫式泛洪合并**：厕位格、凹位等被隔断完全围合、分水岭无法到达的区域，用受限泛洪合并回主空间。
7. **楼梯间补录**：开放式楼梯井常被栅格化漏掉，按编号（如 `II-B1-01#ST`）单独追加为房间。
8. **合班教室纠正**：`_heban_real_polygon` 用语义种子 + 射线投票还原真实边界，解决了合班教室被切碎的问题（F1-RM-0050 还原为 211.9 m²，覆盖率 98.9%，零重叠）。

识别结果：**F1 81 间 / F2 55 间**。

### ⑥ 语义分类与属性增强

在几何之上附加**导航所需的语义**：

- **房间类型**分两层：粗粒度 `type`（功能房间统一 `room`；公共/设施型为 `corridor`、`staircase`、`stair_lobby`、`toilet`、`lobby`、`infrastructure`、`elevator_lobby`），细分用途在 `roomType` / `roomSubType`（`classroom`、`office`、`equipment` …）。
- **门属性**：`doorType`（swing/fire/opening）、`width_m`、`openDirection`、`hingeSide`、`swingIntoRoom`、`wheelchairAccessible`、`hasThreshold`、`isGlass`、`isAutomatic`。
- **无障碍属性**：风险节点（`riskNodes`，F1 68 / F2 41）、电梯、坡道、盲道、地面材质变化。
  > 本套施工图**无无障碍设计专篇图层**，坡道/盲道/地面材质三类数据缺失，已显式标记 `surveyRequired`，需现场勘测补齐。

### ⑦ 骨架提取

走廊是开放空间，没有封闭多边形，需要单独提取**可通行骨架**：

- **人工标注优先**：若存在 `result/skeleton_manual_parsed.json`，则跳过算法中轴提取。做法是把底图导出为 SVG，人工用红色线段/矩形描出走廊中线，再转回 GeoJSON。
  > 这是本方案的一个重要工程决策：开放空间中轴提取极易受墙体毛刺影响，人工标注 30 分钟的收益远大于反复调参。
- **算法回退**：无人工骨架时，用 `medial_axis` 中轴提取 + `skeleton_vectorize` 矢量化 + `junction_detector` 交叉口检测。

**注意**：`skeleton_manual_parsed.json` 是必须纳入版本管理的资产（丢失会导致渲染缺矩形）。

### ⑧ 拓扑图构建

把几何转成可寻路的图。采用**三段式节点模型**，强制"跨房间必须经门"：

| 节点 | 含义 | 说明 |
|------|------|------|
| **TR** | 房间节点（Topology Room） | 房间中心，封闭空间的代表点 |
| **TD** | 门口节点（Topology Doorway） | 门的位置，房间与走廊的唯一通道 |
| **TI** | 交叉口节点（Topology Intersection） | 走廊交汇点，开放空间路网骨架 |
| TF / TEN | 设施节点 / 出入口节点 | 电梯、楼梯、建筑出入口 |

- **边**只连接 TR↔TD、TD↔TI、TI↔TI 等合法组合，**禁止房间直接相连**，从图结构上杜绝"穿墙路径"。
- **跨层边**：按图纸编号（如 `II-B1-01#ST`）自动匹配同编号的上下层楼梯/电梯节点，生成 10 条跨层边（楼梯 7 + 电梯 3），带 `accessibilityLevel`、`riskLevel`、`blindAccessible` 等属性。
- **路由规则**（`route_rules.py`）：门类型惩罚 `DOOR_PENALTY = {swing: 0, fire: 0.5, opening: 1}`；三层回退（最佳门 → 所有门 → 穿墙兜底）；盲模式剔除盲区、禁止楼梯跨层（强制走电梯）。

### ⑨ 质量校验

`src/qa/validate_geojson.py` 做自动化 QA，**核心指标是"无门封闭房间数 = 0"**——即每个封闭房间都必须至少识别出 1 扇门，否则该房间在拓扑图中不可达。

其他校验：跨层边合法性、节点连通性、穿墙边检测（`wall_crossing_titi`，当前为 **0**）、必经门完整性。

### ⑩ 渲染输出

- `render_interactive.py` 生成**自包含单文件 HTML**（`floor_layout_v9_interactive.html`），支持图层开关、缩放平移、点击查看详情（墙厚/材质、房间类型、门属性）、楼层跳转、拓扑联动高亮、边编辑写回、导出 SVG，前端内置 Dijkstra 寻路（与后端 `route_rules` 规则对齐）。
- `render_map.py` 输出 PNG 静态图，用于快速预览与打印。

## 五、关键技术决策

| # | 决策 | 理由 |
|---|------|------|
| 1 | **基于 OCG 矢量图层而非图像识别** | 图纸自带矢量与图层信息，直接解析精度远高于像素级识别，且可追溯来源图层 |
| 2 | **比例尺双证据互证** | 单一依据（轴网）易错；用窗编号交叉验证后发现早期 0.0644 偏大 22% |
| 3 | **走廊骨架人工标注优先** | 开放空间中轴提取对墙体毛刺极敏感，人工标注性价比更高 |
| 4 | **门不合并** | 合并会把不同房间的门混叠，导致门归属错误（如同时归属走廊与教室） |
| 5 | **开放/封闭空间分治** | 走廊与教室在几何上会重叠，必须按语义分开处理并取差集 |
| 6 | **三段式拓扑 TR→TD→TI** | 从图结构上强制"跨房间必经门"，避免产生穿墙路径 |
| 7 | **每个环节可人工干预** | 交互 HTML 支持边编辑写回、房间属性覆盖、骨架导入，形成人工闭环 |
| 8 | **统一常量来源** | SCALE / 门惩罚 / 步速等集中到 `constants.py`，前端由序列化注入，杜绝前后端不一致 |

## 六、当前局限与后续工作

| 局限 | 影响 | 后续方向 |
|------|------|----------|
| 少量标签未匹配到多边形 | 孤儿门 F1 61 / F2 17，部分门缺少房间归属 | 改进标签-多边形关联规则 |
| 卫生间多边形只覆盖盥洗走道区 | 卫生间内部精细化导航不足 | 结合现场勘测补充 |
| 走廊骨架为简化模型 | 复杂路径规划精度受限 | 视需要重建细粒度中轴路网 |
| 门只有位置与宽度，无铰链/朝向完整信息 | 影响"门在左手边/右手边"类精细语音提示 | 现场勘测补充 |
| 无障碍图层缺失（坡道/盲道/地面材质） | 视障导航的关键信息不全 | 现场勘测补齐，已在数据中显式标记 `surveyRequired` |
| DK 遮挡/贴墙过滤存在误删 | 少量门洞漏检 | 优化过滤规则 |
| 图纸坐标与现场存在施工偏差 | 定位精度受影响 | 现场抽查 10~20 点做配准校验 |

## 七、小结

本方案实现了一条**从 CAD 施工图 PDF 到可导航室内地图的完整自动流水线**，核心贡献在于：

1. **证明了纯图纸驱动的室内地图构建可行**——无需 BIM、无需现场测绘即可产出结构化地图（4,442 段墙、136 个房间、208 扇门、465 个拓扑节点）。
2. **把导航约束前移到地图构建阶段**——三段式拓扑与 QA 校验（无门封闭房间 = 0、穿墙边 = 0）从数据层面保证了路径合法。
3. **建立了人工闭环**——人工骨架标注、边编辑写回、属性覆盖，使算法结果可被领域知识修正。
