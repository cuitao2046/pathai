## 1. 背景与目标

现场信标已全部统一为 **Minew E5 定位信标（MinewBeaconAdmin SDK / BeaconSET 固件）**，共 61 枚（1 层 52、2 层 9）。
官方管理工具只有 Android SDK（`minewBeaconAdmin.jar`）与手机 App；Windows 端**无官方 SDK**。
已对该 jar 反编译核验，得到实际私有 GATT 协议（`0000fff0` 服务族、逐特征读写、无 AES），
足以在 Windows 上自实现，见 `docs/reference/Minew_E5_BeaconAdmin_Protocol_Verified.md`。

当前现场流程是「逐台打开厂商 App → 照纸面参数逐项输入 → 无状态、无留痕、无写后校验」，
容易写错 Major/Minor、漏配人工补点，且配错只能在联调阶段由定位异常倒查。

**目标**：自研 `beacon-provisioner` **Windows 桌面程序**（.NET 8 + WPF + WinRT BLE），打通
**「服务端台账 → 扫描/扫码选中 → 按 beaconId 查参数 → 一键写入 → 重启校验 → 留痕」** 的闭环：

1. 启动程序，用**管理后台账号登录**，从服务端拉取全部蓝牙信标部署台账；
2. 扫描蓝牙广播，选中要配置的信标，进入配置页；
3. 按 `beaconId` 查询台账参数；现场可用 **USB 扫码枪**（或手动输入）扫标签二维码定位；
4. 点「写入」，把台账参数直接写入 E5，重启后校验三元组与参数。

**不做**：不改信标固件、不做 OTA、不写非台账参数；
**不提供软关机 / 恢复出厂入口**（关机由操作人物理断电，避免误操作导致设备不可恢复）。

## 2. 现状与缺口（均为实测）

| # | 缺口 | 实测证据 |
|---|---|---|
| G1 | **Major 不能按楼层推算** | 台账中 `BK-M-2-001/002` 是 **floor=2 但 major=1**（minor 20001/20002）；`major=1` 共 52 枚、`major=2` 共 9 枚，**major ≠ 楼层** |
| G2 | **Minor 曾出现漂移** | `BK-TR-F2-001/002/003` 旧手工参数表写 `27B3/27B4/27B5`，台账为 `27AE/27AF/27B0`（该组已重编号） |
| G3 | **无「已配置/未配置」状态与留痕** | 逐台 App 手工输入，无操作人/时间/设备记录；写入值无归档 |
| G4 | **写后无校验** | 无「重扫 + 连接读参」确认步骤；配错只能靠联调异常倒查 |
| G5 | **台账三元组是「规划目标值」，不是设备身份** | 未配置的出厂信标广播厂商默认三元组（多台可能完全相同），不能拿规划三元组匹配设备；写入**只作用于扫描列表中人工选中的那台设备**，以 MAC 区分并作审计记录，不再要求关闭其余信标 |
| G6 | **Windows 无官方 SDK** | 官方 `minewBeaconAdmin.jar` 仅 Android；Windows 需按**已核验协议**自实现 GATT（`0000fff0` 服务族），WinRT `BluetoothLEAdvertisementWatcher` + `BluetoothLEDevice` |
| G7 | ~~设备名写入路径未覆盖~~ **已关闭** | 反编译确认设备名特征 `FFF9` 可写可读（ASCII，无 7 字符硬限制，本项目仍用 ≤7 短码）；旧设计文档未覆盖属遗漏 |
| G8 | ~~广播间隔无法读回~~ **已关闭** | 连接后 SDK 逐特征 Read：间隔 `FFF7`（UINT16）、功率 `FFF5`、名称 `FFF9` 均可读回；写后校验可做全量比对 |
| G9 | **功率是「档位码」不是 dBm** | `MinewBeaconSetting` 档位表 `-30/-20/-16/-12/-8/-4/4/0`，写入是**索引/码**（1 字节），不是 `-12` 的字节 `0xF4`；需先读 `FFF5` 码表再按 -12 dBm 选码 |
| G10 | **旧设计文档协议不可用** | `a3c875xx` 服务族 / AES-128 / Slot0~5 / 两包帧 均不在该 jar 内；以 `Minew_E5_BeaconAdmin_Protocol_Verified.md` 为准 |

**结论**：需要 3 个工具（P0 服务端台账接口、P1 Windows 桌面配置程序、P2 离线一致性校验），
P1 必须包含「选中设备入库 → 写参 → 人工重启 → 校验 → 即时上传」五段，并先完成一次真机协议验证（P1-a）。

## 3. 台账参数（Minew E5 口径）

来源：`docs/07` §2.3（功率档位实测）、台账 `result/ble_deployment.json`、
`docs/reference/Minew_E5_BeaconAdmin_Protocol_Verified.md`（反编译核验的 GATT 协议）。

**只配置与定位/指纹直接相关的 6 个参数**：

| 参数 | 取值 | Windows 写入特征 | 何时可改 |
|---|---|---|---|
| UUID | `B9407F30-F5F8-466E-AFF9-25556B57FE6D`（61/61 一致） | `FFF1`（16B，UUID 文本序） | 仅初始化绑定 |
| Major | **取台账 `major`**（禁止按 floor 推算） | `FFF2`（2B 大端） | 仅初始化绑定 |
| Minor | **取台账 `minor`**（10001~20002） | `FFF3`（2B 大端） | 仅初始化绑定 |
| 设备名称 | **短码**（≤7 字符，`F{floor}-{minor后三位}`，如 `F1-101`） | `FFF9`（ASCII） | 仅初始化绑定 |
| 发射功率 | 统一 **-12 dBm（3 档，约 15 m）** | `FFF5`（1B **档位码**；先读码表再选 -12 对应码，G9） | 初始化 + 现场编辑 |
| 广播间隔 | **300 ms**（台账统一值，合法范围 100 ms~10 s） | `FFF7`（2B 大端，`0x012C`；**单位 ms**） | 初始化 + 现场编辑 |

**保持出厂默认、不允许编辑**：
- 广播模式 `mode`（`FFFE`，固定 iBeacon）；
- 校准 RSSI@1m（`FFF4`，**不写**；仅连接后读回展示，解算用后端配置 `-71`，见 `docs/28`）；
- 设备密码（`FFF6`，默认 `minew123`，**不改**；每次配置仅在 `FFFF` 提交时使用）；
- 其它特征（`FFF8` DeviceID、`FFFA`、`FFFB` 关机）不触碰。

> **官方手册约束（BeaconSET 用户手册 v2.0.0，见 `docs/reference/BeaconSET用户操作手册_v2.0.0.pdf`）**：
> UUID 为 32 位 hex（`0-9`/`a-f`，大小写均可）；Major/Minor **0~65535**；
> 广播间隔 **100 ms~10 s**（`FFF7` 单位是 ms；官方 App 输入框按 **100 ms** 计，输入 20 = 2000 ms）；
> 广播功率**只能从设备档位列表选择**（非任意 dBm，-12 dBm 须在列表内）；
> 校准距离 **-127~0**（常见 `-55/-59`，不建议修改，广播中不可见）；
> 重启密码 **8 位**；连接模式必须保持 **YES**（`NO` 后 5 分钟即不再广播名称）；
> 设备连接 **5 分钟**自动断开，写入流程须在该时限内完成；连续 **5 次错误密码**会触发 5 分钟不可连接。
> 功率档位列表若不含 -12 dBm：**暂停入库**，回填规划台账并重新发布（服务端要求写入值 = 规划值），不要直接写最近档。

> **物理标签**：入库前打印标签贴到信标；标签含 **`beaconId`、短码 `deviceName`、二维码（内容 = `beaconId`）**
> 与楼层/位置；用于人工选择、扫码定位与后续对账（与设备名双重识别，见 §5.5 / §6.11）。

**现场约束**：
1. **UUID 统一约定**：全站固定为系统预定义 UUID `B9407F30-F5F8-466E-AFF9-25556B57FE6D`，**禁止逐台不同**；
   因此三元组唯一性等价于 **`(major, minor)` 唯一**（当前台账 61/61 已验证：UUID 仅 1 种、三元组 61 个、无重复）；
2. **三元组只在初始化绑定写入**；完成后不允许编辑（现场编辑仅 `txPower` / `broadcastInterval`）；
3. E5 **没有指令重启**：`FFFF` 只负责「保存参数 + 密码校验」并断开连接；校验前必须**人工断电重启**；
4. 保持设备**可连接**（禁止改成不可连接/触发后关机）；
5. 同一场地 `(major, minor)` 必须全表唯一，禁止两台配成同一 ID。

## 4. 方案总览

```
result/ble_deployment.json ──┐
（规划台账，只读事实源）      │
                             ├─► P0 服务端（admin 会话鉴权）：发布包增补配置字段 + 台账接口
backend/maps_data/…/<ver>.json（地图包 beacons）│      ├─► GET /beacons（规划参数）
                             │      ├─► PUT/GET/commit deployment-records（真实台账）
                             │      └─► src/tools/gen_beacon_labels.py → 可打印标签（QR = beaconId）
                             │
                             └─► P1 beacon-provisioner（Windows 桌面程序，.NET 8 + WPF + WinRT BLE）
                                   admin 登录 → 拉台账 → 打印/贴标签
                                   广播扫描（iBeacon 帧解析）→ 在列表中选中目标设备
                                   → 扫码枪/手动输入 beaconId → GATT 连接 `FFF0` + 逐特征读回
                                   → 写 `FFF1/2/3/5/7/9` → `FFFF` 提交（密码）
                                   → 人工断电重启 → 重新连接 → 读回校验
                                                │
                                                └─► 本地 SQLite 记录 + 每台即时上传
                                                            │
                                                            └─► P2 validate_beacon_provisioning.py
                                                                 规划/真实/地图包三方比对 + 发布 gate
```

设计原则：
1. **规划台账是只读事实源**：程序写入值全部来自规划台账；真实台账记录实际写入与校验结果。
2. **按选中设备写入**：扫描列表按 RSSI 排序，人工选中目标设备后只对该 GATT 会话写入；MAC 用于区分设备与审计。
3. **写后必须校验**：重启后回扫三元组一致 + 重连读回 6 项（含间隔/名称）逐项一致，才算通过。
4. **一切留痕**：操作人、时间、MAC、写入值（名称/三元组/功率/间隔）、校验结果；每台即时上传，可断点续传。

## 5. P0 —— 服务端台账接口与配置字段

**定位**：让程序用一次轻量请求拿到 61 枚信标的全部配置参数，避免下载数 MB 地图包。

### 5.1 发布包增补字段

`backend/scripts/convert_map_v9.py` 的 `convert_beacons()` 增补：
- `broadcastInterval`（取台账 `broadcastInterval`，缺省报错，不猜默认值）；
- `deviceName`（≤7 字符；规则 `F{floor}-{minor后三位}`，超限按 §5.3 处理）；
- `locationDesc`、`mountType`、`installHeightM`（已存在）。
- **预检**：所有 UUID == 系统预定义常量；`(major,minor)` 全表唯一；`deviceName` 全表唯一且 ≤7 字符；major/minor ∈ [0,65535]；`broadcastInterval` ∈ [100,10000] ms；任一不过则拒绝产出。

> 广播类型、measured power、密码、加密/鉴权保持出厂默认，**不进入配置接口**。

### 5.2 新接口 `GET /api/v1/sites/{siteId}/beacons`

| 项 | 约定 |
|---|---|
| 鉴权 | 复用 admin 会话（`deps.require_admin_ready`）：Cookie `pathai_admin_session`，写请求另带 `X-Admin-CSRF`（见 §5.4） |
| 参数 | `mapVersion`（默认 `latest`；与 `/map` 完全一致：未发布版本 → 404 `MAP_NOT_PUBLISHED`） |
| 响应 | `{"siteId","mapVersion","items":[BeaconConfigItem]}` |
| 数据源 | 只读已发布地图包的 `beacons`（不直读 `result/` 台账文件） |
| 缓存 | 与 `/map` 相同 ETag；客户端可带 `If-None-Match` |

```jsonc
{
  "siteId": "school-building-01",
  "mapVersion": "2026-10-30.1",
  "items": [
    {
      "beaconId": "BK-01-001",
      "deviceName": "F1-101",
      "floorId": "1",
      "coordinates": [-30.25, -75.08],
      "uuid": "B9407F30-F5F8-466E-AFF9-25556B57FE6D",
      "major": 1,
      "minor": 10101,
      "txPower": -12,
      "broadcastInterval": 300,
      "locationDesc": "1F 电梯口（II-01#EL）· 门套或呼梯板旁",
      "mountType": "door_frame"
    }
  ]
}
```

> `beaconId` 用于台账与物理标签；`deviceName` 是**实际写入设备名的短码**（≤7 字符，§5.3），扫描列表按它显示。
> **已发布**：`2026-10-30.1` 是首个携带 `deviceName`/`broadcastInterval` 的地图包（由 2026-10-29.1 增补两字段生成，
> 其余内容不变；重启后端即生效）。旧版本包按需回退：`deviceName` 由 API 按同规则派生，`broadcastInterval` 为 `null`。

### 5.3 设备名长度与短码映射

- 设备名上限 **7 字符**，完整 `beaconId` 放不下 → 生成短码 `deviceName`，与 `beaconId` 一对一；
- 推荐规则 `F{floor}-{minor 后三位}`：`BK-01-001 → F1-101`、`BK-M-2-001 → F2-001`；
- 预检：`deviceName` 全表唯一、长度 ≤7；同一楼层内 `minor 后三位` 不得重复；
- 映射随 `GET /beacons` 下发；物理标签同时印 `beaconId` 与短码；真实台账记录两者。

### 5.4 客户端鉴权：复用 admin 登录（已定）

客户端（Windows 桌面程序）无法使用微信 `wx.login` 的 code → **复用现有管理后台登录，不新增账号体系**
（后端当前只有固定 `admin` 账户，见 `backend/pathai_backend/admin/service.py`）。

| 环节 | 约定 |
|---|---|
| 登录 | `POST /api/v1/admin/auth/login`（`{"username","password"}`）→ 返回 `csrfToken` + `Set-Cookie` |
| 会话 | Cookie `pathai_admin_session`（HttpOnly / SameSite=Strict / `Secure` 当 `env != local`），TTL **8h**（`SESSION_TTL_SECONDS`） |
| 写请求 | `PUT .../deployment-records/{beaconId}`、`POST .../deployment-records/commit` 必须带 `X-Admin-CSRF: <csrfToken>`；缺失或错误 → 403 `ADMIN_CSRF_INVALID` |
| 读请求 | `GET /beacons`、`GET /deployment-records` 只校验会话 Cookie |
| 同源校验 | `deps.check_same_origin` 仅在请求带 `Origin` 时校验；**桌面程序不发 `Origin`**，因此不会被拒 |
| 首次改密 | 登录返回 `mustChangePassword=true` → 程序**阻断并提示到管理后台完成首次改密**（不在程序内实现改密） |
| 会话失效 | 401 `ADMIN_UNAUTHORIZED` → 重新登录；`GET /me` 会轮换 CSRF，重新登录后同时更新 Cookie 与 CSRF |
| 操作人留痕 | 真实台账 `operator` 取登录用户名（当前为 `admin`） |

Windows 实现要点：

1. `HttpClient` + `CookieContainer` 保存会话 Cookie；`DelegatingHandler` 自动附加 `X-Admin-CSRF`；
2. 会话（Cookie + CSRF）用 Windows DPAPI（`ProtectedData`，`CurrentUser` 范围）加密落盘，**不存密码**；
3. 入库结束调 `POST /api/v1/admin/auth/logout` 并清本地会话；
4. `env != local` 时 Cookie 为 `Secure`，生产环境必须 HTTPS。

> **风险**：admin 会话权限覆盖地图发布等管理操作。本期用**专用现场笔记本**、入库结束即退出登录来收敛；
> 若要按角色隔离权限，再单独拆运营账号（不在本期范围）。

### 5.5 标签二维码生成（P0 工具）

**定位**：`src/tools/gen_beacon_labels.py` 从**已发布地图包**读取 `beacons`（与 `GET /beacons` 同源），
生成可直接打印的标签页，保证「标签 / 台账 / 程序」三处一致。

- 输入：`--site school-building-01 --version latest`（默认 `latest`；版本不符处理同 §5.2，返回 409 语义）
- 输出：`result/beacon_labels_<mapVersion>.html`（A4，内联 SVG 二维码，不产生额外图片文件）
- 单张标签内容：
  - 大字 **短码**（如 `F1-101`，≤7 字符）
  - **`beaconId`**（如 `BK-01-001`）
  - **二维码**：内容 = `beaconId` **明文**，纠错等级 M，边长 ≥ 20 mm
  - 小字：楼层 + 位置简述（`locationDesc` 截断）
- 依赖：`segno`（纯 Python、无系统依赖，可直接输出 SVG/PNG），加入后端 `requirements.txt`
- 预检：`beaconId` 唯一且匹配 `^[A-Za-z0-9-]{1,20}$`；`deviceName` 唯一且 ≤7；任一不过则拒绝生成
- 版式：61 枚 → A4 4 列 × 8 行 ≈ 2 页；带裁切线；打印后按 `beaconId` 贴到实物

> 二维码**只放 `beaconId`**、不放 URL/JSON：任何扫码器都能直读，标签更小、识别更快；
> 程序侧再按正则 + 台账存在性校验（§6.11）。

## 6. P1 —— `beacon-provisioner` Windows 桌面程序（.NET 8 + WPF + WinRT BLE）

**定位**：现场入库主力。**Windows 端无厂商 SDK**，按已核验协议自实现 GATT
（协议见 `docs/reference/Minew_E5_BeaconAdmin_Protocol_Verified.md`；.NET/WPF 工程架构参考
`docs/reference/Minew_E5_BeaconPlus_Windows_App_Design_Doc.md`，其 §2 协议部分作废）。入库流程：
广播扫描 → 选中目标设备并连接 → 读回当前配置 → 看当前状态 → 选未入库 `beaconId`（扫码或列表）→
按规划参数写入 → `FFFF` 提交 → 人工断电重启 → 重新连接读回校验 → 即时上传。规划台账不变。

**技术栈**：.NET 8（`net8.0-windows10.0.19041.0`）+ WPF（MVVM）；
WinRT BLE（`Windows.Devices.Bluetooth` / `.GenericAttributeProfile` / `.Advertisement`）；
`HttpClient`；本地 SQLite（`Microsoft.Data.Sqlite`）；扫码枪（HID 键盘输入），可选摄像头扫码（ZXing.Net）。

**协议要点**（依据 `docs/reference/Minew_E5_BeaconAdmin_Protocol_Verified.md`，已按 jar 反编译核验）：

| 用途 | 特征值 |
|---|---|
| 配置服务 | `0000fff0-…` |
| UUID / Major / Minor | `fff1` / `fff2` / `fff3` |
| 校准 RSSI@1m（只读不写） | `fff4` |
| 射频发射功率（1B 档位码） | `fff5` |
| 设备密码（不改） | `fff6` |
| 广播间隔（2B 大端） | `fff7` |
| DeviceID（不碰） | `fff8` |
| 设备名称（ASCII） | `fff9` |
| 软关机（不开放） | `fffb` |
| 广播模式（不碰） | `fffe` |
| **提交 / 生效（写密码）** | `ffff` |

- **无 AES、无 16 字节报文、无 Slot 0~5**：逐特征直写原始值，最后向 `FFFF` 写密码 ASCII 提交；
- 连接后逐特征 Read 取得当前值（`fff1/2/3/4/5/7/8/9/fffe`），`fffe` 读完即判定连接完成；
- UUID 按文本序 32 位 hex 转 16 字节；major/minor/interval 为 2B 大端；名称/密码为 ASCII；
- 功率写入的是**档位码**（G9），不是 dBm 字节，也不是旧文档的 `a3c87504`。

### 6.2 运行环境与启动准备

**环境**：Windows 10/11 64-bit；内置或外接 **BLE 4.0+ 适配器**（WinRT BLE 不可用则阻断）；
Windows BLE **不需要定位权限**（与 Android 不同）；.NET 8 运行时（或 self-contained 免安装）。

1. **打印并贴标签**：用 §5.5 生成的标签页（短码 + `beaconId` + 二维码）贴到实物；
2. **关闭所有蓝牙信标**（界面提示，操作人确认）；
3. **admin 登录**（§5.4），获取会话 Cookie + CSRF；
4. `GET /api/v1/sites/{siteId}/beacons?mapVersion=latest` 拉规划台账；
5. 本地校验：61 条、`beaconId` 唯一、`(major,minor)` 唯一、`deviceName` 唯一且 ≤7、UUID 全部等于系统预定义常量；失败禁止入库；
6. 缓存 `{mapVersion, items, fetchedAt}`；地图换版需重新拉取。

### 6.3 广播扫描与 GATT 连接

1. **适配器检查**：`BluetoothAdapter.GetDefaultAsync()`；无适配器或蓝牙关闭 → 阻断并提示开启；
2. **扫描**：`BluetoothLEAdvertisementWatcher`（`ScanningMode.Active`），解析广播：
   - iBeacon（公司 ID `0x004C` + `0x02 0x15`）：`UUID / Major / Minor / measuredPower`
   - `LocalName`（设备名，未配置时为出厂名）、`BluetoothAddress`（MAC，仅审计）、`RSSI`（排序用）
   - **关键**：未配置信标广播的是出厂三元组，不能当身份（G5）→ 以 MAC 区分、人工选中目标设备
3. **按选中设备写入**：允许多台同时广播；写入只作用于列表中选中的设备；
   列表按 RSSI 降序，显示 `设备名 / MAC / UUID / RSSI / 写入时间`；未配置时以标签为准；
4. **先停扫再连接**（WinRT 同时扫描+连接易失败）：`watcher.Stop()` →
   `BluetoothLEDevice.FromBluetoothAddressAsync(addr)`；
5. **GATT 初始化**：取 `FFF0` 服务与 `FFF1…FFF9 / FFFE / FFFF` 特征（全程 `BluetoothCacheMode.Uncached`）；
   逐特征 Read 当前配置（`FFF1/2/3/4/5/7/8/9/FFFE`），`FFFE`（mode）读完即判定连接完成；
   断开后 `Dispose()` 设备对象（规避 Windows GATT 缓存）；**无需订阅通知，也无需预先解锁**；
6. **口令**：默认 `minew123`，仅在写入末尾向 `FFFF` 提交时使用一次；该固件**没有 AES 握手**，
   密码错误表现为 `FFFF` 写入失败或配置未生效；
7. **读当前状态**：直接用上一步读回值（UUID/Major/Minor/名称/功率码/间隔/校准 RSSI）；
   读失败字段标 `unknown`，不伪造读数；
8. **连接时限**：固件在连接后 **5 分钟**自动断开 → 读回 + 写入 + `FFFF` 提交须在 5 分钟内完成，超时则重连。

### 6.4 当前状态与「开始配置」

1. 展示 **名称、UUID、Major、Minor、功率（dBm）、间隔（ms）、校准 RSSI、MAC、RSSI**（均来自连接后读回）；
2. **开始配置** → 参数页（§6.5）；**取消** → `session.Dispose()` 返回扫描页；
3. 连接失败/断开 → 提示并回到扫描页。

### 6.5 参数页与写入（GATT 直写）

1. 列出**未入库**的 `beaconId`（按字母序），已入库的不显示（重配另设入口，本期不做）；
   支持**扫码枪/手动输入 `beaconId`** 直接定位并选中（§6.11）；
2. 选中后展示该 `beaconId` 的规划参数（**短码/UUID/Major/Minor/功率/间隔**），**只读**；
3. 点「**写入**」按固定顺序下发（Write-With-Response，单步失败/超时 3s → `failed`；
   整组写入 + `FFFF` 提交须在 **5 分钟连接时限**内完成，超时则重连整组重写）：
   - `FFF1` ← UUID（16B，文本序）
   - `FFF2` ← Major（2B 大端）
   - `FFF3` ← Minor（2B 大端）
   - `FFF5` ← 功率**档位码**（按连接时读回的码表选 -12 dBm 对应码）
   - `FFF7` ← 广播间隔 `0x012C`（300 ms，2B 大端）
   - `FFF9` ← 名称短码（ASCII）
   - `FFFF` ← 密码 ASCII（**提交生效，必须最后一步**）
4. **不写** `FFF4`（校准 RSSI）/ `FFF6`（密码）/ `FFFE`（mode）/ `FFF8`（DeviceID）；
5. 成功 → 提示并记录 `written`；失败/中断 → 标记 `failed`，重连后整组重写（幂等）；
6. `FFFF` 提交成功后设备保存参数并断开连接；**SDK/固件均无「指令重启」**（仅有 `FFFB` 单向关机，不开放），
   因此程序写入并保存后弹窗提示操作人**物理断电重启**，点击 OK 表示已完成，才允许进入校验（Mock 走同一流程）。

> **界面按 3 步按钮呈现**：`1 写入（含 FFFF 保存）` → 弹窗提示「人工断电重启，OK 后继续」→ `2 校验`（回读比对）→ `3 上传`（PUT 真实台账），
> 上一步成功后才解锁下一步；任一步失败都停在当前步并给出差异/错误，便于真机联调逐段定位。
> **应用内不提供重启/上电/关机按钮**：E5 只能人工断电重启，`FFFB` 单向关机也不开放。

### 6.6 重启与校验

1. 操作人断电/上电，等待广播恢复；
2. **回扫比对**：广播 `(uuid, major, minor)` == 规划值，`LocalName` == 短码；
3. **重连读回**：`FFF1/2/3/5/7/9` 逐项比对（间隔按 UINT16、名称按 ASCII、功率码换算回 dBm）；
4. 全部一致 → `verified: full-readback`；任一不符 → `failed`，列出差异并允许重写；
5. 通过后关闭信标，进入下一枚。

### 6.7 设备名方案（≤7 字符）

设备名上限 **7 字符**，完整 `beaconId`（9~12 字符）放不下 → 使用**短码**，与 `beaconId` 一对一映射：

- **推荐**：`F{floor}-{minor 后三位}`，如 `BK-01-001 → F1-101`、`BK-M-2-001 → F2-001`；
  长度 6 ≤7，61/61 唯一（已校验），直观体现楼层；
- 备选：`M{major}-{minor 后三位}`（如 `M1-101`），由广播三元组派生，但 `major≠楼层`，人看不直观；
- 不推荐顺序号（`B001…B061`）：台账增删会漂移，且无位置含义；
- `deviceName` 由 P0 生成并随 `GET /beacons` 下发；物理标签同时印 `beaconId` 与短码；
- 标签二维码内容 = `beaconId` 明文（§5.5），程序扫码/输入即可定位该条台账（§6.11）；
  扫描列表与参数页显示 `LocalName / MAC / UUID·Major·Minor / RSSI`；
- **Windows 端设备名写入已确认可用（G7 关闭）**：写 `FFF9`（ASCII），读回 `FFF9` 用 `getStringValue`；
  短码 ≤7 字符是**项目约定**（固件/手册未给长度上限），便于扫描列表与标签肉眼对账；
- **连接模式必须保持 `YES`**：官方手册明确 `NO`（不可连接）模式在 5 分钟后不广播设备名称，
  扫描列表会显示 `Unknown`，按名称过滤失效——因此 `FFFE` 只读不写；
- 预检：`deviceName` 全表唯一、长度 ≤7；同一楼层内 `minor 后三位` 不得重复。

### 6.8 记录与上传（真实部署台账）

- **每台即时上传**：写入并校验通过后立即 `PUT` 上传，服务端按 `beaconId` **幂等 upsert**；
  失败进入本地待上传队列，恢复网络后重试；
- **结束汇总**：全部完成后调 `POST .../commit` 做一次完整性汇总（数量、未上传、失败项）；
- **规划台账不变**：真实部署台账是独立实体，记录实际写入值与校验结果；
- 换电脑/清缓存前先把待上传队列清空；本地记录可导出备份。

| 接口 | 用途 |
|---|---|
| `PUT /api/v1/sites/{siteId}/deployment-records/{beaconId}` | 单台写入/校验结果幂等 upsert |
| `GET /api/v1/sites/{siteId}/deployment-records` | 查询真实部署台账（现场编辑/复核） |
| `POST /api/v1/sites/{siteId}/deployment-records/commit` | 结束汇总：完整性校验、锁定本轮 |

// PUT body / state record
{
  "beaconId": "BK-01-001",

### 6.9 现场编辑（部署后调整）

- 入口：真实部署台账中按 `beaconId` 打开；
- **仅允许编辑 `txPower` / `broadcastInterval`**；`uuid / major / minor / name / mode / measured power / password` **只读**；
- 编辑后必须：连接写入 → 重启 → 全量校验 → `PUT` 更新真实台账（`source=field_edit`，记录差异与操作人）；
- **规划台账不变**：差异只存在于真实部署台账。

**Windows 实现（2026-10-31）**：主界面新增「现场编辑」tab，左侧列出真实部署台账记录，右侧复用扫描/连接与
「写入编辑（含保存） → 人工重启 → 重新连接 → 校验 → 上传」按钮；功率为档位下拉、间隔为数字输入，
其余字段只读。上传请求 `source=field_edit`、`nameWrite=unchanged`，服务端只放行功率/间隔差异。

### 6.10 安全护栏（必须实现）

| 护栏 | 说明 |
|---|---|
| 目标设备 | 只对扫描列表中人工选中的设备写入；多台同时广播不阻断 |
| 未入库清单 | 参数页只显示未入库 `beaconId`；一个 `beaconId` 只产生一条真实台账记录 |
| 参数只读 | 参数页不提供手工改参；写入值只能来自规划台账 |
| 只写 6 项 | 仅下发 `FFF1/FFFF`：uuid/major/minor（`FFF1/2/3`）、功率（`FFF5`）、间隔（`FFF7`）、名称（`FFF9`）；`FFF4/FFF6/FFF8/FFFE` 一律不动 |
| 对象确认 | 写入前展示 `beaconId` + 短码 + 三元组 + 功率/间隔，二次确认 |
| 标识占用检查 | 台账内 **`(major,minor)` 全表唯一**（UUID 全站统一，等价于三元组唯一） |
| 禁止不可逆模式 | 固定 iBeacon（`FFFE` 不动）且保持可连接；**不提供软关机（`FFFB`）/ 恢复出厂 / 改密码（`FFF6`）入口** |
| 密码不改 | 默认 `minew123` 仅在 `FFFF` 提交时使用一次，不写入 `FFF6`、不落盘 |
| 保持可连接 | `FFFE` 固定 `YES`；设为 `NO` 后 5 分钟即停止广播名称，扫描列表显示 `Unknown`、无法按名过滤 |
| 密码不重试 | 连续 5 次错误密码会触发 5 分钟不可连接；写入失败即停，人工核对密码后再试，禁止自动循环重试 |
| 写入应答 | 每步 Write-With-Response，单步超时 3s → `failed`；重连后整组重写 |
| 写后校验 | 回扫三元组一致 + **重连读回 `FFF1/2/3/5/7/9`** 全部一致（`full-readback`） |
| 断线保护 | 写入中断标记 `failed`；重连后从 `FFF1` 开始整组重写（不留半配状态） |
| 扫码校验 | 扫码/输入必须匹配 `beaconId` 正则且在台账中存在；不存在/已入库/格式不符 → 拒绝进入写流程 |

### 6.11 二维码扫码（Windows）

**用途**：扫码只做「定位到某条台账」这一件事，参数一律来自 `GET /beacons`，二维码本身不携带参数。

| 场景 | 行为 |
|---|---|
| 入库前查看配置 | 扫标签 → 展示该 `beaconId` 的参数卡（短码/三元组/功率/间隔/楼层/位置），不写设备 |
| 连接后选目标 | 扫标签 → 直接进参数页并选中该 `beaconId`（替代在未入库清单里手工查找），仍需未入库 |
| 写后校验/复核 | 扫标签 → 确认物理标签与本次写入目标一致（防相邻信标混淆），再回扫比对 |
| 现场编辑 | 扫标签 → 打开该 `beaconId` 的真实台账记录 |

**实现**（按「现场笔记本不一定有摄像头」的实际情况排序）：

1. **主路径：USB 扫码枪（HID）**——扫码枪即键盘，输出 `beaconId` 到当前输入框；
   程序全局拦截「回车提交 + 前缀匹配」，无需驱动、离线可用（推荐现场标配一支）。
2. **备用路径：手动输入** `beaconId`（含模糊提示，列出未入库项）。
3. **可选路径：摄像头扫码**——`MediaCapture` + `ZXing.Net` 解码；无摄像头时自动隐藏该入口。
4. 解析：`trim` 后必须匹配 `^[A-Za-z0-9-]{1,20}$`，且在本地台账中存在对应 `beaconId`；
   否则提示「不是本场地信标标签」，不进入任何写流程。
5. 二次确认：任何写入前都展示 `短码 / beaconId / 三元组`，扫码结果不能直接触发写入。
6. 二维码内容如需变更（例如未来加 `siteId`），必须同步 §5.5 生成器与程序校验正则，并升级程序版本。

## 7. P2 —— 新建 `scripts/validate_beacon_provisioning.py`（离线一致性报告）

**三方比对**：

| 来源 | 字段 |
|---|---|
| ① 真实部署台账 `deployment-records` | 实际写入值与校验结果（per beaconId） |
| ② 规划台账 `result/ble_deployment.json` | 规划值（uuid/major/minor/floor/txPower/interval） |
| ③ 地图包 `backend/maps_data/<site>/<version>.json` 的 `beacons` | 客户端/后端实际消费的解析表 |

| 规则 | 级别 | 内容 |
|---|---|---|
| P-R1 | ERROR | 规划台账 `beaconId` 未出现在真实部署台账（未入库） |
| P-R2 | ERROR | `verify.passed != true`（未通过“扫描 + 连接全量”校验） |
| P-R3 | ERROR | 真实台账与规划台账的 **三元组不一致**（`uuid/major/minor` 必须完全等于规划） |
| P-R4 | ERROR | 任一来源内 `(major,minor)` 重复（UUID 统一下等价于三元组重复） |
| P-R5 | ERROR | 规划台账 `major` 与地图包 `major` 不一致（G1 类回归） |
| P-R6 | WARN | 真实台账 `txPower` 与规划不一致（现场调整，需有 `source=field_edit` 记录） |
| P-R7 | WARN | 扫描到陌生 iBeacon |
| P-R8 | WARN | 规划内却未部署（无现场扫描记录） |
| P-R9 | WARN | 真实台账 `broadcastInterval` 与规划不一致（现场调整，需有 `source=field_edit` 记录） |
| P-R10 | WARN | 真实台账缺少 `deviceMac`（审计信息缺失） |
| P-R11 | WARN | 设备名与 `deviceName` 不一致（标签/名称识别对账失败） |

**输出**：`result/beacon_provisioning_report.json` + 控制台摘要；ERROR 非零退出，
可作为地图发布 gate。

**实现与用法（2026-10-31）**：

```powershell
python backend/scripts/validate_beacon_provisioning.py --site school-building-01
# 可选：--db backend/.local/pathai.db  --map <版本包>  --scan <扫描快照.json>
```

- 真实台账读 SQLite `beacon_deployment_records`；规划台账与地图包默认取最新；
- `--scan` 提供时校验 P-R7/P-R8，缺省则记录一条跳过说明；
- 发布前建议先跑该命令，ERROR=0 再发布（是否强制阻断待决策 14）。

## 10. 风险与边界

| 风险 | 应对 |
|---|---|
| 反编译结论与固件实现有偏差 | 已按 jar 逐字段核验；P1-a 用 1 枚真机复核写入与读回，成功后再批量；厂商 App 兜底 |
| `FFF5` 档位码表因固件而异 | 写入前先读 `FFF5` 码表，按 -12 dBm 选码，不硬编码；台账记录实际码值 |
| 旧设计文档协议误导 | 已将 `a3c875xx`/AES/Slot 标注作废；实现仅以 `Protocol_Verified` 为准 |
| Windows GATT 缓存 / 适配器差异 | 全程 `BluetoothCacheMode.Uncached`、断开即 `Dispose`；目标机型先验证；异常时换外置 USB BLE 适配器 |
| WinRT 同时扫描+连接冲突 | 连接前先 `watcher.Stop()`；连接失败重试 1 次并提示 |
| 笔记本无蓝牙/蓝牙关闭 | 启动即检查适配器与开关，未就绪禁止进入扫描 |
| 多台信标同时广播 | 允许；写入只作用于选中设备的 GATT 会话，MAC 记录用于对账 |
| 设备名 7 字符放不下 beaconId | 使用短码 `F{floor}-{minor后三位}` + 物理标签（§6.7） |
| admin 会话权限过大（笔记本丢失/借用） | 专用现场笔记本；入库结束即 `logout`；会话 8h 自动过期；`env != local` 强制 HTTPS |
| 二维码贴错/磨损/扫不出 | 标签同时印 `beaconId` + 短码；USB 扫码枪 + 手动输入双路径；写入前展示三元组二次确认 |
| 旧标签与换版台账不一致 | 标签页与 `GET /beacons` 同源生成；扫码只定位、参数一律取台账；换版后重打标签 |
| 写错设备 | 选中设备 + 扫码/标签核对 + 写前展示三元组 + 回扫校验 |
| 已入库 beaconId 被重复选择 | 参数页只列未入库；服务端按 `beaconId` 幂等 upsert |
| 离线或上传失败 | 本地 SQLite 队列持久化，恢复网络重试；换机前清空队列 |
| 现场编辑导致与规划差异 | 仅允许 `txPower/broadcastInterval`；`source=field_edit` 留痕；P2 告警 |
| 设备有密码/密码被改 | 入库/编辑均不改密码；未知密码只能用厂商 App 恢复出厂（需物理接触） |
| 反编译协议的合规 | 仅用于本项目自有信标配置、不二次分发；若厂商提供 Windows SDK，优先替换自实现协议 |

**协议（反编译核验，唯一依据见 `docs/reference/Minew_E5_BeaconAdmin_Protocol_Verified.md`）**

| 用途 | 特征值 | 格式 |
|---|---|---|
| 服务 | `0000fff0-…` | — |
| UUID | `fff1` | 16B（UUID 文本序） |
| Major / Minor | `fff2` / `fff3` | 2B 大端 |
| 校准 RSSI@1m | `fff4` | 1B 有符号（只读） |
| 射频功率 | `fff5` | 1B 档位码（先读码表） |
| 密码 | `fff6` | ASCII（不改） |
| 广播间隔 | `fff7` | 2B 大端（300 = `0x012C`） |
| DeviceID | `fff8` | 4B（不碰） |
| 设备名称 | `fff9` | ASCII |
| 软关机 | `fffb` | 1B `0x00`（不开放） |
| 广播模式 | `fffe` | 1B（不动） |
| 提交生效 | `ffff` | 密码 ASCII |

**WinRT API**

| 环节 | API |
|---|---|
| 适配器 | `BluetoothAdapter.GetDefaultAsync()` |
| 扫描 | `BluetoothLEAdvertisementWatcher`（`ScanningMode.Active`）+ `Received` |
| 广播解析 | iBeacon：company `0x004C` + `0x02 0x15`；另取 `LocalName` / `BluetoothAddress` / `RSSI` |
| 连接 | `BluetoothLEDevice.FromBluetoothAddressAsync(addr)`；`GetGattServicesForUuidAsync(..., Uncached)` |
| 读写 | `GattCharacteristic.ReadValueAsync(Uncached)` / `WriteValueWithResultAsync(...)` |
| 释放 | 断开后 `Dispose()`（规避 GATT 缓存） |
| 登录鉴权 | `POST /api/v1/admin/auth/login` → Cookie + `csrfToken`；写请求带 `X-Admin-CSRF`（§5.4） |
| 扫码 | USB HID 扫码枪（主）/ 手动输入（备）/ `MediaCapture` + `ZXing.Net`（可选） |
| 标签生成 | `segno`（§5.5） |

**配置参数范围**：写 `uuid / major / minor / txPower / interval / name`（`FFF1/2/3/5/7/9` + `FFFF` 提交）。
