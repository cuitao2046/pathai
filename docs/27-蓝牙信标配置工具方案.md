# 蓝牙信标配置工具技术方案

> 文档版本：1.0 ｜ 2026-10-27 ｜ 状态：**待评审**（本文只出方案，不含实现）
> 关联：`docs/07-信标部署方案.md`（§5 参数配置、§6 台账）、
> `docs/08-信标部署与指纹采集实施方案.md`（§3.1.6 现场实施）、

## 1. 背景与目标

信标（RF-B-SR1）部署到场后，需要用手机 App 经 BLE 连接、逐台写入 AT 指令，把出厂默认参数
改成部署方案要求的值。当前**只有一份手工粘贴用的 markdown 清单**，且该清单基于已废弃的历史布点方案。

**目标**：建立「台账 → 配置指令 → 现场写入 → 写后校验 → 一致性报告」的闭环工具链，
使 61 枚信标的参数配置**可批量生成、可校验、可追溯**，消除手工抄错与漏配。

**不做**：不改信标固件、不做 OTA、不替代厂商 App 的底层能力、不引入 PC + USB 蓝牙适配器的现场方案
（现场只有手机）。

---

## 2. 现状与缺口（均为实测）

| # | 缺口 | 实测证据 |
|---|---|---|
| G1 | **清单不覆盖现行台账** | 最新清单 `beacon_at_commands_trilateration_routes.md`（66 枚）仅覆盖现行 61 枚中的 **53 枚**，缺全部 **8 枚 `BK-M-*` 人工补点**（清单内 `BK-M-` 命中 0 次） |
| G2 | **生成器读不到现行台账** | 脚本读顶层 `d["uuid"]`；而 `result/ble_deployment.json` 顶层仅 `schemaVersion/generatedBy/generatedAt/beacons/summary` → **KeyError**，UUID 须改从 `beacons[0].uuid` 取 |
| G3 | **Major 会写错** | 脚本用 `hex4(floor)` 当 Major；台账中 `BK-M-2-001/002` 是 **floor=2 但 major=1**（minor 20001/20002）。按 floor 写 `0002` 与地图包/客户端三元组解析不一致（`major=1` 共 54 枚、`major=2` 共 7 枚，**major ≠ 楼层**） |
| G4 | **清单内 minor 与台账漂移** | `BK-TR-F2-001/002/003` 清单写 `27B3/27B4/27B5`，台账为 `27AE/27AF/27B0` —— 该组已重编号但清单未重生成 |
| G5 | **`AT+NAME` 超长** | 手册规定名称**最大 11 字节**；清单为 10 枚 `BK-TR-Fx-00x`（12 字节）生成了 `AT+NAME=BK-TR-F1-001`，**设备会返回 ERROR**（清单合计 18 行违规） |
| G6 | **全手工、无状态、无留痕** | 逐台 nRF Connect 连接、逐条复制粘贴，无「已配置/未配置」状态，无操作人/时间记录；`RSSI@1m` 补码靠人工 `(256+RSSI)&0xFF` 心算 |
| G7 | **写后无校验** | 无「回扫确认广播三元组 == 台账」步骤；配错只能在联调阶段由定位异常倒查 |

**结论**：需要 3 个工具（下述 P0/P1/P2）。其中 **G5 是当前最紧急的**——照现有清单执行，10 枚信标
的设置命令会直接失败，且现场不易察觉（`AT+NAME` 失败但后续 `AT+BEACON` 成功会让信标"看起来配好了"）。

## 3. 要配置的参数（权威口径）

来源：手册第 9~17 页 + `docs/07` §5 + 现行台账实测。

| 参数 | 取值 | AT 指令 | 依据 |
|---|---|---|---|
| 设备名称 | `beaconId`，**≤11 字节** | `AT+NAME=<名>` | 手册 P10（超 11 字节报错） |
| iBeacon 参数 | `CompanyID=004C`、Major、Minor、RSSI@1m、UUID | `AT+BEACON=004C,<Major4>,<Minor4>,<RSSI1m>,<UUID32>` | 手册 P13 |
| 发射功率 | 统一 **-10 dBm**（档位 -28/-20/-10/-5/-3/0/1/2/4/6，无 -8/-12） | `AT+POWER=-10` | 手册 P16、docs/07 §5.1 |
| 广播间隔 + 模式 | **300 ms**（门口 400 ms）、**模式必须 =1（可连接）** | `AT+ADS=,1,<ms>` | 手册 P11 |
| Beacon 模式 | **=0 iBeacon**（默认值，须确认未被改成 Eddystone） | `AT+MODE=0` | 手册 P12 |
| 鉴权 | **保持关闭**（`AT+AUTH=0`）；如启用须每次连接后先鉴权 | `AT+AUTH=0` | 手册 P16 |
| 广播加密 | **保持关闭** | `AT+ENCRYPT=0` | 手册 P11 |

现行台账统一值（61/61 一致）：`uuid=B9407F30-F5F8-466E-AFF9-25556B57FE6D`、`txPower=-10`、
`broadcastInterval=300`、`minor ∈ [10001, 20002]`。

**现场通信约束**（手册 P9）：AT 指令**只能通过 App 发送**、**必须大写**、**不带回车换行**、
主机端 **MTU 须 ≥128 字节**、除鉴权外**立即生效且掉电保存**（无需 SAVE/RESET）。

**编码规则**（手册 P13 备注）：参数 1/2/3/5 的前导零**不能省略**——Major 设为 1 必须写 `0001`
（写 `1` 或 `01` 返回 ERROR）；RSSI@1m 为**有符号字节**，负值取补码（-62 → `C2`）。

**危险操作**：`AT+ADS` 参数 2 一旦设为 `0`（不可连接广播），**将永久无法再修改任何参数**（手册 P11 明确备注）。

## 4. 方案总览

```
result/ble_deployment.json ──┐
（现行台账，唯一事实源）      │
                             ├─► P0 gen_beacon_at_commands.py（改造）
backend/maps_data/…/<ver>.json（地图包 beacons）│      │
                             │      ├─► docs/reference/beacon_at_commands_ledger.md（61 枚配置指令）
                             │      └─► result/beacon_provisioning_plan.json（机器可读配置计划）
                             │
                             └─► P1 beacon-provisioner（新微信小程序，现场主力）
                                    │  扫描 → 连接 → 写 AT → 回扫校验 → 记录
                                    └─► 导出 result/beacon_provisioning_state.json
                                                │
                                                └─► P2 validate_beacon_provisioning.py
                                                       三方比对 + 阻断地图发布
```

设计原则：
1. **台账是唯一事实源**，工具不自行推断 Major/Minor/间隔（消除 G3）。
2. **生成（离线）与执行（现场）分离**：现场工具只消费生成好的配置计划，不做布点计算。
3. **写后必须回扫校验**，以「设备实际广播的三元组」为通过标准，而非「指令返回 OK」。
4. **一切留痕**：每条配置记录含操作人、时间、设备 MAC、写入值、校验结果、1m 实测 RSSI。

## 5. P0 —— 改造 `src/tools/gen_beacon_at_commands.py`

**定位**：最小改动、立即消除 G1~G5，先让现场有正确的清单可用。

### 5.1 改动点

| 项 | 现状 | 改为 |
|---|---|---|
| 输入源 | `result/beacon_deployment_plan_routes.json`（已不在仓库） | 新增 `--ledger result/ble_deployment.json`（默认）；保留 `--src` 兼容历史方案 |
| UUID | 顶层 `d["uuid"]` → KeyError | 从 `beacons[0].uuid` 取，并**校验全表 UUID 唯一性**（多于 1 个即报错） |
| Major | `hex4(floor)` | **`hex4(b.major)`**（取台账字段，消除 G3） |
| Minor | `b["minor"]` | `b["minor"]`（不变），但输出前**比对台账并断言一致** |
| 间隔 | `b.get("broadcastInterval", 400)` | `b["broadcastInterval"]`（台账恒有，缺则报错而非默认值） |
| 名称 | `AT+NAME={bid}` 无长度检查 | **≤11 字节校验**：超长时按映射表截断（见 §5.2），并在清单中标注原名 |
| 新增指令 | 无 | 补 `AT+MODE=0`、`AT+AUTH=0`、`AT+ENCRYPT=0`（幂等确认，防前次误配） |
| 输出 | 单一 markdown | markdown + `--emit-plan result/beacon_provisioning_plan.json` |
| 校验 | 无 | **预检**：三元组 (uuid,major,minor) 全表唯一、minor ≤ 65535、major ≤ 65535、名称合规、台账必填字段齐全；任一不过即非零退出 |

### 5.2 `AT+NAME` 超长映射（G5）

手册限 11 字节。10 枚 `BK-TR-Fx-00x`（12 字节）需改名。建议规则：
- 方案 A（推荐，短）：`TR-F1-001`（9 字节）——去掉 `BK-` 前缀，保留可读性；
- 方案 B：`BKT-F1-001`（10 字节）——压缩 `BK-TR` → `BKT`。

映射表写死在工具内并**在清单中同时打印原名与写入名**；台账不改（`beaconId` 仍是台账 ID，
设备名只是现场识别用的别名）。**必须在方案评审时二选一。**

### 5.3 输出物

**`docs/reference/beacon_at_commands_ledger.md`**（61 枚全覆盖）：逐枚目标值 + 四条 AT 命令 +
位置/坐标/安装方式（便于现场找位），文末保留 RSSI@1m 校准步骤。

**`result/beacon_provisioning_plan.json`**（P1 的输入契约）：

```jsonc

  "defaults": { "companyId": "004C", "uuid": "B9407F30-…FE6D",
                "txPower": -10, "interval": 300, "rssiAt1mPlaceholder": -59 },
  "beacons": [
    { "beaconId": "BK-01-001", "deviceName": "BK-01-001",
      "floor": 1, "major": 1, "minor": 10101,

      "locationDesc": "1F 电梯口（II-01#EL）· 门套或呼梯板旁",
```

## 6. P1 —— 新建 `beacon-provisioner` 微信小程序（现场主力）

**定位**：现场用手机完成「扫描 → 连接 → 写入 → 校验 → 留痕」，零安装、与既有
`fingerprint-collector` 同构（复用其 `openBluetoothAdapter` 写法与页面风格）。

### 6.1 目录结构（拟）

```
beacon-provisioner/
├── app.js / app.json / app.wxss         # 全局：场地标识、操作人、导入配置计划
├── data/provisioning_plan.js            # AUTO-GENERATED：由 result/beacon_provisioning_plan.json 转换
├── utils/
│   ├── ble.js                           # 适配器/扫描/连接/MTU/写特征值/notify 封装
│   ├── atcmds.js                        # AT 指令构造与编码（补码、前导零、名称校验）
│   └── pstore.js                        # 配置记录存储 + 导出 JSON
└── pages/
    ├── index/                           # 仪表盘：进度（已配/待配/失败）、操作人、导入计划
    ├── setup/                           # 核心：选目标 beaconId → 连接 → 逐条写 → 回扫校验
    ├── verify/                          # 批量校验：扫全场，比对实际广播 vs 计划
    └── export/                          # 记录复核 + 导出状态 JSON
```

### 6.2 核心流程（`pages/setup`）

```
1. 选目标：从计划列表选一枚（可按楼层筛选/搜索，未配置置顶）
2. 扫描：startBeaconDiscovery → 列出附近 iBeacon（uuid/major/minor/rssi/设备名）
   └─ 自动高亮「与目标三元组一致」的那一枚（若已配好 → 直接进校验）
3. 选择设备 → createBLEConnection（用 deviceId）
4. setBLEMTU(128)  ── 失败即中止（AT 无法设置，手册 P9）
5. 发现服务/特征值 → 打开 notify（读 OK/FAIL/ERROR/BUSY）
6. 逐条写 AT：
   - 每条写入后等 notify 响应，超时 2s 视为失败
   - 名称/Beacon 参数由 atcmds.js 生成（禁止手工输入）
   - 顺序：MODE → NAME → BEACON → POWER → ADS → AUTH → ENCRYPT
   - 任一条返回 FAIL/ERROR → 中止并提示具体指令（不留半配状态）
7. 断开 → 回扫校验：重新 startBeaconDiscovery
   └─ 断言 (uuid, major, minor) == 计划值；失败标红并要求重配
8. 写入记录（见 §6.4）
```

### 6.3 状态机

```
idle → connecting → mtuReady → writing(n/7) → verifying → done
                                   │                        │
                                   └── failed(reason) ◄─────┘（校验不通过）
```

### 6.4 数据契约：`result/beacon_provisioning_state.json`

```jsonc
{
  "schemaVersion": "1.0",
  "type": "beacon_provisioning_state",
  "planSha256": "…",                       // 对应 plan 的 sha256，防计划与记录错配
  "operator": "张三",
  "device": { "model": "…", "system": "…", "platform": "android" },
  "exportedAt": "2026-10-27T…Z",
  "summary": { "total": 61, "configured": 40, "verified": 38, "failed": 2, "pending": 19 },
  "records": [
    { "beaconId": "BK-01-001", "deviceMac": "8A:E5:84:7A:E7:C9",
      "deviceName": "BK-01-001",
      "configuredAt": "2026-10-27T09:12:33Z",
      "written": { "uuid": "B9407F30-…FE6D", "major": 1, "minor": 10101,
                   "txPower": -10, "interval": 300 },
      "rssiAt1m": -62,                      // 现场 1m 实测（AT+RSSI 或扫描读数）
      "verify": { "passed": true, "observed": { "uuid": "…", "major": 1, "minor": 10101 },
                  "at": "2026-10-27T09:13:05Z" },
      "error": null }
  ]
}
```

### 6.5 安全护栏（必须实现）

| 护栏 | 说明 |
|---|---|
| **禁止下发 `AT+ADS=,0,…`** | 代码层硬编码模式位为 1；UI 不提供间隔以外的可编辑项。置 0 后设备**永久不可连接**（手册 P11） |
| MTU 门禁 | `setBLEMTU(128)` 失败即中止，不允许"试试看" |
| 命令白名单 | 只允许 `MODE/NAME/BEACON/POWER/ADS/AUTH/ENCRYPT` 与查询类 `?` 指令；**禁止 `AT+RESET`、`AT+MAC=`、`AT+AUTH=1`** |
| 三元组占用检查 | 写前检查目标 (uuid,major,minor) 是否已被其它信标占用（防两台配成同一 ID） |
| 名称长度校验 | 写前按 11 字节上限校验，超长即拒发（消除 G5 类错误） |
| 二次确认 | 写入前弹出「目标 beaconId + 将要写入的 7 条指令」供确认 |
| 断线保护 | 写入中掉线 → 标记 `failed`，重连后**从第一条重写**（AT 指令幂等，重复写安全） |

### 6.6 RSSI@1m 校准（把人工心算做成工具能力）

现流程：站 1m 处读 RSSI → 人工算补码 → 手工替换第 4 参数 → 重发（docs/08 文末）。
改造为：站 1m → 点「读取 1m RSSI」（可多次取中位数）→ 工具自动转补码 hex → **自动重发
`AT+BEACON`（仅第 4 参数变化）** → 记录写入 `rssiAt1m`。

> 说明：仓库当前定位算法走**三点定位**，`rssi_to_distance` 用的是 `txPower`（-10）而非
> `RSSI@1m`（见 `location_solver.py`），故 `RSSI@1m` **不影响现行解算**，属"为未来指纹/距离
> 类逻辑预留"的可选项。建议**抽测 5~10 枚填典型值**即可，不必逐枚校准。

### 6.7 批量校验（`pages/verify`）

不连接、只扫描：把扫到的所有 iBeacon 三元组与计划比对，输出三类结果——
「计划内且一致」「计划内但值不符」「扫描到但不在计划内（陌生信标）」。
用于**安装后整体验收**与**换电池后抽检**。

## 7. P2 —— 新建 `scripts/validate_beacon_provisioning.py`（离线一致性报告）

**定位**：把「配置状态」纳入发布门槛，与地图发布流程衔接。

**三方比对**：

| 来源 | 字段 |
|---|---|
| ① 配置状态 `beacon_provisioning_state.json` | 已配/已校验的 beaconId 与实际写入值 |
| ② 现行台账 `result/ble_deployment.json` | 应有值（uuid/major/minor/floor/txPower/interval） |
| ③ 地图包 `backend/maps_data/<site>/<version>.json` 的 `beacons` | 客户端/后端实际消费的解析表 |

**校验规则**（沿用 `validate_beacon_deployment.py` 的 R 编号风格）：

| 规则 | 级别 | 内容 |
|---|---|---|
| P-R1 | ERROR | 台账 `beaconId` 未出现在配置状态中（漏配） |
| P-R2 | ERROR | 配置状态 `verify.passed != true`（未通过回扫校验） |
| P-R3 | ERROR | ②③ 的 (uuid,major,minor) 不一致（地图包与台账漂移） |
| P-R4 | ERROR | 任一来源内三元组重复（两台信标配成同一 ID） |
| P-R5 | ERROR | 台账 `major` 与地图包 `major` 不一致（G3 类回归） |
| P-R6 | WARN | 已配但 `rssiAt1m` 为空（未做 1m 校准） |
| P-R7 | WARN | 扫描到陌生 iBeacon（不在计划内） |
| P-R8 | WARN | 计划内却未在 `state.json`（未部署） |

**输出**：`result/beacon_provisioning_report.json` + 控制台摘要；ERROR 非零退出，
可在发布流程中作为 gate（**地图发布前跑一次，避免把错配的信标表发上线**）。

## 8. 测试策略（按 `docs/开发规范.md` §4）

| 层 | 用例 |
|---|---|
| P0 生成器（pytest） | Major 取台账而非 floor（含 `BK-M-2-001` floor=2/major=1 回归）；UUID 从 `beacons[0]` 取；minor 与台账一致；名称 >11 字节被拒或按映射截断；补码编码（-57→C7/-62→C2/-59→C5）；前导零（Major=1→`0001`）；三元组重复即报错；61 枚全覆盖 |

## 9. 实施顺序与依赖

## 10. 风险与边界

| 风险 | 应对 |
|---|---|
| **`AT+ADS` 误置 0 → 设备永久失联** | 代码层禁止（§6.5）；清单与 UI 均不暴露模式位 |
| iOS/Android BLE 写特征值行为差异 | 现场实测两种机型；写入后以 notify 响应为准，不假设"写了就成" |
| 部分机型 `setBLEMTU` 不支持/返回失败 | 明确中止并提示换机，不降级降 MTU（手册要求 ≥128） |
| 信标出厂 `AT+AUTH` 已被启用 | 工具提供"输入鉴权密码"入口；若不知道密码只能 `AT+RESET` 恢复出厂（需物理接触、重新配） |
| 同一操场存在其它项目 iBeacon（陌生信标） | `pages/verify` 区分"计划内/计划外"，不误配陌生设备 |
| 微信 `startBeaconDiscovery` 后台限制 | 仅前台作业（与 `fingerprint-collector` 一致），工程上不承诺后台扫描 |
| 厂商 App 与自研工具的差异 | 自研工具**不做**厂商 App 未覆盖的能力；`AT+NAME` 改名后设备默认名 `RFstar_XXXX` 变化，需在场地申请/台账中说明 |

## 附录 A：AT 指令速查（摘自手册 P9~P17）

| 指令 | 用途 | 本项目取值 |
|---|---|---|
| `AT+NAME?` / `AT+NAME=<名>` | 设备名称，**≤11 字节** | `beaconId`（超长走映射） |
| `AT+MAC?` | 查 MAC（16 进制字符） | 只读，用于留痕 |
| `AT+ADS?` / `AT+ADS=,<模式>,<间隔ms>` | 模式 0 不可连接 / 1 可连接；间隔 200~10240 ms | `AT+ADS=,1,300`，**模式恒为 1** |
| `AT+MODE?` / `AT+MODE=0\|1` | 0=iBeacon（默认）、1=Eddystone | `AT+MODE=0` |
| `AT+BEACON?` / `AT+BEACON=<CID>,<Major4>,<Minor4>,<RSSI1m>,<UUID32>` | iBeacon 参数；前导零不可省；RSSI 负值取补码 | `AT+BEACON=004C,0001,2775,C5,B9407F30…FE6D` |
| `AT+POWER?` / `AT+POWER=<dBm>` | 档位 -28/-20/-10/-5/-3/0/1/2/4/6 | `AT+POWER=-10` |
| `AT+AUTH?` / `AT+AUTH=<0\|1>,<密钥>,<秒>` | 用户鉴权（连接后须先鉴权） | 保持关闭：`AT+AUTH=0` |
| `AT+ENCRYPT?` / `AT+ENCRYPT=<0\|1>,<16字节密钥>` | 广播数据加密 | 保持关闭：`AT+ENCRYPT=0` |
| `AT+RSSI` | 查当前连接信号强度（dBm），每调用返回一次 | 1m 校准采样 |
| `AT+VERSION?` | 固件版本（如 `SR1_V1.1_2025.03.11`） | 只读，用于留痕 |
| `AT+RESET` | 恢复出厂并重启（连接中立即断开） | **工具禁用**（需人工评估后手工执行） |

响应：`OK` 成功 / `FAIL` 失败 / `ERROR` 指令错误 / `BUSY` 忙（等待上一条）。
写入特征值：Nordic UART **RX `6E400002…`**（写入通道，参考 `docs/reference/beacon_at_commands_*.md`）。
