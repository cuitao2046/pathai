## ⚠️ git 目录误删 bug 再次触发 + 恢复（本次合入期间）
- 触发组合：`git checkout -b`(切新分支) + `git branch -d`(删本地分支) + `git push origin --delete`(删远端分支) 三者连续执行，触发 MEMORY 记录的「git 目录误删 bug」。
- 现象：`git status` 突现 21 个已跟踪文件变为 ` D`（物理缺失）：`.workbuddy/memory/2026-08-04~13.md`(12) + `MEMORY.md`(1) + `debug/*.py`(8)，HEAD 中仍存在（对象库完好）。
- 即时恢复：`git checkout HEAD -- .`（从对象库取回全部已跟踪文件到工作树，MEMORY 推荐手段）→ exit 0。
- 权威验证：`git diff HEAD --quiet` 返回 0 ✅ 工作树与 HEAD 完全一致；`git status` 仅剩 3 个 `ble_refine_*` 未跟踪调试产物。
- 注意：Git Bash 下 `[ -e ]` / `test -s` / `git cat-file -e HEAD:"$中文路径"` 对中文路径会**编码误报缺失**，但 git status/diff 自身校验可靠——勿被误报警慌。
- 经验补充：除 MEMORY 已记的「checkout + cherry-pick 双触发」外，**「切分支 + 删分支（本/远端）」组合亦会触发**。规避建议：删分支与切分支之间穿插其他操作，或删分支后用 `git checkout HEAD -- .` 立即自检一次。
