## 手动骨架 SVG 导入 + F2 连通修复

用户用红色 `<path>`(自由曲线) 在 `C:/Users/xinni/Downloads/pathai-skeleton.svg` 画了 F2 南北连廊，但 F2 一直 69–72% 孤立(南簇 47 节点)。排查链路：

1. **根因① `_path_to_points` 只读首控制点 + 忽略相对命令**：连廊是相对 `m/c/l` 命令的 path，旧解析函数只取每段贝塞尔首控制点当终点，整条 path 错乱 → 连廊从未被读入。重写为正确解析相对 m/l/c/s、贝塞尔按 6 步采样、RDP(eps=1.5m) 抽稀(保留首尾端点供吸附)。
2. **根因② 端点未吸附既有 TI**：手绘线端点与既有 TI 重合(0.01m)却生成坐标重合、id 不同的幽灵节点 → 连廊成 size=2 孤岛。`build_from_lines` 加 `snap_to_existing`(tol=0.8m)，端点复用既有 TI id。
3. **根因③ 小缺口**：连廊南端距南簇入口 0.64m(手绘留 0.5–0.7m 缝)，重导后无连边。`build_from_lines` 末尾加**缺口缝合**：同层内分属不同分量、<2m 的 TI 自动补边(仅跨分量，不误连同分量并行走廊)。
4. **根因④ 旧坏 apply 幽灵污染**：上次坏解析的 `--apply` 残留幽灵 TI(F2-TI-0075) 在 geojson 里，新 path 吸附到幽灵而非真南簇。→ 重导前先 `cp debug/backup_geojson_before_manual_skel.geojson result/...geojson` 恢复干净自动拓扑再 apply。

结果(新生 geojson)：F1/F2 均 **100% 连通、单分量**；F2 南簇房间(原孤岛)→北簇 46.3m 可达；全部 39 个 F2 房间可达；跨层边 10 不变；校验 PASS。

## 前端 Dijkstra 对齐 route_rules（Task #17）+ 全量校验（Task #18）

`render_interactive.py` 前端路由此前与后端 `route_rules.py` 三条规则不同步（同层允许 facility 中转、无门优先级、无 room↔room 防护、无穿墙剔除）。本次对齐：

1. **新增模块级辅助** `compute_route_rule_extras(geo)` + `_seg_crosses_wall`：在 Python 端预计算并注入 PATH_GRAPH——每边 `doorType`(从门节点推导)、每房间 `bestDoorType`、穿墙 TI↔TI 边集合 `wall_crossing_titi`（11 条，与后端一致）。前端无需访问墙体几何即可剔除穿墙边。
2. **PATH_GRAPH 注入字段**：节点补 `doorType/rooms/roomType/roomId/bestDoorType`；边补 `type/crossFloor/doorType/wallCrossing`（同层边也带 `type=null`、`crossFloor=false`）。
3. **前端 `dijkstra` 重写**对齐后端：
   - `MID_TYPES` 按同层/跨层切换（同层 `{intersection,facility_entrance,doorway}`，跨层 +`facility`）→ 规则 1。
   - `edgeAllowed` 补盲模式 `crossFloor && type==='staircase'` 剔除 → 规则 2。
   - 门类型边权惩罚（room↔door 边，swing0/fire0.5/opening1）、房间仅用≥自身最佳门的门、room→door→room 穿透防护 → 规则 3。
   - 剔除 `wallCrossing` 边（默认不穿墙）+ 三层回退（最佳门→所有门→穿墙边 wall_fallback，回退标 `note`）。
   - 距离按后端 `round(...,2)` 对齐。
4. **验证**：新建 `debug/verify_frontend_parity.py`——用真实 PATH_GRAPH 在 Node 执行前端 dijkstra，与后端 route_rules 逐条比对。6/6 通过（同层 room→room 的 normal/blind、跨层 normal/blind/wheelchair、同层 room→facility），且规则不变量全 PASS（同层无 facility 中转、盲跨层无楼梯、无 room→door→room 直连）。`validate_geojson`→PASS，`verify_route_rules`→全部通过 ✅。

# 经验
- 前端/后端双实现同源的关键：把「依赖外部几何(墙体)的计算」(穿墙边集合、门类型)在 Python 端预计算并随数据注入，JS 只做纯拓扑判定——避免在前端重复几何库，且保证两端逐字节一致（用 Node 实跑比对验证）。
- 距离四舍五入差异也会让"路径等价"测试 FAIL：前端返回原始 float、后端 `round(...,2)`，比对前须统一精度。
