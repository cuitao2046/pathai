## 简化门洞（DK → opening）识别规则

用户反馈：卫生间通往公共空间的门洞丢失（之前 F1 仅 8、F2 仅 4）。明确**门洞 = window 图层中带 DK 矢量 strokes 文字标注的部分**，DK 标注在 CAD 中可有 4 个旋转方向（0°/90°/180°/270°，门外圈字标按室内阅读者放置），DK 识别本身已由旋转无关的 `is_dk_block` 处理。

**改动（`src/parse_cad_pdf.py`）**：
1. **移除 `_opening_in_scope` 范围过滤**——它只保留卫生间/楼梯间附近 30pt 内的 opening，**绝大部分洞口**（尤其卫生间通往过道/公共空间）都被它误丢。删除该段（连带 `OPENING_SCOPE_PT`、`toilet_polys+stair_polys` 局部使用）。
2. **`_door_is_internal_core` 首行豁免 opening**：函数首个判据改为 `if kind=="opening": return False`（门洞两侧皆通行，不算"内部隔断门"），仅对 swing/fire 检查核心内部隔断。该步让男↔女卫生间内部 DK 开门、卫生间→设备间 DK 开门等被全部找回。
3. **重写 `find_wall_openings`**：删除"对所有摆弧门中心近邻 <18pt 跳过"的全局避让（这条过去会因相邻不同门洞误删），**保留**「距 swing_centers < DK_NEAR_ARC_PT 才跳过」（避免普通门编号被误当洞口）；修复 wall 吸附分支缩进 bug（原代码无 `gap` 时墙吸附不可达，导致该分支永远死代码）；目标签名 `find_wall_openings(dk_blocks, all_segs, wall_gaps=, swing_centers=)` 简化。
4. parse_floor 调用同步更新（去掉 `window_groups`/`doors` 形参）。

## 严格 DK 识别——按字符列验证 D/K（第 3 轮修复）

用户反馈：v9.1 仍把非 DK 开头的 window 元素误判为 DK（旧 `is_dk_block` 仅用「左 40%
有竖笔 + 中段有对向斜线」的笼统区域判定，M1524/C01224/甲1224 都可能满足）。

**改动（`src/parse_cad_pdf.py`）**：
- `is_dk_block` 重写为**按字符列逐一验证**：
  - 沿书写轴向把块内笔画聚成字符列（水平书写按 x，竖排按 y），与 `_glyph_vertical_angle` 配合覆盖 4 个旋转方向
  - 第 0 列 = D：有长竖茎 + 茎右侧有弧线笔画（不多设竖茎数上限——CAD 中 D 弧线由 2-4 段近竖直短划组成）
  - 第 1 列 = K：有长竖茎 + 同时存在上下对向斜线
  - 必须同时满足两个列的条件，且列紧邻
- 删除 `_cluster_x_columns`（旧版字符分列，被新的 `_cluster_along_axis` 取代）
- 新增 `_cluster_along_axis(feats, axis='x'/'y', gap=4.0)` 按轴聚笔画为字符列

**诊断验证**：在放开竖茎上限后，DK 识别 F1 从 52→20、F2 从 51→27（~60% 减少）。
拒绝原因分布完全是真实的非 DK 字形：`block_too_narrow`（太窄标签）、`d_no_vert`（无 D 茎）、`d_no_right_arc`（非 D，可能是 M/1/2 等）、`k_no_vert`（数字位）、`k_no_opp`（无 K 斜线配对）。

## DK 旋转支持（180°/270°）+ 楼梯间房间并入（第 4 轮修复）

用户反馈：
1. 男卫生间/女卫生间 → 公共空间的 DK1224 元素未识别——截图显示 DK 文字倒置（180° 旋转）
2. II-WR-04 男卫生间 DK 元素未识别
3. F1 楼梯间 6 个 II-Bx-yz#ST DK 元素未识别
4. F2 楼梯间通往公共空间的 DK 组件未识别

**根因**：
- (1)(2) 180° 旋转的 DK 字符：旧 `is_dk_block` 要求 col[0]=D、col[1]=K，180° 旋转后 col[0]=K、col[1]=D，判定失败
- (3)(4) 楼梯间没有 roomType="staircase" 的房间，门归属把 DK 标记的门丢了

**改动**：
- `is_dk_block` 改为「相邻两列中存在 D-形 + K-形配对（顺序不限）」：
  - 新增 `_has_d_shape(col)` = 有竖茎 + ≥1 非茎笔画
  - 新增 `_has_k_shape(col)` = 有竖茎 + 上/下对向斜线
  - 接受 `(col0=D, col1=K)` **或** `(col0=K, col1=D)` 配对，覆盖 4 个旋转方向
- 在 rooms 列表中**追加 staircase 房间**：
  - 在 `parse_floor` 门去重之后、build_rooms 之前提前聚类 STAIR+A-FLOR-STRS 双层点
  - build_rooms 后追加 `R{楼层}S{idx}` 房间（roomType=staircase，bbox 即 stair_box）
  - 让门归属能找到楼梯间，DK 摆弧门重分类/无摆弧门洞生成都能命中楼梯
