## 简化门洞（DK → opening）识别规则

用户反馈：卫生间通往公共空间的门洞丢失（之前 F1 仅 8、F2 仅 4）。明确**门洞 = window 图层中带 DK 矢量 strokes 文字标注的部分**，DK 标注在 CAD 中可有 4 个旋转方向（0°/90°/180°/270°，门外圈字标按室内阅读者放置），DK 识别本身已由旋转无关的 `is_dk_block` 处理。

**改动（`src/parse_cad_pdf.py`）**：
1. **移除 `_opening_in_scope` 范围过滤**——它只保留卫生间/楼梯间附近 30pt 内的 opening，**绝大部分洞口**（尤其卫生间通往过道/公共空间）都被它误丢。删除该段（连带 `OPENING_SCOPE_PT`、`toilet_polys+stair_polys` 局部使用）。
2. **`_door_is_internal_core` 首行豁免 opening**：函数首个判据改为 `if kind=="opening": return False`（门洞两侧皆通行，不算"内部隔断门"），仅对 swing/fire 检查核心内部隔断。该步让男↔女卫生间内部 DK 开门、卫生间→设备间 DK 开门等被全部找回。
3. **重写 `find_wall_openings`**：删除"对所有摆弧门中心近邻 <18pt 跳过"的全局避让（这条过去会因相邻不同门洞误删），**保留**「距 swing_centers < DK_NEAR_ARC_PT 才跳过」（避免普通门编号被误当洞口）；修复 wall 吸附分支缩进 bug（原代码无 `gap` 时墙吸附不可达，导致该分支永远死代码）；目标签名 `find_wall_openings(dk_blocks, all_segs, wall_gaps=, swing_centers=)` 简化。
4. parse_floor 调用同步更新（去掉 `window_groups`/`doors` 形参）。
