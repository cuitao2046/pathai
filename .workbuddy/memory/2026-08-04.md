## 🚪 门洞(DK)识别规则修正 —— 楼梯间/卫生间门洞漏识修复

**用户规则（明确）**：门洞 = window 图层中带 **DK 矢量 strokes 文字标注**的部分。

**根因**：原 `find_wall_openings` 要求「墙缝(wall_gap) + 该处 60pt 内有 DK 块」双重条件。楼梯间/卫生间通往过道/公共空间的门洞常绘于家具隔墙或墙缝未被 `opening_gaps` 捕获，于是 DK 标注虽在却被整体丢弃；且旧 dedup 用 `dr["center"]`（摆弧门在墙上的中心）做 18pt 邻近跳过，会把「DK 块恰在某扇摆弧门 18pt 内」的**不同**门洞误删。

**诊断发现**（直方图）：F1 的 52 个 DK 块中 32 个落在 window 组 0–15pt 内 —— 这些门洞本身被 `classify_window_layer` 当成了「窗口」(类窗元素画在 window 层)，其 DK 标注又被旧「near window 跳过」规则删掉。

**最终方案**（`src/parse_cad_pdf.py`）：
1. 每个 DK 块：若距某 window 组中心 < 13pt（`DK_WIN_CONVERT_PT`）→ 该 window 组实为门洞，转成 `opening` 并从 `window_groups` 移除（不再当窗封口/渲染）；优先复用其几何轴与宽度。
2. 其余 DK 块 → `find_wall_openings`：优先复用邻近墙缝实测宽度，否则吸附到最近墙线段（结构层+家具层并集）、轴垂直墙、默认宽 30pt(`DEFAULT_OPENING_WIDTH_PT`)。
3. 全局 `dedupe_doorways`：仅当两门中心 <13pt(`MERGE_PT`) 才合并（开口轴⊥墙、摆弧轴∥墙，不能用轴平行判定，否则墙角误并）；优先保留摆弧门(swing/fire)。
4. 新增常量 `DEFAULT_OPENING_WIDTH_PT=30`、`DK_SNAP_WALL_PT=50`、`DK_DEDUP_PT=18`、`DK_WIN_CONVERT_PT=13`。

**结果**：门洞(opening)数量 F1 20→42、F2 30→37（合计 50→79）；geojson 通过 `validate_geojson.py`。交互 HTML 已重生成，普通门/门洞/防火门三类开关计数随之更新（F1: 73/42/55，F2: 40/37/34）。
