- **关联文档：** [spec.md](spec.md)、[checklist.md](checklist.md)

## Gate 0：规格审阅与决策冻结

- [ ] T-001 评审 `spec.md` 的范围、状态机、产品行为和排除项；经用户批准后标记规格版本。
- [ ] T-002 冻结首发场所、地图包 API schema、坐标/楼层约定、地点索引、信标映射及转换/验证/打包/复核/发布流程样例；不在对应地图契约冻结前实现转换工具。
- [ ] T-003 将已确定的强制微信登录落实到 API 契约：code 换 token、openid 主体绑定、令牌校验和会话所有权隔离。
- [ ] T-004 对 WechatSI 执行目标设备集成、权限/隐私数据流和失败降级验证；用户已确认可作为首期依赖。
- [ ] T-005 采用规格中的工程初始定位/导航默认值开展开发联调；制定现场采集、参数调优、验收指标与用户路径安全策略，未验证前不作为上线门槛通过。
- [ ] T-006 落实已建议的权限重试、未授权功能边界、候选选择确认、屏幕阅读器控件/语音替代；冻结目标设备/辅助技术版本及后台安全策略。
- [ ] T-007 完成 360 天脱敏分析数据的隐私/安全审查、账号删除及备份/日志到期清理方案；更新验收清单。
- [x] D-008 后端首期技术栈：Python 3.13+、FastAPI/Pydantic 2、Uvicorn、SQLAlchemy 2、Alembic；本地开发使用 SQLite，Demo 使用托管 PostgreSQL（psycopg 3）。通过环境配置显式选择数据库，禁止 Demo 静默回退 SQLite；数据库兼容查询以 PostgreSQL 集成测试验证。Demo 采用单体 API + 对象存储，不引入 Redis/消息队列/Kubernetes；托管厂商及密钥配置随部署环境冻结。

## Gate 1：接口和地图契约

- [ ] T-009 为 API-01..09 冻结机器可验证的请求/响应 schema、错误码、鉴权策略、幂等规则和版本行为。
- [ ] T-010 将现有扩展 GeoJSON 和信标部署数据转换为版本化 API 地图包；校验 schema、拓扑连通/视障可达性、地点/楼层/信标引用、摘要和发布清单，保存可重复构建记录。
- [ ] T-011 为定位、路线和指令生成建立可重复的基准数据与契约/回归测试。

## Gate 2：后端能力

- [ ] T-011 建立 API 服务基础：请求校验、requestId、统一错误、鉴权/会话所有权和幂等存储。
- [ ] T-012 实现发布地图与地点读取、版本/摘要和地点候选查询。
- [ ] T-013 实现受控意图解析；模型结果 schema 校验、地点消歧，禁止模型输出动作。
- [ ] T-014 实现 BLE RSSI 预处理、三点定位、质量分类、序号/新鲜度/地图版本检查，并运行现场参数回归。
- [ ] T-015 实现受限 Dijkstra 路由与规则回归；明确回退标志及首条受控指令。
- [ ] T-016 实现导航会话状态机、位置更新、偏航重规划、恢复、到达判定、查询和幂等结束。
- [ ] T-017 实现最小数据留存、脱敏日志、到期删除及授权安全测试。

## Gate 3：小程序能力

- [ ] T-019 实现权限/地图启动流程、WechatSI 接入及按住说话、播报队列和生命周期清理。

## 依赖关系

- Gate 0 的用户批准是进入实现的前置条件；微信登录、权限交互、导航/定位的工程默认值等已由规格给出，但现场校准、设备验证、隐私审查和发布门槛仍不可跳过。
- Gate 1 的地图/API 契约先于后端与客户端并行实现。
- T-010 的路线与定位基线分别是 T-014..016 的回归前置。
- 后端核心 API 和小程序可在契约冻结后并行开发；端到端联调依赖双方实现完成。
- 真机/现场/视障参与者安全门槛是受控试点的前置条件，而非普通单元测试的替代品。
