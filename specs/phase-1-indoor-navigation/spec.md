## 1. 目标与成功条件

为全盲或低视力用户提供非视觉主导的室内导航流程：用户启动小程序，获知权限及位置状态，通过按住说话指定地点并确认，由受控地图、定位和路线服务引导到目的地区域。到达、主动结束或无法安全继续时，系统明确反馈并停止导航专用采集。

成功条件：在已发布地图和信标覆盖的测试区域中，用户确认有效目的地后系统创建有效导航会话；系统仅在位置可信且路线有效时提供方向指令；到达由服务端规则确认并仅通知一次；主动结束或安全异常时不再播报过期方向指令。

## 2. 范围与边界

### 包含（第一阶段）

- 小程序启动、定位/蓝牙/录音能力检查、首次使用说明、位置状态播报。
- 按住说话、松开提交、客户端语音识别和合成（讯飞在线 WebSocket，签名 URL 由后端签发），以及受控意图解析；按住说话按钮位于全屏地图页下端居中，无独立语音首页。
- 地图版本及地点读取、地点候选澄清、用户确认。
- BLE 信标扫描与位置估计；导航会话、受限路径规划、导航指令、位置更新、恢复、重规划、结束和到达。
- 权限、网络、地图、定位、语音、生命周期异常的安全反馈。
- 微信登录主体、令牌、幂等、所有权校验与隐私最小化规则。

### 不包含

摄像头识别与动态避障；动态封路/施工、多场馆运营；地图管理后台 UI；紧急呼叫/救援；离线 ASR/TTS；大模型生成或控制路线动作；将系统作为专业出行辅助工具的替代品。

## 3. 规范性约束与术语

- **必须/不得**表示强制行为；**可以**表示允许行为。
- 用户的语音或大模型只用于理解意图与目的地。地点匹配、定位、路线、动作、到达状态由服务端受控逻辑及发布地图决定。
- API 中位置坐标单位为米、角度单位为度，时间采用 ISO 8601 UTC；传感器批次带单调递增序号。
- 每次会话固定一个不可变 `mapVersion`；地图、位置、路径和指令必须可追溯到该版本。
- 第一阶段定位算法为 BLE RSSI 三点定位（滑动窗口滤波、至少三个有效信标的三边交汇/最小二乘）；IMU 字段仅预留，不参与首阶段解算。不得把设计目标描述为已实现的惯性融合或地图匹配能力。
- 路线采用现有受限 Dijkstra：边权为几何距离与门惩罚；盲模式跨楼层仅允许电梯。内部寻路可以按“最佳门→所有门→穿墙边”诊断回退，但公开路线默认不得包含穿墙边；仅在受控测试配置显式启用时才可返回 `wall_fallback`，且必须标记并执行 REQ-NAV 的风险拦截。不得宣称多目标路线或分层 A* 已支持。规则以 `docs/05-路线规划算法.md` 为基准，产品安全限制以本规格为准。
- PathAI 后端不接收原始录音；ASR/TTS 由讯飞开放平台在线 WebSocket 提供（签名 URL 由后端签发、密钥仅存服务端），依赖网络与 socket 合法域名，不承诺离线能力。
- 低质量、过期或楼层不确定的位置不得驱动确定性转向或到达判断。宁可进入恢复状态，也不得猜测。

## 4. 系统边界

### 小程序客户端

权限和生命周期管理；无障碍触摸/双击与语音状态交互；讯飞在线 ASR/TTS（wss 直连，签名 URL 由后端签发）；BLE/IMU 数据采集（IMU 首阶段不用于定位解算）；地图版本缓存及完整性校验；请求 API；过滤过期播报；导航结束时释放采集资源。

### PathAI 服务端

首期强制微信登录；客户端通过 `POST /auth/wechat` 用微信临时 code 换取 PathAI 短期 Bearer token，服务端绑定并校验唯一 `openid` 主体。匿名访问不支持。所有需用户身份的 API、会话及定位/导航资源均校验该主体所有权；不信任客户端自报主体。令牌不写日志，失效后重新登录。登录不意味着采集或持久化额外微信资料。

#### 后端技术栈与运行依赖（Demo/小用户量）

- **运行时与 Web 框架**：沿用仓库 Python 3.13+；FastAPI + Pydantic 2，Uvicorn 作为 ASGI server。请求处理采用同步 SQLAlchemy Session/同步路由，避免首期为少量并发引入异步数据库复杂度；CPU 密集定位/路由不得在事件循环中执行。
- **数据库与迁移**：本地开发默认 SQLite（文件数据库）；Demo 使用托管 PostgreSQL。SQLAlchemy 2 + Alembic 管理模型和迁移；Demo PostgreSQL 驱动使用 psycopg 3，SQLite 开发使用 Python 内置 sqlite3。通过 `PATHAI_DATABASE_URL` 选择数据库：本地缺省可指向仓库忽略的 `backend/.local/pathai.db`；Demo 必须显式配置托管 PostgreSQL URL，缺失时启动失败，不得静默退回 SQLite。迁移及应用查询避免仅某一数据库支持的语法。数据库持久化用户主体映射、导航会话、幂等记录及必要的最小业务元数据；不将地图几何大文件存入数据库。SQLite 用于本地开发和快速测试，不作为 Demo/生产部署数据库。
- **数据库兼容性验证**：单元测试可使用临时 SQLite 数据库；涉及并发写入、幂等/唯一约束、事务隔离或数据库特定行为的集成测试必须在 PostgreSQL 上执行，Demo 发布前须通过托管 PostgreSQL 的迁移和冒烟测试。不得把 SQLite 测试通过当作 PostgreSQL 兼容性证明。
- **地图文件**：不可变地图包作为版本化 JSON 文件存储；本地开发使用文件系统适配器，Demo 使用对象存储；数据库只保存版本、摘要和对象地址等元数据。发布物均须验证 SHA-256。对象存储厂商/桶权限与生命周期策略在部署时冻结。
- **首期中间件/基础设施**：HTTPS 由部署平台入口/API Gateway 或反向代理终止；应用提供 requestId、统一异常/错误响应、Bearer 鉴权依赖、输入校验和脱敏结构化日志。生产环境入口负责 TLS、基础请求速率限制和请求体大小限制；微信小程序合法 request 域名按环境配置。导航幂等由数据库唯一约束/事务实现，并在 PostgreSQL 集成环境验证。
- **暂不引入**：Redis、消息队列、独立搜索引擎、Kubernetes。Demo/小用户量先以单体 API + PostgreSQL + 对象存储部署；只有实测负载或功能需要时再评估拆分/缓存。不得用进程内状态保存会话或幂等数据。
- 依赖版本通过锁定文件固定并在 CI 安全更新；密钥、数据库凭据和微信 AppSecret 由环境变量/部署密钥管理注入，禁止提交仓库或写日志。

### 外部依赖

微信小程序平台、讯飞开放平台语音服务（语音听写大模型 V2.0、超拟人合成；wss 合法域名与配额）、已发布的场所地图与信标部署。外部依赖失败不得产生虚假的成功状态。

## 5. 状态与不变量

### 客户端交互状态

`initializing`、`permission_blocked`、`idle`、`recording`、`processing`、`awaiting_confirmation`、`navigating`、`recovering`、`arrived`、`ended`。导航会话服务端状态是 `active`、`recovering`、`arrived`、`ended`，不可与客户端呈现状态混为一谈。

服务端允许迁移：`active ↔ recovering`、`active/recovering → arrived`、`active/recovering → ended`；终态不可逆。

### 必须始终成立

1. 未确认目的地不能创建活动导航会话。
2. 用户只能读写归属于自身的会话；会话的地图版本固定。
3. 小于已处理序号的位置批次不能回退导航位置或重复推进指令。
4. `unreliable` / `lost` 状态不提供普通方向指令；客户端必须停止播报缓存的过期转向。
5. 到达仅由服务端判断，单会话只触发一次；客户端不得伪报到达。
6. 结束/到达后停止导航专用 BLE/传感器采集和路线提示；恢复前必须重新取会话状态、检查权限和位置新鲜度。
7. 语音、视觉、触觉反馈按可用能力组合；颜色/图标不得作为关键状态唯一反馈。
8. API 错误按稳定 `code` 处理，不按 `message` 分支。

## 6. 功能规格

### REQ-BOOT 启动与位置状态（P0）

- 每次启动/回到前台时检查定位授权、系统定位服务、蓝牙状态、地图可用性及未结束会话。
- 首次启动按平台流程请求授权，播报授权结果和简短操作说明；拒绝时进入受限待命并解释如何重试。重试入口须在首页持续可达：提供可访问的“开启定位/蓝牙权限”操作，能调用平台设置页时引导用户前往设置；返回前台后重新检查状态。不得循环弹窗或将拒绝视作已授权。
- 未授权时仍可使用不依赖位置/蓝牙的功能：登录、语音输入、地点目录/搜索、候选选择、帮助与权限说明；不得查询或播报当前位置、创建导航会话或提供路线指引。语音输入所需麦克风权限仍按平台实际能力检查。
- 授权及依赖可用时加载最新发布地图、校验数据摘要并请求位置估计；仅播报由服务端质量及地图支持的楼层/语义区域。未知时播报无法确定位置。
- 获取或播报失败时给出明确原因与可执行重试/结束路径。

### REQ-PAGE 页面结构与主流程（P0）

- **首屏即全屏地图页**：启动完成权限与地图加载后直接呈现全屏楼层地图（已完成能力，保持）；
  不设独立语音首页，原语音首页（pages/index）退役，其能力全部并入地图页。
- **左上角竖向工具条**：设置、楼层选择、全图三个控件在地图页**左上角竖向排列**，
  按钮尺寸一致（宽度按三者文案中最宽者自适应，不设固定大尺寸），悬浮在地图上方；
  设置入口点击进入设置页进行 mock 相关数据设置（数据源 mock/live 等开关），
  设置写入本地缓存，按既定约定重启小程序后生效。入口在两种数据源下均可见，
  保证 live 模式可回切 mock。
- **楼层选择按钮横向展开**：楼层选择按钮常显当前楼层（如「1F」）；点击横向展开可选楼层，
  选中即切换并收起；展开的候选为浮层，**不改变设置/全图等按钮的位置**；
  地图上不再单独显示「一楼」之类文字角标，展开态中当前楼层按钮高亮（active）。
- **全图居中**：启动首屏与切换楼层后，地图均以**该层全图模式居中展示**（自动适配视口）；
  待命态不做位置跟随平移，导航态才收窄视野并跟随当前位置。
- **按住说话按钮居中于屏幕下端**：按住即开始、松开即提交
  （语义见 REQ-VOICE），其余区域持续展示地图。按钮须提供可访问的非视觉反馈与状态文案。
- **意图结果居中展示**：目的地找到后的确认卡片、候选澄清列表在地图页**屏幕居中**以浮层展示，
  与语音播报同步；候选点选、确认并开始、取消等交互沿用 REQ-VOICE/REQ-DESTINATION 语义。
- **导航态融合**：确认目的地后在同一地图页进入导航展示（见 REQ-NAV）；
  原独立导航页退役，其状态文案与"结束导航"等可访问控件以地图页浮层形式保留
  （REQ-A11Y 约束全部不变）。
- 客户端交互状态机（§5）不因单页化改变；各状态的进入/退出条件与反馈规则以对应 REQ 为准。

### REQ-VOICE 语音输入和意图（P0）

- 主交互热区按住开始语音输入，立即给出非视觉反馈；松开立即停止采集并提交识别。生命周期切换、音频中断、取消、失败时停止并释放录音资源。
- 客户端使用讯飞在线服务转写与播报：识别文本提交 PathAI，原始音频仅流向讯飞云、不进入业务后端。讯飞不可用、超时、网络失败或麦克风权限缺失时明确提示并允许重试，不静默改用未评审方案。
- `POST /intents/parse` 仅返回受控意图、结构化槽位、候选地点及澄清/确认文本。支持 `start_navigation`、`query_location`、`search_facility`、`cancel`、`end_navigation`、`repeat_instruction`、`unknown`。
- 歧义、低置信度、不存在地点或不支持意图必须澄清/失败，不得自动开始导航。`search_facility` 的“附近”排序仅在当前可信定位（`reliable` 且未过期）可用时按距离排序；否则按场馆配置的固定分类/名称顺序返回，并明确不代表附近。返回候选后用短列表逐个播报名称、楼层及序号；用户可说“第 N 个/名称”选择，系统复述所选项并要求确认，确认后才执行导航；取消、超时或输入无法匹配时留在待命/重新澄清，不默认选择首项。
- 大模型不能输出可执行动作、路线或地图中不存在的地标。服务端校验结构、地点 ID、地图版本和当前会话状态。

### REQ-DESTINATION 目的地确认（P0）

- 唯一有效地点播报名称和楼层并进入 `awaiting_confirmation`，确认卡片在地图页屏幕居中显示（REQ-PAGE）；多候选时语音列举有限候选、居中浮层同步列出候选，等待用户明确选择。
- 用户语音明确确认，或在确认态通过聚焦“确认并开始”控件触发屏幕阅读器双击/非屏幕阅读器双击才可继续；取消/否定/重新输入返回待命或识别流程。
- 确认时再次验证地图版本、权限、起点质量、目的地可达性及所需平台能力。任何检查失败不得创建活动会话，并返回可理解提示。

### REQ-MAP 地图与地点（P0）

- `GET /sites/{siteId}/map?version=latest` 返回不可变发布版本、楼层、坐标参考、HTTPS 数据地址及 SHA-256；支持 ETag 缓存。首版地图包由当前扩展 GeoJSON 与信标部署数据共同转换、校验、打包生成，使用仓库维护的流程，第一阶段不建设在线地图管理后台。GeoJSON 提供几何、语义、拓扑、跨层边及无障碍信息；信标部署数据提供 beacon ID、坐标、楼层及部署属性。规划点位与现场实际部署点位须在数据中区分并保留来源，不得将规划坐标误认为已安装位置。转换器将这些输入映射为冻结的 API schema；发布前校验 schema、拓扑连通/视障可达性、楼层/地点/信标引用、版本唯一性和摘要。发布物不可变，更新必须生成新 mapVersion 并走复核、测试、发布步骤。
- 地图包包含本阶段导航所需的可通行拓扑、地点/地标目录、跨层连接、风险语义及信标映射。
- 地点查询支持名称/别名/楼层/类别；只返回可导航已发布地点。无结果返回空列表；候选结果必须属于同一地图版本。
- 转换器与 API 地图 schema、地点/分页上限需在接口契约冻结时定稿；首发 siteId 和场馆/楼层范围仍须用户确认。

### REQ-LOCATION 位置估计（P0）

- 客户端采集并按窗口聚合当前场所登记信标 ID、RSSI、观测时间和序号；不得上传无关蓝牙设备 MAC。IMU 仅按 API 预留字段传送或不传，不能影响第一阶段输出。
- `POST /locations/estimate` 校验场所/地图版本、时间新鲜度、序号、RSSI 范围、信标登记和输入完整性；未知 beacon 可忽略并回报。
- BLE 三点定位输出估计坐标（可空）、楼层（可空）、朝向（若可用）、置信度、质量 `reliable|degraded|unreliable|lost`、匹配区域、算法版本及观测时间。质量差时不得返回可驱动安全指令的可靠位置。
- **工程初始默认值（非现场标定结果）**：扫描/上报目标 1 Hz，定位窗口最近 5 秒；RSSI 输入暂收 `-100..-20 dBm`；快照超过 10 秒视为过期；窗口内先对同一 beacon 做中位数滤波。定位质量阈值不以未经验证的米级精度定义，先依据有效 beacon 数、几何分布和残差分为 `reliable/degraded/unreliable/lost`，各阈值由现场标定冻结。以上值仅便于开发联调，必须在上线前采集现场样本、回放和调整。
- 旧序号返回稳定冲突错误，不能覆盖新结果。坐标以场馆局部米制坐标为基准；朝向采用设备相对场馆北向的顺时针角度（0° 为场馆北向），没有可靠朝向时不得播报依赖朝向的左右转指令。批次大小等 API 限制在契约冻结时确定。

### REQ-NAV 导航会话与路线（P0）

- `POST /nav/sessions` 仅在用户确认后调用；要求可信起点、有效目的地、当前发布地图及可达路线，使用 `Idempotency-Key`。创建后返回 `active` 会话、目标、版本、路线和结构化首条指令。
- **路径概要先行**：会话创建成功后，先播报路径概要（总距离、途经楼层变化、终点名称），**跨楼层时必须显式提示**（如"路线需要乘坐电梯上二楼"），概要播报完成后再播首条行动指令。概要仅基于服务端已返回的路线数据生成，不新增服务端契约。
- **地图路径展示（步行导航视觉，P0）**：
  - 创建会话后，在地图上绘制**用户所在楼层**的完整路线全貌（整条该层路线高亮，而非只显示前方一段）；用户切换楼层视图时展示对应楼层的路线段；
  - 导航进行中采用类高德步行导航的展示：路线持续高亮、用户位置沿路线实时推进、视口跟随当前位置，到达转向点/楼层变化点前有醒目标记；
  - 展示层不得替代安全规则：定位不可信时进入恢复态，地图"当前位置"随之停止推进；播报仍严格受本 REQ 与 REQ-SESSION 的质量、状态机约束支配。
- 导航更新提交有序序号和位置。可信位置可推进路径、触发偏航重规划或到达；不可信位置转入 `recovering`，返回安全级重定位提示，不提供普通转向。
- **工程初始默认值（待实测调整）**：位置/导航更新目标 1 Hz；偏航触发先用与当前路线横向距离 3 m 且连续 2 个可信样本超阈作为重规划候选；到达候选先用目标入口/门口 2 m 区域内连续可信观测至少 5 秒，且路线末段完成后再由服务端确认。该默认值不得作为安全或性能达标声明；现场测试中若不能可靠识别/避免误报，则提高安全门槛或关闭自动到达/自动重规划，进入语音询问或恢复流程。
- 视障 `blind` 模式跨楼层必须使用电梯。不可达或无可用电梯时返回相应错误且不创建活动会话。受限寻路失败时，面向用户的公开路线默认不得采用 `wall_fallback`；仅在受控测试配置显式允许时可返回该诊断结果，并标记 `fallbackType: "wall_fallback"`、`safeForBlind: false`、风险原因和“此路线不可用于行走”的提示。客户端须暂停导航并提供退出/重新定位/求助场馆工作人员等选项，不得播报穿墙路径行动指令；确认仅用于记录已知悉风险，不能解锁行动指引。
- 路由响应包含固定 `mapVersion`、`routeRulesVersion`（首期初始值 `1.0.0`，按语义版本递增且会话内固定）、`routeId`、单调递增 `instructionSequence`、指令有效期 `expiresAt`、`fallbackType`（`none|best_door|all_doors|wall_fallback`）、`safeForBlind` 和结构化风险提示；首条指令随创建会话响应返回。重复请求/播报通过 `instructionSequence` 去重；重复指令仅在仍未过期（默认 10 秒）时允许重播。路由规则版本变更不能影响已创建会话。
- 重规划仅在可信位置执行；新指令必须基于固定地图版本和路由规则。客户端只播报当前有效指令；旧/重复更新不得重复推进。
- 到达使用目标区域、可信位置和已冻结的停留条件综合判定；产生单次 `arrived` 终态。上述参数均为工程默认，必须按现场结果调整后冻结；未完成现场验证前不自动向用户宣布已到达。

### REQ-SESSION 会话恢复与结束（P0）

- `GET /nav/sessions/{id}` 只向会话所属用户返回状态。终态不得返回可执行旧指令。
- 后台恢复先读取会话状态，再校验地图版本、权限、传感器、位置新鲜度，满足条件后才恢复；读到 `active` 本身不代表可继续行走。
- 导航中语音结束/取消、可访问“结束导航”控件激活，或非屏幕阅读器模式下双击，可调用结束 API；结束接口幂等，终态不可复活。客户端停止采集与播报并确认结束。
- 定位恢复时服务端只允许 `recovering → active` 于新位置可信后发生。连接恢复和重复请求不得破坏状态机。

### REQ-A11Y 交互可访问性与播报（P0）

- 双击不得作为屏幕全局手势截获。标准屏幕阅读器模式下，焦点落在独立的“确认并开始”或“结束导航”可访问控件时，由系统双击激活该控件；提供语音命令作为免触摸替代。非屏幕阅读器模式可保留大热区双击。提供明确、可访问的取消/结束控件；不以摇晃、复杂多指手势或短时序连击作为唯一操作。
- 语音队列允许安全提示打断普通提示；新指令到达时丢弃过期普通提示；“重复”只重播当前仍有效指令。
- TTS 失败时以震动及可访问文本提示并安全暂停导航，不得无声继续确定性指引。
- iOS/Android 微信及 VoiceOver/TalkBack 版本范围在试点设备清单中冻结；辅助技术、手势冲突、插件配额/网络/延迟和中断恢复需实机验证。阈值待确认。

### REQ-PRIVACY 隐私与运行安全（P0）

- 全部业务 API 使用 HTTPS；除 `POST /auth/wechat` 外均必须携带 Bearer token。服务端按 `openid` 主体校验资源归属。令牌、原始语音、识别原文和完整坐标不得写入明文日志；只处理导航所需的最少数据。
- 原始录音不进入 PathAI 后端；识别文本只为当次处理使用，不默认持久化或用于训练。外部语音服务数据流须告知并经上线隐私评审。
- 分析用途的脱敏数据自脱敏完成之日起最多保留 360 天，之后删除或不可逆匿名化；分析数据不得包含令牌、openid、原始语音、识别原文或可直接识别个人的完整轨迹。脱敏方案及重识别风险需上线前由隐私/安全评审确认。其他个人信息按微信平台规则及经批准的隐私政策处理；账号注销/删除请求须触发关联个人数据删除流程。备份和日志须有对应到期清理策略。
- 会话固定地图版本；低质量或过期定位以安全提示替代方向指令；系统不得宣称替代盲杖/导盲犬。
- 小程序不承诺后台/锁屏持续导航。切后台后应按平台能力安全暂停；回前台按 REQ-SESSION 重校验。

## 7. API 契约摘要

基路径 `/api/v1`，JSON UTF-8。`POST /auth/wechat` 以外所有 API 必须携带 Bearer token；`API-01` 用微信临时 code 换取 PathAI token 并建立 `openid` 主体。公共错误格式为 `{error:{code,message,retryable,details},requestId}`；客户端按 `code` 分支。幂等操作支持 `Idempotency-Key`，同 key/同请求返回原结果，同 key/不同请求返回 `409 IDEMPOTENCY_CONFLICT`。

| API | 方法与路径 | 主要责任 |
|---|---|---|
| API-01 | `POST /auth/wechat` | 必需的微信登录换取 PathAI Bearer token，并绑定 `openid` 主体；不得泄露 code/AppSecret |
| API-02 | `GET /sites/{siteId}/map` | 获取发布地图版本和摘要 |
| API-03 | `GET /sites/{siteId}/places` | 地点查询及候选 |
| API-04 | `POST /intents/parse` | 受控文本意图和地点解析 |
| API-05 | `POST /locations/estimate` | BLE 快照定位估计 |
| API-06 | `POST /nav/sessions` | 确认后创建会话并规划路线 |
| API-07 | `POST /nav/sessions/{id}/updates` | 位置推进、恢复、重规划、到达 |
| API-08 | `GET /nav/sessions/{id}` | 查询会话与恢复校验 |
| API-09 | `POST /nav/sessions/{id}/end` | 幂等结束会话 |

完整字段、示例及错误码以来源 API 文档为基线；进入接口实现前将 OpenAPI/schema（或等价契约测试）冻结，补齐 TBD，不允许客户端与服务端各自解释。

## 8. 可观测性与失败规则

- 每个响应含 `requestId`；日志使用脱敏结构化字段，不记录令牌、原始语音、识别原文或完整坐标。
- 依赖错误、超时、schema 不合法、地图冲突和定位不可信均显式失败；禁止自动无限重试。
- 可重试错误向客户端标记 `retryable`；客户端重试必须受控，并保持幂等。
- 语音失效或定位失效时，不继续输出未经验证的转向；用户始终可取消/结束（平台仍可用时）。

## 9. 验收场景（概要）

1. 授权通过与拒绝、首次与后续启动均给出正确非视觉反馈；拒绝时绝不声称已定位。
2. 按住/松开、取消、插件失败及后台中断均能正确停止录音并反馈。
3. 唯一地点需确认后才创建会话；歧义、不存在、低置信度和无路由均不能启动。
4. 地图摘要通过、缓存未变、未发布、校验失败、版本冲突分别有正确处理。
5. 信标不足、RSSI 非法、未知 beacon、旧序号和定位失可信时不输出错误可靠位置或方向。
6. 路由符合受限 Dijkstra 规则；盲模式不走楼梯；回退路线明确标识。
7. 更新乱序、重复请求、偏航、定位恢复、到达、主动结束、跨用户访问均符合状态机及幂等约束。
8. TTS/网络/蓝牙失效、切后台/恢复、语音队列过期提示时安全降级。
9. 真实设备、无障碍辅助技术及现场定位/导航安全测试通过后，才可申请开放真实路线试点。
10. 单页主流程符合 REQ-PAGE：首屏全屏地图、底端设置入口（写本地缓存）、下半屏按住/松开、目的地确认卡片居中；导航创建后先播路径概要且跨楼层显式提示，地图呈现用户所在楼层路径全貌与类高德跟随展示，恢复态不推进位置显示。

## 10. 已确认决策与剩余冻结项

以下已按用户答复写入本规格；工程默认值仅用于开发和受控测试，不能视为现场验证或上线验收通过。

### 已确认决策

1. **身份与鉴权**：首期强制微信登录；不提供匿名导航主体。API-01 换取 PathAI Bearer token，服务端以 `openid` 绑定主体并校验会话所有权。
2. **语音依赖**：WechatSI 插件（个人主体不可用）已替换为**讯飞开放平台在线语音**——语音听写大模型 V2.0 + 超拟人合成，wss 直连、签名 URL 由后端签发、密钥仅存 `PATHAI_XFYUN_*` 环境变量；仍须按目标设备验证网络依赖、socket 合法域名、麦克风权限、失败降级与供应商数据流告知。
3. **参数策略**：定位和导航采用 §6 标明的工程初始默认值，开发/测试后基于现场采集调整；上线前冻结经验证参数，未验证前不得宣称性能达标。
4. **权限与无障碍**：按 REQ-BOOT 的首页重试入口和未授权功能边界；屏幕阅读器使用聚焦可访问控件的系统双击激活，另提供语音命令及明确控件，不截获全局双击。
5. **数据留存**：分析用途脱敏数据最多保留 360 天；其他个人信息遵循微信平台规则及经批准的隐私政策，并落实注销删除和备份/日志到期清理。
6. **验收门槛**：现场采集和真实设备/无障碍验证前，不声明定位误差、楼层识别、错误转向、恢复时长、时延、功耗或安全测试达标。
7. **页面架构（2026-10-26 用户确认）**：单页化——导航态融合进全屏地图页（原独立导航页退役）；语音首页 pages/index 彻底移除，按住说话、意图结果与目的地确认全部并入地图页（下半屏热区、屏幕居中浮层）；屏幕底端设置入口常显（mock/live 均可进入，设置写本地缓存、重启生效）。详见 REQ-PAGE。

### 分阶段冻结项

规格经用户批准后，可按下列门槛分阶段开展开发和验证；未到冻结时点的事项不得被当作已确定的生产参数或验收结论。相关模块的契约/安全边界冻结后，可开始该模块实现；全量未决项不构成所有开发的统一阻塞条件。

#### 对应模块实现前冻结

1. **地图与地图 API**：确定首发 `siteId`、场馆和楼层范围、地图包 API schema、地点/分页上限、GeoJSON 与信标部署数据的字段映射、规划点位/现场实际点位的选取规则及版本发布样例。首版地图包由当前扩展 GeoJSON 与信标部署数据共同转换、校验、打包；第一阶段不需要单独的在线管理后台，使用仓库内版本化工具链即可。GeoJSON 提供地图几何/语义/拓扑等信息，信标部署数据提供 beacon ID、坐标、楼层及部署属性；两类输入须保留来源和版本对应关系，规划坐标不得冒充已安装点位。上述契约冻结前可使用合成/固定样例开发与测试非生产逻辑，但不得开始依赖该契约的转换器、地图 API 和真实地图联调实现。
2. **API 与路线契约**：冻结 API 请求/响应 schema、稳定错误码、鉴权范围、幂等规则、`routeRulesVersion`、fallback 字段/风险提示、首条指令、指令序号/失效/重复有效期。冻结前可用模拟契约开发独立逻辑；前后端集成实现和契约测试必须基于同一冻结版本。

#### 真实数据测试或试点前冻结

3. **定位现场参数**：冻结 RSSI 距离/位置模型、质量阈值、场馆坐标北向和朝向校准方法、现场采样/验收方法及可接受误差。§6 经验值仅可用于模拟、开发联调和探索性测试，不能作为现场精度或上线验收结论。
4. **导航现场参数与安全策略**：通过现场测试冻结更新/偏航/到达参数和风险策略。`wall_fallback` 默认不得进入面向用户的真实导航；是否允许受控测试显式启用须在相关测试风险评审时确认。未经验证的默认值不得作为安全或性能达标声明。
5. **设备与生命周期**：真机验证前冻结目标 iOS/Android 微信及 VoiceOver/TalkBack 版本清单，并验证切后台/锁屏时的暂停与恢复策略；不得承诺后台持续导航。
6. **隐私/安全评审**：使用真实用户数据测试、持久化或上线前，确认 360 天分析数据集字段确已脱敏、重识别风险可接受，并冻结账号删除、备份/日志到期清理和 WechatSI 数据告知流程；该规格不是法律合规结论。纯合成数据开发测试不受此项阻塞。
7. **验收数值**：在申请真实路线试点/发布前，以现场基线、风险分析和受控视障评估结果确定定位误差、楼层识别、错误转向、恢复、延迟、功耗及试点门槛；在此之前不得以工程默认值替代验收门槛或宣称达标。
