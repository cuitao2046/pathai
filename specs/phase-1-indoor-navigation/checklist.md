## 地图与定位

- [ ] CHK-008 地图只加载已发布不可变版本，校验 HTTPS 与 SHA-256；失败或版本冲突不允许导航。（REQ-MAP）
- [ ] CHK-009 只查询可导航发布地点；无结果为空；候选与当前 mapVersion 一致。（REQ-MAP）
- [ ] CHK-010 定位输入校验场所、版本、信标、RSSI、时间及序号；陌生信标不参与计算。（REQ-LOCATION）

- [ ] CHK-012 不可信/丢失定位不提供确定性坐标、转向或到达判断；客户端停止播报旧方向。（REQ-LOCATION, REQ-NAV）
- [x] CHK-013 乱序位置不会覆盖新位置；位置质量、算法/参数版本（API-05 `paramsVersion`，会话固化）与地图版本可追溯。（REQ-LOCATION；自动化覆盖：`test_location_api` / `test_nav_api`）

## 路由与会话

- [ ] CHK-014 未经目的地确认、起点不可信、地图无效或路线不可达，均不创建活动会话。（REQ-DESTINATION, REQ-NAV）
- [ ] CHK-015 路由符合 `docs/05-路线规划算法.md`：受限 Dijkstra、门惩罚、盲模式跨层走电梯；面向用户默认不允许 `wall_fallback`，受控测试若返回仅提示不可行走并暂停，不提供穿墙行动指令。（REQ-NAV）
- [ ] CHK-016 路线指令及地标可追溯地图且 LLM 不能制造行动指令；响应含 map/rules 版本、routeId、指令序号/有效期、fallback 类型和首条指令；重复或过期指令不重复播报。（REQ-NAV）
- [ ] CHK-017 `active ↔ recovering`、终态迁移合法；终态不可逆；只有可信新位置可恢复。（REQ-NAV, REQ-SESSION）
- [ ] CHK-018 重复/过期序号及幂等请求不重复推进、建会话或结束；跨用户访问被拒绝。（REQ-NAV, REQ-SESSION）
- [ ] CHK-019 到达由服务端以已冻结规则判定，每会话仅一次；结束后客户端停止采集和旧提示。（REQ-NAV, REQ-SESSION）
- [ ] CHK-020 后台恢复先查会话、地图、权限和位置新鲜度；不因会话 active 自动继续行走。（REQ-SESSION）

- [ ] CHK-025 API 服务使用 Python 3.13+、FastAPI/Pydantic 2、Uvicorn；SQLAlchemy 2 + Alembic 管理数据库模型/迁移，依赖版本锁定。（§4）

- [ ] CHK-027 地图包本地使用文件系统、Demo 使用对象存储；数据库仅存元数据，地图版本不可变并校验 SHA-256。Demo 为单体 API + PostgreSQL + 对象存储，不引入 Redis/队列/Kubernetes；HTTPS、限流、请求体限制和密钥管理由部署层/应用配置提供。（§4）

## 已确认决策

- 后端首期采用 Python 3.13+、FastAPI/Pydantic 2、Uvicorn、SQLAlchemy 2、Alembic；本地开发用 SQLite，Demo 用托管 PostgreSQL。
- 微信登录为必需项；令牌绑定 `openid`，用户资源服务端隔离。
- 语音采用**讯飞开放平台在线 WebSocket**（听写大模型 V2.0 + 超拟人合成，签名 URL 由后端签发、密钥仅存服务端），替代 WechatSI；仍需目标设备集成、socket 合法域名与数据流告知验证。
- 定位/导航默认值仅供开发和测试，须经现场数据调整；数值验收指标不预设达标。
- 权限拒绝后提供持久可达的重试入口；屏幕阅读器使用系统控件双击和语音替代，不截获全局双击。
- 分析用脱敏数据保留上限 360 天；其他个人信息按微信平台规则和隐私评审执行。
