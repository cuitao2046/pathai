# 现场采集与导航对比开发计划

评审基线为 2026-11-19 工作区，需求以 [现场测试方案](../../docs/现场测试方案.md) 第三至第九节为准。日期为方案中的现场窗口。开发状态与真机放行分别记录。

## 里程碑

| 阶段 | 现场窗口 | 放行条件 |
| --- | --- | --- |
| M0 巡检和测点准备 | 11-21/22 T1，11-28 T2 | 可逐枚复扫和登记信标。可登记复测数据，并下发获准的标定、静态和检查点清单。 |
| M1 实验数据底座与 T3 试走 | 11-29 T3 | 可跑完 12 段标定队列。完成一轮 8 分钟连续试走，断网后可继续录制，恢复后可补传和复算。 |
| M2 T4 建库与 T6 正式采集 | 12-05 T4 首采，12-20 T6/T7 | T4 一键采完一个点的四朝向，T6 能接着现有实现按正式批次执行，异常及漏点可追溯和补采。 |
| M3 T8 方法轮换与实验交付 | 12-19 配置冻结，01-10 T8 首测 | A/B/C 可选、可追踪、可重放。使用试走数据生成完整实验 ZIP，独立复算到达和转向指标。 |

M0 到 M1 的时间最紧。先交付巡检的扫描及登记，真值表单和正式清单接着推进。M1 的数据契约先定，T3 与 T7 可并行实现。若 T1 当天巡检页未就绪，可用现有工具扫描并人工登记，随后导入并核对。若 M1 或 M2 放行条件未通过，当次采集标作预实验，复测通过后再纳入正式批次。

## M0 · 信标巡检与真值

- [x] **FC-01 · T1/T10 巡检。** 新增信标巡检入口，保留 `p0-probe` 的局域网诊断用途。从当前地图包加载 27 枚，按 UUID/major/minor 匹配扫描结果，显示 RSSI、最后收到时间和在位状态。登记贴装时间、固定方式、位置、异常和拆除复核，并导出台账。发射功率用设备配置或台账核对，验收时区分实扫状态和人工确认。
- [x] **FC-02 · T2 真值登记与下发。** 保留已内置的 12 个标定、18 个静态、8 个检查点及双墙参照，登记两墙实测值、复测值、换算坐标、审核人和覆盖边缘备注。审核后生成版本化清单和 `ground_truth.csv`。T4 按批准边界裁剪，复核当前 252 个候选中的 48 个待复核点，再下发正式清单，最多 256 点。
- [ ] **验收。** 真机逐枚核对 27 枚信标；用现场测距复测一个候选点，从登记、审核到小程序获得正式坐标走一遍。

## M1 · 实验数据底座、T3 和 T7 试走

- [x] **FC-03 · 今日任务和持久化。** 按任务、日期、批次下发点位与路线，显示下一点、完成数和跳过原因。正式模式拒绝清单外采集，以任务、批次、点位及朝向判断完成，跨日期批次可重复。关闭小程序再打开时恢复进度，保留旧记录和现有诊断入口。
- [x] **FC-04 · 原始数据与补传。** 统一 `segmentId`、`runId`、版本、批次、设备、操作者及起止时间。RSSI 按段保存，时间戳直接使用开启自动设置时间的手机系统时间。完成时先落盘再自动上传。提供持久化待补传及手动重传，服务端按稳定 ID 幂等确认，成功后才清队列。真机验收区分扫描回调数与逐信标样本数。
- [x] **FC-05 · T3 自动三批。** 在专用任务入口执行 12 点 × 3 批 × 120 秒，按点推进，同一点三批逐段确认落盘。保留单信标对数等距和手动静态采集用于诊断。
- [x] **FC-06 · T7 行走打点与场记。** 按顺序加载 8 个检查点，启动前倒计时，沿路持续保存原始 RSSI，提供单手大按钮打点、2 秒撤销留痕和带原因的中止。结束后核对并导出打点时刻、时长、漏点和观察员记录。场记同一 `runId` 下还可记录进出场异常与清场结果。
- [ ] **验收。** 加速测试完整 12 段队列，真机实测每点采一次 120 秒，后端按三个 40 秒窗口生成标定输入。完整走一轮至少 8 分钟，检查 8 个打点、撤销与中止各一例。断网不停止采集，重开后补传两次，服务端只留一份并能对齐观察员时刻。

## M2 · T4、T6 与补采

- [x] **T6 四朝向连续采集基础。** 每点一次开始，N/E/S/W 各 30 秒，转向缓冲独立计时，每段单独保存并导出朝向。正式批次和真机验收仍在本阶段。
- [x] **FC-07 · T4 四朝向完整窗口。** 按正式网格逐点采 N/E/S/W。每向 25 秒达到 60 条 RSSI 和 3 枚有效信标即保存，否则延长到 30 秒复核，仍未达标则补采。转向缓冲单独计时。
- [x] **FC-08 · T6 正式批次和 T9 补采。** 固定同一组 18 个复测点及批次，测试集与建库、拟合数据分开。低帧段保留并标记，补采使用 `-R1` 等后缀关联原段，不覆盖。把漏点、异常和未补完记录合成次日优先清单。
- [ ] **验收。** 真机连续完成至少两个 T4 点和两个 T6 点，核对每点四段、朝向、窗口长度、批次与 RSSI 时间戳。模拟低帧、断网与重启，确认异常可补采、已完成项目正确置灰、测试集不能误入指纹库或拟合流程。验收网格底部面板、参考墙和点选后地图拖动缩放。

## M3 · T8、冻结和导出

- [x] **FC-09 · T8 对比。** A 使用默认参数三点定位，B 使用标定参数三点定位，C 优先匹配冻结指纹库并在未命中时回退 B。实现三选一、按测试日轮换、切换后重建会话、顶部展示当前方法。会话记录所选方法、实际定位来源、地图和参数版本、指纹库版本、导航阈值、检查点，以及指令生成和实际播报事件。观察员按 `runId` 补录到达和提示评价。
- [x] **FC-10 · 配置冻结与统一导出。** 先用试采段做 A/B/C 重放预检，再生成不可变实验配置快照。设置页提供待补传和实验导出，后端打包五类 JSONL、观察员及真值两份 CSV 和 `manifest.json`。清单包含版本、计数、排除原因和补采关系。配套解析脚本校验文件结构、ID、版本、计数和时间对齐。
- [ ] **验收。** 验证三天轮换及每种方法的会话记录。用一次端到端试走的 ZIP 独立复算检查点误差、转向提示时间和到达判定。现场验收同时核对冻结的 2.0 m 到达半径与 3.0 m 转向提前距离。

## 开工时确认的实验口径

- 开发初期可用版本化候选清单联调。现场负责人审核真值、T4 边界及排除项后，正式批次才使用获准清单。
- A/B/C 算法已确认。A、B 共用三点定位流程，差异为默认参数与现场标定参数。C 的回退仍属于 C 轮次，单列回退率，指纹命中数不包含回退。
- 8 分钟无线录制、断网补传、蓝牙帧率和双人记录能否对齐，以真机记录为验收证据。自动化用于检查状态迁移、数据边界、幂等和导出契约。

## 小程序操作入口

- 所有已登录用户可从「设置 → 现场采集工具 → 打开现场实验」进入。T3、T4、T6 候选点试采每段 10 秒，和正式清单分开，模拟数据不会上传。
- 先在「真值登记」保存复测点，复核当天的范围与点数后发布。当天任务可按日期和批次恢复。T4 清单可分日发布。
- 在「任务」完成正式 T3 后点「生成正式标定样本」，进入定位常量计算页审核并应用结果。完成 T4 后，在「场记及导出」输入已完成的正式清单编号，经确认建库。建库会替换采集楼层的现用指纹，旧版本可回滚。
- 在「场记及导出」冻结配置，并用一轮已上传的 T7 试走重放 A/B/C。确认数据可用后，在 T8 任务选定冻结配置，按当日方法进入地图。每轮结束可查看待补传并补录观察员时刻。导航未报告到达时，如果现场已完成该轮，可按「完成本轮」保留失败的到达判定。
- 导出正式实验 ZIP 后，校外运行 `python tools/analyze_field_experiment.py <实验ZIP>` 核对文件和数量，复算转向、到达及 C 的回退率。基于点位估计计算的转向结果与观察员评价分别保留。

当前勾选项代表已接入代码并完成相应自动化核对。四个现场放行项仍需用真实蓝牙、复测真值和参与者设备验证。
