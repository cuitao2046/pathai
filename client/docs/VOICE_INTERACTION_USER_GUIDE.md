# 旁白模式下语音交互操作说明

面向使用 VoiceOver / TalkBack（下文统称"系统旁白"）的视障使用者，也可供现场同事照着陪练。
本文按当前 `client` 代码的真实行为编写；凡是代码未实现的能力，本文不会写成"已有"。

> 一句话版本：**先在设置里打开「旁白语音交互」，回到地图后聚焦底部语音按钮，双击一次开始说话，再说完后再双击一次结束。等一次短震动再开口，听到双短震表示已停止。**

---

## 1. 开启与关闭

1. 进入「设置」页（地图页左上角第一颗按钮，名称是「打开设置」）。
2. 找到「无障碍模式」分组里的「旁白语音交互」开关，打开。
   - 开关的无障碍名称是「旁白语音交互，开启后双击开始和结束录音」。
   - 保存失败会提示「设置保存失败，请重试」，开关会自动回到原来的状态。
3. 返回地图页即生效（每次回到地图页都会重新读取该开关），不需要重启小程序。
4. 关闭开关即恢复为「按住说话」，同样即时生效。

需要知道的边界：

- 这个开关**只改变小程序内的录音方式**，不会打开手机的系统旁白，也不读取系统旁白是否开启。
- 它与「视障模式」开关相互独立：可以只开旁白语音、不开视障模式，反之亦然。
- 切换开关的瞬间，正在进行的录音会被取消、正在播放的应用语音会被停止（本次不补播）。

---

## 2. 语音按钮在哪里

- 位置：地图页**底部居中**的一颗原生按钮（不是普通文本块，所以系统旁白能对它执行"激活"）。
- 旁白模式下按钮的可见文字会被读屏跳过，读屏读的是按钮名称；名称会随状态变化：
  - 待机：「开始语音输入」
  - 录音中（麦克风已就绪）：「结束语音输入，正在录音」
  - 准备中：「结束语音输入，麦克风准备中，可再次激活结束」
  - 识别中：「正在识别」
  - 失败：「语音识别失败，双击重试」
- 地图尚未加载完、加载失败、正在识别、正在理解时，这颗按钮处于**禁用**状态，无法开始新的录音。

---

## 3. 发起一次语音输入

1. 单指滑动到「开始语音输入」按钮。
2. **双击（系统"激活"手势）一次**，开始录音；不需要按住，也不需要做任何滑动以外的触摸动作。
3. 此时听到/感知到的顺序是：
   - 按钮名称立即变成「结束语音输入，麦克风准备中，可再次激活结束」；
   - 屏幕上出现状态文字「正在打开麦克风，请稍候」；
   - **等到一次短震动**，才表示麦克风真正打开、可以开口。此前说的话可能录不进去。
   - 短震动后按钮名称变为「结束语音输入，正在录音」，状态文字变为「开始录音，请说出目的地，说完激活结束语音输入」。
4. 准备阶段（还没震动）也可以再次双击，直接结束本次录音。

## 4. 结束与提交

- 麦克风就绪后，**再次聚焦同一颗按钮并双击一次**结束录音。
- 结束时会给出**双短震动**（两下短震，间隔约 0.12 秒），表示"已停止"。
- 录满 **15 秒**会自动结束并提交，不需要也不能延长。
- 结束后的阶段：
  1. 按钮变为「正在识别」，状态文字「正在识别，请稍候」；
  2. 识别出文字后自动进入理解阶段，状态文字「正在理解，请稍候」，屏幕上"你说"显示识别结果；
  3. 识别结果为空时提示「没听清，请再说一遍」（3 秒内连续出现只提示一次）；
  4. 识别最长等 **30 秒**，超时会提示「语音识别超时，请重试」，本次不提交。

## 5. 说完之后会得到什么

旁白模式下**应用不会用语音朗读自己的答复**（见第 7 节），反馈以可聚焦文字呈现：

| 阶段 | 呈现位置 |
| --- | --- |
| 识别中 / 理解中 | 页面底部「语音状态」区域（aria-live 礼貌级别） |
| 识别结果 | 居中卡片「你说」 |
| 助手答复 | 居中卡片「助手」 + 「语音状态」区域 |
| 多个候选目的地 | 居中卡片里的候选按钮，每个名称形如「选择 图书馆，3 楼」 |
| 唯一目的地 | 「开始导航：目的地名称」按钮 |
| 导航进行中 | 导航 HUD 顶部的状态文字（礼貌级别）与当前指令（紧急级别）；此时居中卡片不再显示 |

- 选候选、确认开始导航，都是把焦点移到对应按钮后双击激活。
- 导航进行中也可以再次双击语音按钮提问或换目的地，录制方式与平时相同。
- 是否会被系统旁白**自动读出**每次变化，取决于手机系统与微信版本；应用没有调用任何"让系统朗读"的接口，因此**不保证自动朗读**。如果设备不自动读，可单指滑动聚焦「语音状态」区域读当前状态。

## 6. 取消

- 录音中、识别中、正在理解时，页面会出现「取消语音输入」按钮（旁白模式下才出现），双击即取消。
- 取消后状态文字变为「已取消语音输入」，本次不提交。
- 理解阶段取消不会撤回已经发出的请求，但它的迟到结果会被忽略，不会弹出候选或开始导航。
- 切到后台、离开地图页、切换「旁白语音交互」开关，也会取消当前录音并丢弃结果。
- 录音状态下，如果电话等其他系统音频打断录音，代码层面没有单独的恢复逻辑，请重新双击开始。

## 7. 播报、打断与优先级

旁白模式下：

- **应用 TTS 关闭**：所有本该朗读的答复改为写入「语音状态」区域与「助手」文字。
- **本地提示音也不播放**：包括「程序已启动」「地图加载中」「地图已加载」「地图过旧」等；`nav-start` 之类的导航提示音同样被跳过。
- 因此旁白模式的反馈是"文字 + 震动"，不会再与系统旁白叠音。
- 启动/加载类提示音被跳过后**没有等价的文字提示**；地图加载失败时仅有长震动与屏幕上的错误说明文字。

普通模式（关闭旁白开关）下：

- 应用 TTS 正常朗读（走讯飞云端合成），本地提示音正常播放；
- 优先级为 **安全警示 > 导航转向 > 普通提示**：安全警示会打断转向与提示，转向会打断普通提示，同级按先后排队；
- 录音开始时会**立即停止正在播放的内容并清空待播队列**，被打断的内容不会在录音结束后补播；录音期间到达的新播报同样不出声（旁白模式也一样）。

## 8. 震动的含义

| 震动 | 含义 |
| --- | --- |
| 单次短震 | 麦克风就绪，可以开口说话（旁白、普通模式一致） |
| 双短震 | 旁白模式下再次双击后"已停止录音" |
| 长震 | 地图加载失败、导航定位不可信（进入"恢复中"）、语音播报通道不可用（自动切换为文字提示） |
| 连续节拍（越近越密）+ 到点一记长震 | 仅在「视障模式」+ 导航中 + 当前是转弯时生效的**转弯逼近提示**；录音期间自动暂停 |

## 9. 出错与重试

所有提示都是可听懂的中文，原始错误码不会念给用户。处理方式统一：**双击语音按钮重新开始**。

| 你遇到的情况 | 提示文字 | 后续 |
| --- | --- | --- |
| 没录到声音/识别为空 | 没听清，请再说一遍 | 直接重新双击开始 |
| 麦克风权限被拒 | 需要麦克风权限，请在设置中开启 | 授权后再双击 |
| 录音启动失败 | 录音没有成功，请重试 | 重新双击 |
| 识别失败或识别过程中断 | 语音识别失败，请重试 | 重新双击 |
| 识别超过 30 秒 | 语音识别超时，请重试 | 本次丢弃，重新双击 |
| 网络/意图解析失败 | 具体的网络或接口提示（如「网络异常，请重试」） | 重新双击 |
| 地图未就绪 | 无语音提示，按钮处于禁用态 | 等地图加载完成或点「重试」 |

连续快速失败时，提示语有 3 秒防抖，只显示（并播报）一次，避免叠音。

关于系统旁白正在朗读：手机旁白朗读时应用无法控制它的结束时间；请**听到就绪短震后再开口**，否则开头会被旁白盖住。

## 10. 普通模式（关闭旁白）的操作差异

| 项目 | 旁白模式（开） | 普通模式（关） |
| --- | --- | --- |
| 底部语音按钮 | 双击开始 / 再双击结束 | 按住说话、松开结束 |
| 全屏长按说话 | 停用 | 仅「视障模式」且「全屏按住说话」开启时可用：地图空白处单指按住约 0.5 秒进入录音，松手结束，15 秒自动结束 |
| 点按（tap） | 用来开始/结束录音 | 不触发语音（避免和长按手势冲突） |
| 应用语音 | 不朗读，改文字 | 正常朗读 |
| 本地提示音 | 不播放 | 正常播放 |
| 录音时的播报 | 停止并清空，不补播 | 停止并清空，不补播 |
| 结束震动 | 双击结束后双短震 | 无（仅就绪短震） |

## 11. 与 `VOICE_INTERACTION.md` 的对照（以代码为准的补充与出入）

- **补充**：`VOICE_INTERACTION.md` 只写了"双击开始/再双击结束"，没写准备阶段（麦克风未就绪）的按钮名称与"可再次激活结束"。代码实现是允许的，本文第 3、4 节已补全。
- **出入**：`VOICE_INTERACTION.md` 把"录音中到达的应用播报不出声"写在旁白模式段落，但代码在**普通模式同样成立**（录音开始时统一清空队列，录音状态下播报直接跳过，本地提示音也跳过）。
- **遗漏**：`VOICE_INTERACTION.md` 未说明旁白模式下启动与地图加载提示音被整体跳过、且没有替代文字；代码在 `onMapEvent` 与 `bootstrap` 中用 `getScreenReaderVoice()` 直接跳过播放。
- **范围差异**：「取消语音输入」按钮并非全程存在，只在录音、识别、理解三个阶段显示；待机与失败状态没有该按钮。

## 12. 尚未验证的部分

以下行为代码已实现，但**未在真机上验收**，现场陪练时请以实测为准：

- 不同微信版本/机型上，`aria-live` 区域与动态按钮名称是否会被系统旁白自动朗读、朗读时机是否及时；
- 同一按钮名称变化后焦点是否稳定、双击是否严格"一次开始、一次结束"（代码同时处理了触摸与 tap 两条路径，避免双触发）；
- 首次授权、拒绝授权、断网、无音频、15 秒自动收尾在具体设备上的表现；
- 蓝牙耳机/车机等外接音频切换时的录音抢占效果。
